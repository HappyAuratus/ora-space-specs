# 发现进程的等待、清理与隔离

决策依据：[Agent 插件发现契约](../../../../decisions/desktop/plugin/agent/0-discovery-contract.md)（`approved`）。实现尚未开始，本文件全部义务的证据状态为 `Missing`。

## Waiting For Commands Must Stay Within The Cap And The Cleanup Reserve

### 风险

等待没有上限会拖慢界面；占用清理时间会在 Agent 历史里留下本可删除的会话；命令没到就判失败，会连模型一起丢掉。

### 前置状态

- 使用可控时钟。一次发现有总预算和清理预留；插件可以调低等待上限。
- Agent 分别：在 `session/new` 响应之前上报；响应之后上报；先后上报两次；不上报；另一个会话先上报；`session/new` 在预算末尾才响应。

### 触发

分别发起需要命令和不需要命令的发现。

### 必须成立

- 等待从收到 `session/new` 响应起算，只认属于该临时会话的第一条上报；响应之前到达的同样算数，收到立即继续。
- 等待不超过契约常量；插件的值只能调低，高于契约上限的值不生效。
- 等待截止于“上限”与“总预算减去清理预留”中较早的一个。
- 不需要命令时不等待。
- 到上限时模型照常返回，命令为 `None`。

### 禁止结果

- 等待后续上报，或采用其他会话的上报。
- 等待占用清理预留。
- 断言具体的等待数值，使下调上限必须改用例。

### 验证义务与证据

| 验证义务 | 代表性证据测试 | 状态 |
| --- | --- | --- |
| 响应前、响应后到达的上报都算，其他会话的不算 | 尚无实现 | `Missing` |
| 等待不超过契约常量，插件不能调高 | 尚无实现 | `Missing` |
| 预算末尾的等待让出清理预留 | 尚无实现 | `Missing` |
| 不需要命令时不等待 | 尚无实现 | `Missing` |

### 决策依据

- D1 第 3 点、D3 第 2–5 点。
- 不变量 3、4、13。

## Cleanup Must Not Lose Results Or Leave A Process

### 风险

清理卡住时丢掉已读到的结果，或只删会话不结束进程，会让一次展示失败，或累积 Agent 进程。

### 前置状态

- Agent 分别声明和没有声明支持 `session/delete`。
- 删除请求分别成功、报错、超时；进程不响应关闭。
- 发现已经读到模型，并分别读到和没有读到命令。

### 触发

发现进入清理。

### 必须成立

- 读取命令之后才清理；声明支持时尽力删除临时会话。
- 无论删除结果如何，最后结束进程。
- 清理超时或失败不影响已经读到的模型和命令。

### 禁止结果

- 没有声明支持时发送 `session/delete`。
- 清理失败使发现失败，或把命令改为 `None`。
- 发现结束后留下 Agent 进程。

### 验证义务与证据

| 验证义务 | 代表性证据测试 | 状态 |
| --- | --- | --- |
| 按声明决定是否删除 | 尚无实现 | `Missing` |
| 删除失败、超时都仍返回已读到的结果 | 尚无实现 | `Missing` |
| 各种结局下进程都已结束 | 尚无实现 | `Missing` |

### 决策依据

- D3 第 5 点。
- 不变量 5、13。

## Discovery Must Not Touch Sessions Or Shared Connections

### 风险

发现若复用 Ora 的连接或当作会话处理，会触发会话启动 hook、启动 MCP、写入历史或挡住会话删除。

### 前置状态

- Ora 正在与同一 Agent 进行一个 turn。
- Workspace 配置了 MCP server，并有一个尚未发过消息的 Ora Session。

### 触发

对同一 Agent 和 Workspace 发起需要命令的发现。

### 必须成立

- 使用独立的一次性进程和临时 ACP 会话，`mcpServers` 为空。
- 进行中的 turn 和现有连接不受影响。
- 不创建 Ora Session 或绑定、不写历史，打开会话仍不连接 Agent，会话的生命周期状态不变。

### 禁止结果

- 在共享连接上发送 `session/new`。
- 启动任何 MCP server，或因展示命令而连接会话的 Agent。

### 验证义务与证据

| 验证义务 | 代表性证据测试 | 状态 |
| --- | --- | --- |
| 发现使用独立进程，不向共享连接发请求 | 尚无实现 | `Missing` |
| 发现的 `session/new` 不带 MCP | 尚无实现 | `Missing` |
| Ora Session、绑定、历史与状态不变 | 尚无实现 | `Missing` |

### 决策依据

- D3 第 1、6 点，D7 第 4 点。
- 不变量 5、7。

## Discovery Must Use The Same Skill Input As Session Setup

### 风险

只传可读根，或由插件自己推断，发现会系统性地缺少会话里会有的命令；不支持额外目录的 Agent 若因此失败，连模型也列不出。

### 前置状态

- 有 Skill 可读根和 Available Skill 目录；另有一个没有 Available Skill 的 Workspace。
- Agent 分别声明和没有声明额外可读目录能力。

### 触发

对同一 Workspace 各做一次会话 setup 和一次需要命令的发现；再做一次不需要命令的发现。

### 必须成立

- 需要命令时，两处 `session/new` 的 Skill 可读根和 `_meta` Skill 目录出自同一个构造，值相同，由 Desktop 给出。
- 额外可读目录只在 Agent 声明能力时发送，缺少能力不使发现失败。
- Skill 目录为空时不带该字段。
- 不需要命令时可以省略 Skill 输入和修订号，模型不受影响。

### 禁止结果

- 发现只传可读根，不传 Skill 目录。
- 插件自己推断 Skill 输入。

### 验证义务与证据

| 验证义务 | 代表性证据测试 | 状态 |
| --- | --- | --- |
| 发现与会话 setup 的 Skill 输入相等 | 尚无实现 | `Missing` |
| 没有能力时不发送且发现成功 | 尚无实现 | `Missing` |
| 目录为空时不带字段 | 尚无实现 | `Missing` |
| 不需要命令时省略 Skill 输入仍返回模型 | 尚无实现 | `Missing` |

### 决策依据

- D1 第 3 点、D5。
- 不变量 8。
