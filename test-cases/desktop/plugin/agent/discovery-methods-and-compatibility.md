# 发现方法与新旧版本兼容

决策依据：[Agent 插件发现契约](../../../../decisions/desktop/plugin/agent/0-discovery-contract.md)（`approved`）。实现尚未开始，本文件全部义务的证据状态为 `Missing`。

## Discovery Must Call Exactly One Of The Two Methods

### 风险

兼容期内新旧方法名并存。契约检查要求错了方法，或一次发现两个都调用，会让 Agent 不可用，或为一次展示起两个 Agent 进程。

### 前置状态

- 四种插件：只注册 `agent/list_models`；只注册 `agent/discover`；两者都注册；两者都没有。
- 另有一个插件注册了 `agent/discover` 但该方法返回错误。

### 触发

Desktop 完成各插件的契约检查，再各发起一次需要命令的发现。Node 用同一份契约检查加载同样的插件。

### 必须成立

- 至少有一个方法的插件通过契约检查；两者都没有的契约不完整，Agent 不可用。
- 注册了 `agent/discover` 时只调用它；只有 `agent/list_models` 时调用后者，命令为 `None`。
- `agent/discover` 失败时这次发现失败，Agent 仍可用，后续发现可以重试。
- Desktop 与 Node 的契约检查结论相同，Node 不调用发现。

### 禁止结果

- 一次发现中两个方法都被调用，或失败后退回 `agent/list_models`。
- 一次发现失败使 Agent 变为不可用。

### 验证义务与证据

| 验证义务 | 代表性证据测试 | 状态 |
| --- | --- | --- |
| 四种注册组合的契约检查结论 | 尚无实现 | `Missing` |
| 每次发现只调用一个方法，失败不退回 | 尚无实现 | `Missing` |
| 发现失败不使 Agent 不可用 | 尚无实现 | `Missing` |
| Node 使用同一份契约检查 | 尚无实现 | `Missing` |

### 决策依据

- D1 第 4 点、D4、D7 第 5 点。
- 不变量 1、3、10。

## Every Old And New Combination Must Still List Models

### 风险

Desktop 与插件分别升级。任一方向上模型发现断掉，用户就选不了模型。

### 前置状态

- 支持本契约之前的 Desktop 版本与支持之后的版本。
- 支持本契约之前的插件与用新 SDK 构建的插件，后者只实现一个 `discover()`。

### 触发

四种组合各列一次模型。

### 必须成立

- 四种组合都返回模型。
- 旧 Desktop 调用新插件的 `agent/list_models` 时，SDK 以不需要命令、没有 Skill 输入的方式调用 `discover()`，不等待命令，只返回模型。
- 旧 Desktop 接受插件注册多余的方法；这一点用真实旧版本验证。

### 禁止结果

- 新 Desktop 因插件缺少 `agent/discover` 而把旧插件判为不可用。
- 旧 Desktop 为用不到的命令等待。

### 验证义务与证据

| 验证义务 | 代表性证据测试 | 状态 |
| --- | --- | --- |
| 新 Desktop 配旧插件列出模型，命令为 `None` | 尚无实现 | `Missing` |
| 旧 Desktop 配新插件列出模型且不等待命令 | 尚无实现 | `Missing` |
| 真实旧版本 Desktop 接受同时注册两个方法的插件 | 尚无实现 | `Missing` |

### 决策依据

- D4 兼容表与第 3 点、风险“旧 Desktop 与多出的方法”。
- 不变量 4、10。

## Unknown Commands Must Stay Distinct From An Empty List

### 风险

把“不知道”写成“没有”，界面会否认实际存在的命令；把“没有”写成“不知道”，界面会一直提示用户先对话。

### 前置状态

- Agent 分别：上报非空列表；上报空列表；在上限内不上报；不等到上报就退出。
- 调用方分别需要和不需要命令。
- 一条平台冻结模型的路径。

### 触发

对每种情况发起一次发现。

### 必须成立

- 非空上报得到 `Some([...])`，内容和顺序与 Agent 上报一致，不按名称与 Ora Skill 合并。
- 空上报得到 `Some([])`。
- 没有等到上报、进程退出、通道关闭、不需要命令、冻结模型的路径都得到 `None`，模型照常返回。
- 这个区别从插件经宿主传到前端不丢失；`None` 时界面与没有本契约时相同。

### 禁止结果

- 没有收到上报时返回空列表。
- 冻结模型的路径启动发现进程。

### 验证义务与证据

| 验证义务 | 代表性证据测试 | 状态 |
| --- | --- | --- |
| 三种命令值各自的来源 | 尚无实现 | `Missing` |
| 没有等到上报、退出、关闭时模型仍返回 | 尚无实现 | `Missing` |
| 三种值经协议和公共契约到前端不变 | 尚无实现 | `Missing` |
| 冻结模型的路径不启动发现进程 | 尚无实现 | `Missing` |

### 决策依据

- D1 第 2、3 点，D2，D3 第 4、7 点。
- 不变量 2、3。
