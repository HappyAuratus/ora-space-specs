# 项目 Git：内嵌 Git server、ref 规则、每轮交付、外部同步与推回、外部仓库令牌

依据 [项目 Git 根决策](../../../decisions/cloud/project-git/0-embedded-git-server-and-in-process-external-sync.md)（`approved`）。
下文的 D 编号与不变量编号都指这篇根决策。

截至 cloud `80e9c9f1`，v2-server 只在建项目时 mirror clone 一次，本机配套服务的 Git 只放行 upload-pack，用客户端证书认证；
没有 receive-pack、ref 变化事件、交付、外部同步、推回和外部仓库令牌，任务在回合结束时直接进入待验收，变更视图读本机
checkout。desktop `dcff8afe` 的 Node 每次 clone 都重新拉快照，checkout 没有 remote。下列义务都没有直接证据，如实标为
**Missing**，由 I6 #1056（Git server、事件、Node 一侧、交付登记与变更视图）与 I7 #1057（外部同步、推回、凭据）补齐。
现有代码里针对旧路径的测试（建项目时的地址校验、Node 的快照 clone 核实）验证的是将被替换的机制，不登记为证据。

## A Project Token Reaches Only Its Own Project Repository

- 风险：一个项目的 Node 或 Agent 读到、写到另一个项目的仓库；探测出别的仓库是否存在。
- 前置状态：两个项目各有仓库和有效的项目令牌；另有一个已吊销的令牌。
- 触发：用项目 A 的令牌访问项目 A 和项目 B 的仓库路径；不带令牌、带已吊销的令牌、带用户会话访问；访问不存在的仓库；
  请求 dumb HTTP 或三个 smart HTTP 请求以外的路径。
- 必须成立：只有“有效令牌访问自己项目的仓库”成功，并能读到整个仓库的全部 ref；其余情况返回同一个 `404`；
  项目之间不共享对象目录。
- 禁止结果：跨项目读写成功；不同的失败原因得到可区分的应答；用户会话能访问 Git 入口。
- 验证义务与证据：**Missing** — 没有按项目令牌认证的 Git 入口（I6 #1056）。
- 决策依据：D1、D3，不变量 1、2。

## A Push Outside The Ref Rules Writes Nothing

- 风险：Agent 改写外部跟踪 ref 或快照、覆盖别人的成果、删除 ref、强推丢掉提交，或借一次混合推送写入一部分。
- 前置状态：项目仓库里已有跟踪 ref、快照 ref、一个工作分支和一个已登记的交付 ref；Cloud 已要求一次尚未登记的交付。
- 触发：用项目令牌分别推送：新建和快进工作分支；非快进工作分支；`refs/ora/upstreams/**`、`refs/tags/*`、`refs/heads/` 下
  表外的名字；删除任意 ref；新建 Cloud 要求的交付 ref；新建 Cloud 没要求的交付 ref；改写已有的交付 ref；
  一次推送里同时带一条合规和一条违规的更新；带 push options。
- 必须成立：只有新建或快进工作分支、新建 Cloud 已要求且未登记的交付 ref 成功；其余整次推送被拒绝，仓库的 ref 和对象
  都不变。
- 禁止结果：违规更新被写入；混合推送里合规的那一条被写入；任何 ref 被删除；交付 ref 或快照 ref 被改写。
- 验证义务与证据：**Missing** — 没有 receive-pack（I6 #1056）。
- 决策依据：D2、D3，不变量 3、4、5、6。

## A Lost Ref Event Does Not Leave A Delivery Unregistered

- 风险：推送已经写入，但事件没被处理（订阅者出错、进程在两者之间退出），交付永远不登记，任务卡住。
- 前置状态：Cloud 已要求一次交付，Node 即将推送交付 ref。
- 触发：交付 ref 写入后丢弃这次事件，然后 Node 在控制协议里报告交付结果；同一个事件重复送达；事件先于 Node 的报告到达。
- 必须成立：Node 的报告到达时 Cloud 直接读交付 ref 并登记；登记以仓库里 ref 的当前值为准；重复处理只登记一次。
- 禁止结果：交付 ref 已存在而成果永远不登记；同一交付登记两次；登记的提交与交付 ref 指向的提交不一致。
- 验证义务与证据：**Missing** — 没有事件和交付登记（I6 #1056）。
- 决策依据：D4、D7，不变量 7。

## A Task Enters Review Only After Its Delivery Is Registered

- 风险：任务显示待验收，但 Cloud 上没有成果可看；交付失败后任务停在待验收。
- 前置状态：一个任务运行的一轮对话刚结束，工作目录里有未提交的改动；另一轮没有任何改动。
- 触发：回合结束；交付 ref 到达；Node 报告交付失败；等待超过时限；上一条交付还在等待时发起新一轮。
- 必须成立：回合结束时任务还不是待验收；成果登记和进入待验收在同一个事务里；没有改动也交付并登记；交付失败或超时
  时任务回到可以再次运行，原因可见，下一轮的交付包含之前的改动；上一条交付还在等待时新一轮不开始；普通对话同样
  每轮交付。
- 禁止结果：待验收的任务没有登记的成果，或成果指向不存在的交付 ref；交付失败后任务停在待验收。
- 验证义务与证据：**Missing** — v2-server 在回合结束时直接进入待验收，没有交付（I6 #1056）。
- 决策依据：D5、D7，不变量 8。

## Pushes Arriving After An Execution Ended Change No Business Record

- 风险：执行已中断或令牌已吊销，仍在传输的推送随后写入，把已结束的执行改成有成果，或让任务进入待验收。
- 前置状态：一次交付在等待中；所属的执行被中断（Cloud 重启、宿主断开或 Node 退出）。
- 触发：中断之后交付 ref 才写入，事件到达；Node 重放的交付报告到达；Cloud 重启后仓库里存在未登记的交付 ref。
- 必须成立：等待中的交付在中断时作废；之后到达的交付 ref 留在仓库里但不登记；任务状态和成果记录不变；重启不补发事件。
- 禁止结果：已中断的执行出现新登记的成果；任务因迟到的推送进入待验收。
- 验证义务与证据：**Missing** — 没有交付（I6 #1056）。
- 决策依据：D3、D4、D7，不变量 9。

## The Change View Is Computed From The Git Server

- 风险：多机部署下 Cloud 读不到 Node 的目录，变更视图为空或读到别的机器上的旧目录；页面不随推送刷新。
- 前置状态：一个会话目录的基准提交已知；Node 的目录对 Cloud 不可读。
- 触发：Agent 推送工作分支；一轮结束交付到达；读取会话、任务运行和工作流运行的变更视图。
- 必须成立：变更视图取这个工作区最近到达的提交与基准提交比较；工作分支前进和交付到达都经 SSE 通知页面；
  读取过程不访问 Node 的文件系统。
- 禁止结果：变更视图依赖 Cloud 本机上的 checkout 路径；交付到达后变更视图仍是旧内容。
- 验证义务与证据：**Missing** — `workspacefs` 读本机 checkout，变更视图没有 SSE（I6 #1056）。
- 决策依据：D5。

## A Session Directory Starts At The Base Commit Without A Full Clone

- 风险：会话从错误的提交开始；每个会话都完整 clone；Agent 改过的 Git 配置让 Node 把交付推到别处或泄露令牌。
- 前置状态：Node 上已有项目副本；Git server 上的当前快照比副本新。
- 触发：建第二个会话目录；指定一个 Git server 上取不到的基准提交；删除项目副本后再建会话目录；Agent 在会话目录里
  `git fetch`、`git push`，并改写 `.git/config` 的 remote、凭据和钩子配置后触发一次交付。
- 必须成立：第二次只做增量 fetch；会话目录有独立的对象库，HEAD 等于基准提交；取不到基准提交时失败，不用别的提交
  代替；副本丢失后重新 clone；Agent 的 `git push` 写到自己工作区的工作分支；令牌文件仍只有 Node 管理进程可读，令牌
  不出现在 `.git/config` 里；Node 自己的 fetch 和交付不受会话目录里的配置和钩子影响；没有 `ora-git`。
- 禁止结果：会话目录的 HEAD 不等于基准提交却报告成功；交付被 Agent 的配置改道；工作负载直接读到令牌文件。
- 验证义务与证据：**Missing** — Node 每次重新拉快照，checkout 没有 remote（I6 #1056 及其 `decisions/node/` 后续 ADR）。
- 决策依据：D6，不变量 10。

## Webhook Content Never Decides What Gets Synced

- 风险：伪造或被篡改的 webhook 让 Cloud 同步别的仓库、分支或提交；webhook 风暴触发大量并发同步。
- 前置状态：项目绑定了一个外部仓库的一个分支，有 webhook 密钥。
- 触发：密钥错误的请求；密钥正确但请求体写着别的仓库、分支和提交；同步进行中连续多次触发；手动同步；外部分支被
  强推；外部分支被删除；Cloud 在同步途中重启。
- 必须成立：密钥错误返回 `401`，不同步；同步的对象只由绑定决定，取到的提交以 Cloud 自己 fetch 的结果为准；每个项目
  同时最多一次同步，进行中的多次触发合并成之后的一次；成功时快照 ref 和跟踪 ref 一起写入，当前快照随后推进；强推
  时跟随并保留旧快照；分支被删时失败，当前快照不变；重启后进行中的同步标为中断，不自动重跑；已有的会话目录不变。
- 禁止结果：请求体里的内容改变了同步的目标；同一项目两次同步并行；当前快照指向一个没有快照 ref 的提交。
- 验证义务与证据：**Missing** — 没有同步和 webhook（I7 #1057）。
- 决策依据：D8，不变量 5、13、14。

## External Git Never Reaches Disallowed Addresses

- 风险：用户填写的仓库地址把 Cloud 引向回环地址、数据库或内网服务，借 Cloud 的网络位置和凭据探测或攻击它们。
- 前置状态：部署配置了外部 Git 白名单。
- 触发：绑定或同步指向回环地址、Cloud 自己、数据库地址、不在白名单内的私网地址；域名先解析到允许的地址，执行时改为
  解析到内网地址；外部仓库返回重定向；地址使用 `https` 以外的协议或带用户信息。
- 必须成立：只有白名单内或公网的地址被访问；每条 Git 命令使用已检查过的 IP；不跟随重定向；非 `https` 和带用户信息的
  地址被拒绝。
- 禁止结果：Cloud 向不允许的地址发起连接；令牌被发往重定向后的主机。
- 验证义务与证据：**Missing** — v2-server 现在不限制外部地址的主机（I7 #1057）。
- 决策依据：D8。

## Publish Is Fast-Forward Only And Never Re-Pushed

- 风险：推回覆盖了别人在外部仓库的提交；结果不明时自动重推造成重复或错误的写入；Agent 的推送触达外部仓库。
- 前置状态：项目有一个已登记的交付和一个工作分支；外部分支有当前值。
- 触发：管理员、项目创建者和普通成员分别发起；期望的旧值不是来源提交的祖先；外部分支在发起后前进；同一目标分支上
  两次推回同时发起；推送途中 Cloud 重启或连接断开；之后用同一来源和目标再次发起，外部分别已经是来源提交和不是。
- 必须成立：只有管理员或项目创建者能发起，发起人被记录；非快进直接拒绝且不访问外部；外部已变化时不推送；同一目标
  分支同时最多一次推回；结果不明时标为中断，没有后台核验和重推；再次发起时外部已等于来源提交就记为成功，否则重新
  判断；成功且目标是绑定分支时触发一次同步，推回本身不改当前快照。
- 禁止结果：强推、删除外部分支或推 tag；Cloud 自动重推；Node 或 Agent 的推送到达外部仓库。
- 验证义务与证据：**Missing** — 没有推回（I7 #1057）。
- 决策依据：D9，不变量 12、14。

## The External Repository Token Stays Inside Cloud

- 风险：外部仓库令牌出现在日志、API 应答、命令行或 Node 里；数据库泄露后密文被直接使用或挪到别的项目。
- 前置状态：项目配置了外部仓库令牌；部署配置了一组带标识的密钥。
- 触发：读取项目和凭据相关的 API；执行同步和推回并检查日志、子进程的命令行和下发给 Node 的消息；把一个项目的密文
  复制到另一个项目；更换部署的当前密钥后读取旧密文、写入新密文；去掉密钥后启动 Cloud；普通成员尝试填写或更换令牌；
  公开仓库不填令牌。
- 必须成立：API 只返回是否已配置和最后更换的时间；明文只在 Cloud 进程和它启动的外部 Git 子进程里；挪用的密文解密
  失败；旧密钥仍能解密，新写入用当前密钥；密钥缺失时 Cloud 照常启动，需要令牌的同步和推回失败并写明原因；只有团队
  管理员能填写、更换和删除；公开仓库匿名拉取。
- 禁止结果：令牌明文进入日志、API 应答、命令行参数、地址、Git 配置或 Node 容器。
- 验证义务与证据：**Missing** — 没有外部仓库令牌（I7 #1057）。
- 决策依据：D10，不变量 11。
