## Native macOS Cleanup Reports Its Best Effort Boundary

### 风险

用进程组为空推导所有历史后代退出，或以 VM 替代原生执行，会改变已批准的保证和业务环境。

### 前置状态

原生 macOS Git／测试插件可后台化、创建新会话并产生跟踪缺口；完成判据按平台方案冻结。

### 触发

通过生产入口运行，强杀 guardian 后恢复清理，分别注入已知残留、清理失败和尽力判据满足的情况。

### 必须成立

- 始终原生执行并报告尽力保证；要求强纳管时不能静默使用本模式。
- 已知冲突进程存活或清理失败不报告完成；判据满足后保留未跟踪残留可能性，业务对账满足政策后可恢复。

### 禁止结果

使用 Linux VM 冒充本机执行；进程组为空或等待到限即报告强静止；条件恢复后永久阻塞。

|---|---|---|
| 原生后台化／新会话／跟踪缺口不被误报为强静止 | 尚无直接证据；需真实 macOS 与 guardian 强杀验证 | `Missing` |

## Reused Process Identifiers Never Target Unrelated Processes

### 风险

恢复时盲信磁盘 PID 或进程组编号会把新占用该编号的无关进程杀掉。

### 前置状态

保存的旧进程／进程组身份已过期；同一编号现在指向无关进程，另有身份可核实的目标后代。

### 触发

Guardian 失效后读取旧记录并执行发现与清理；分别让身份核实成功、失败和未知。

### 必须成立

- 信号发送前按平台机制核实目标；不能核实的旧编号不作为安全目标。
- 无关进程持续运行，目标清理结果保留实际证据范围；不能因跳过未知目标就宣称强静止。

### 禁止结果

仅匹配数字 PID／进程组就发信号；将无法核实改写为目标不存在。

### 验证义务与证据

| 验证义务 | 验证方式与直接证据 | 状态 |
|---|---|---|
| 复用编号不导致误杀，已核实目标仍可清理 | 尚无直接证据；需身份判定的可控场景与真实信号边界验证 | `Missing` |
| 未知身份保留不确定性，不制造清理证据 | 尚无直接证据；需磁盘旧记录和 guardian 恢复测试 | `Missing` |
