# 普通停止保留活动保护，管理员强停使用独立意图并等待真实终止

普通停止、重启和删除拒绝打断运行任务；管理员强制停止另设明确入口，允许中断目标运行时中的全部工作，但必须保存原因、关闭新准入并确认实际终止。强停保留运行时持久数据，不自动重启、接管或删除。不能以“Cloud 已标记 stopped”代替执行端终止证据。

本 ADR 于 2026-09-28 经用户明确批准，状态为 `approved`，尚未实现；涉及 Cloud 生命周期、Ora 前端、Controller 与 Substrate。当前 `administrative_stop` 是有活动保护的行政停止，并非强停；本决策不静默改变它的既有语义。核心用例见[安全停止与强停](../../../test-cases/cloud/operation/safe-stop-and-administrative-force-stop.md)，新保障的直接证据为 `Missing`。

## 现状与继承

本叶子依次继承[独立运行时生命周期](0-workspace-runtime-follows-desktop-node.md)与[具体默认分支](20260926-require-concrete-default-branch.md)。[Cloud 当前实现](https://github.com/ora-space/cloud/blob/67dcbf95b408559acd5680cf36e84f30e4caad4a/internal/core/public.go)对 stop/delete 检查活动；[执行契约](https://github.com/ora-space/cloud/blob/67dcbf95b408559acd5680cf36e84f30e4caad4a/docs/execution-contract.md)要求终止确认后才删除数据或更换运行代次。

| 前序约定 | 本决策处理 |
| --- | --- |
| 具体分支、每运行时独立 clone，start 不重新 clone | 继承，不变 |
| stop / administrative_stop 经关闭准入、idle、terminate | 继承，并检查使用权限与独占权 |
| 有活动或未知执行不能以 idle 停止或删除 | 继承，不变 |
| 每个项目一个未完成生命周期 operation | 普通操作继承；紧急强停意图可以登记，但不允许两个普通生命周期同时推进 |
| 外部 effect 先计划后派发，结果不明需对账 | 继承；强停也不得绕过 |
| 只有删除数据动作销毁运行时持久数据 | 继承；强停不包含数据删除 |

## 决策

### D1：普通操作必须有使用权限、独占权和活动证据

按[权限矩阵](../workspace/20260927-runtime-workspace-use-permissions.md)检查创建者或管理员。普通停止和重启还须持有当前操作会话，无活动 ticket、未结束写活动或未知执行；关闭准入后，由执行端原子核验不存在漏记活动。竞争的新准入被拒绝，不能在 idle 证据与 terminate 之间插入执行。

重启是受同一持久意图约束的安全停止再启动，不是前端独立发送两个请求。停止未确认时不能启动新一代。独立运行时删除额外要求创建者或管理员身份，无其他持有者；终止确认后才能计划数据删除。main 仍不能单独删除。

项目删除要求管理员，并原子检查全部运行时可以进入删除维护状态；任一运行时被其他会话占用或仍有活动就返回冲突，不部分删除、不自动强停。管理员应先对具体运行时显式处置，再重试项目删除。

### D2：强停是独立授权与明确影响的管理操作

强停接口只接受当前租户管理员，要求目标版本、同次重试沿用的幂等键及非空原因。前端二次确认说明：将中断该运行时的所有成员与 Agent 工作，可能丢失未落盘内容，已保存文件保留；不影响同项目其他运行时。服务端不依赖弹窗授权。

强停不要求先取得被占用的普通操作权，否则它无法处理故障。接受时用短事务保存独立的强停意图、发起人、原因、目标运行时代次和受影响执行关联，同时关闭新准入、撤回当前普通操作资格。被中断者的创建者、任务 actor 和历史结果不改写。

管理员身份在接受时验证；之后的终止、对账和清理是已接受意图的系统责任。管理员随后离开不使系统放弃终止，也不赋予其新请求权限。重复请求返回同一意图，原因或目标不同且沿用同一键时冲突。

### D3：强停不能被普通生命周期串行永久阻塞

强停意图与普通 operation 的排他领取分开表达。目标正在 create、clone、start、plugin 或 stop 时，也能持久登记强停；它首先让该运行时停止派发新的普通副作用，保存与在途 operation、execution、effect 的关联，随后协调目标的终止。

不能删除在途记录、抢改为成功、伪造失败或将未知执行重试一遍来腾出项目唯一约束。若当前普通 operation 属于同项目另一个运行时，强停仅针对本次目标，不中断另一个运行时的工作。新的普通项目生命周期仍按原串行规则处理。

迟到的 sandbox ensure、clone 结果或旧控制指令必须按原稳定身份对账。强停完成条件包括：目标代次的已知或可能迟到资源均已被终止规则覆盖，不会因晚到 ensure 再创建可写旧实例。具体外部终止与禁止重新创建旧实例的责任参见[跨进程交付决策](../controller-integration/20260927-fenced-runtime-control-delivery.md)。

### D4：强停状态与失败恢复

| 状态 | 转换条件 | 对外行为 |
| --- | --- | --- |
| 已请求 | 意图持久化、准入关闭、普通操作资格撤回 | 返回已接受；不宣称已停止 |
| 终止中 | 持久 effect 计划已建立，Controller 请求关闭输入及终止目标 | 禁止启动、接管和删除数据 |
| 待对账 | 响应丢失、执行端不可达或不能证明旧实例无法写入 | 保留终止责任，重查原 effect/实例；不新建执行重试身份 |
| 已停止 | Substrate 确认目标终止且迟到创建受约束；执行责任得到结算 | 保留数据和中断记录，后续启动需新请求与新代次 |

终止成功不能把未知业务任务伪装为成功：有直接终止证据的活动记录为被强停中断；已经完成的结果保留原结果；尚不能关联到被终止范围的记录继续对账。取消或关闭浏览器不撤销已接受的强停责任。第一阶段不提供强停“撤销”功能。

### D5：数据和进程分别说明

| 对象 | 保存者与边界 | 停止 / 强停 / 重启 / 删除 / 故障 |
| --- | --- | --- |
| 权限、运行时身份、操作、执行登记、effect 与审计引用 | Cloud PostgreSQL | 停止保留；重启继续关联；软删除仍保留清理与审计引用 |
| Git 克隆、已保存文件、Node 本地执行日志等持久工作数据 | 执行节点的运行时数据目录或挂载卷，不是 PostgreSQL | 普通停止及强停保留；重启挂载同一运行时数据；确认终止后显式 data delete 才删除 |
| 内存、运行进程、尚未保存的编辑内容 | 当前沙盒及客户端 | 停止不保留运行进程；强停可能丢失未落盘数据；不承诺自动恢复 |
| 节点不可达、宿主磁盘损坏 | 部署的存储与恢复能力 | 不可达不等于已停止；同目录可恢复不等于跨宿主可迁移，磁盘损坏不承诺无损恢复 |

[Docker Substrate 决策](../../cluster/sandbox-server/20260926-docker-sandbox-lifecycle-via-substrate-effects.md)约定按运行时保存命名卷、terminate 移除容器、显式删除才删卷；本次只核查了该规格，未检查 cluster 仓库实现或实际故障恢复。必须在对应实现与部署验证后才把这些行为列为已交付证据。

## 为什么不是这些替代方案

| 方案 | 取舍 |
| --- | --- |
| 将现有 administrative_stop 改为直接杀进程 | 接口少，但旧客户端会在无强停提示时产生破坏性影响 |
| 强停等待当前普通 operation 完成后才接受 | 保持现有队列简单，但挂起的 clone 等可能让紧急停止永远不可用 |
| 只在数据库清除活动票据 | 状态看似空闲，真实进程仍能写入，是虚假安全证据 |
| 强停同时删除目录 | 清理快，但扩大影响并丢失需要保留和救援的工作 |

## 不变量与预期验收

1. 普通停止、重启、删除遇到活动或未知执行必须拒绝，准入与 idle 竞争不产生遗漏。
2. 两次并发强停及响应丢失重试只产生同一终止责任，不跨运行时终止。
3. create/clone/plugin 在途时可登记强停，迟到结果不能重新开放准入或恢复旧沙盒。
4. 终止未确认时保持不可接管、不可重启、不可删数据；恢复后从持久计划继续。
5. 已保存代码在停止、强停与重新启动后仍存在；显式删除按顺序清理并保留审计引用。
6. 发起人离开、权限撤回、进程重启不丢失已接受的终止责任。

## 落地顺序与后续边界

核心用例已建立；先交付持久强停意图及冲突仲裁，再对接真实 Controller/Substrate，最后开放前端强停。外部实现若不能证明旧代次不可写，功能保持不可用或待对账，不用模拟器结果代替生产验收。跨宿主存储迁移、备份及自动灾难恢复不在本决策中承诺。
