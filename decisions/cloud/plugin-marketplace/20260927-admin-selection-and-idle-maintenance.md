# 管理员保存空间插件期望，逐运行时维护等待空闲并使用同一独占边界

插件期望属于 Space，各 Workspace 保存执行实例。只有当前管理员可以改变期望；维护等待无人
持有操作会话、无活动/未知执行及项目生命周期槽位，再取得系统维护资格。接受期望不等于安装
完成，持久 pending 在条件变化和恢复扫描时继续收敛。

本决策的管理员门控和维护等待后端已实现；执行面演进见 D4 的后续决策指针。完整联合故障矩阵
由[后续 ADR](../execution-admission/20261013-runtime-control-ui-and-fault-acceptance.md)承接。
证据见[管理员维护用例](../../../test-cases/cloud/plugin-marketplace/admin-selection-and-idle-maintenance.md)。

## 决策

### D1：管理员改变期望，成员读取安全汇总

安装、移除和版本选择重新校验当前管理员、资源版本和幂等输入；拒绝不建立期望或执行责任。
保存请求者和冻结 release。共享响应给出受影响、完成、等待和失败数量，过滤其它运行时的
执行详情；接受的系统维护责任不因原管理员离开而消失。

### D2：安装与移除共用人类操作的互斥边界

维护不能抢占闲置的人类会话，也不能与 Agent/clone/其它未知工作并行。已停止实例等待正常
启动，不为安装自行启动。维护获得独占后人类获取返回占用；不同项目可并行，同项目保留普通
operation 串行。维护身份只授权固定目标、release 和期望版本。

### D3：等待、执行和新期望按持久责任收敛

pending 保存等待原因及目标实例，恢复扫描重新检查可用条件。计划先持久再派发；未知结果
查询原 execution，不换身份重跑。管理员改变期望时检查版本，已派发旧意图先核对结果，再向
最新版本收敛，不能并行装卸。旧结果不能覆盖新 desired revision；删除目标退出维护候选，
保留清理引用，不恢复已删除实例。明确失败释放本次维护，后续新意图可继续。

### D4：Node 执行及新 Workspace 补装以后续决策为准

本 ADR 原 D4 对未接线执行器及新实例不补装的限制由
[20260928 Node 执行决策](20260928-node-executes-plugin-installs.md)修改，载荷、结果和补装规则
以该后续 ADR 为准，不在此复制。该后续 ADR 保持 `approved`，其独立验收不能由本决策
管理员门控/维护等待的 `implemented` 状态推导完成。

## 不变量

1. 只有当前管理员改变 Space 期望，普通成员拒绝无写副作用。
2. 安装和移除都不能抢占人类会话或与其它写活动并行。
3. pending 和稳定执行责任持久保留，条件恢复后继续处理。
4. 新旧期望、未知结果和删除不会产生重复执行或复活目标。
5. 共享汇总不暴露受限日志，Node 结果才证明实例安装结局。
