# 小队引用工作区内的人和 Agent，编组不产生新的访问或执行授权

Cloud 以 Squad 组织同一协作空间内的人类成员与 Space Agent。租户成员资格继续决定人类准入，
小队成员关系只表达协作分工与本队维护权；普通邀请不自动编组，定向加入由 tenancy 的原子加入契约负责。

本决策为 `proposed`，定义真实编组与邀请闭环的领域边界，不表示已经开放小队管理或 Team 执行。
产品称“小队 / Squad”，既有协作协议称 `team`，两者映射到同一小队身份。本文不改变现有运行、
个人模型、Git 凭据或运行时使用权限，不引入私有小队、多 Agent 自动委派或存量 mock 数据迁移。

## 问题与约束

工作区成员资格已持久化，小队入口却只有演示数据。直接复制成员列表到小队既不能表达多队分工，
也会产生两套人员状态。反过来将小队作为新的权限边界，会使既有共享 Project、Issue、Thread 的
可见性发生未经定义的变化。需要在保留租户唯一授权的前提下，建立独立、可撤销、可追溯的编组关系。

## D1：身份归属唯一，职责与资料不复制成第二份权威

小队有稳定且不可复用的身份，属于且仅属于一个租户及其唯一协作空间，不能迁移到另一工作区。
名称、简介与协作说明可编辑；名称不是身份，不承诺同名小队合并。小队成员为显式类型化引用：
人类引用用户身份，Agent 引用 Space Agent 身份；不使用无法区分两者的裸 memberId，不引用邮箱
或显示名匹配身份。Workflow 是可调用能力，不是小队成员。

人类入队时必须是同租户的有效成员与有效用户，Agent 入队时必须是同空间的活动 Space Agent。
一个对象可加入多个小队；同一小队同一类型与身份最多一条有效编组关系。职责描述可以因队伍而异，
但姓名、工作区角色、插件身份、个人模型与凭据继续由原领域拥有。职责描述不是执行或授权指令。

成员退出或被移除后保留该次编组的来源与终止事实；重新加入是新的明确授予，不消除旧历史。
不得通过重启、重新登录、重新安装插件或再次加入工作区复活已结束的编组。

## D2：全部有效成员可见，小队维护权不扩大到工作区

当前有效工作区成员可读取小队与成员，非成员不可读。首期所有小队均在工作区内可见；不在某队
不削减既有 Project、Issue、Thread 的访问，也不额外授予这些资源的访问。

| 动作 | 当前工作区管理员 | 本队有效人类维护者 | 其他有效工作区成员 |
| --- | --- | --- | --- |
| 查看小队、成员与职责 | 可以 | 可以 | 可以 |
| 创建小队 | 可以 | 可以 | 可以 |
| 修改本队、添加已有成员或 Agent、维护职责与维护者 | 可以 | 可以 | 不可以 |
| 归档小队、配置或清除 leader | 可以 | 可以 | 不可以 |
| 退出自己所在小队 | 可以 | 可以 | 可以 |
| 邀请工作区外新人、批准加入申请 | 可以 | 仅在同时为工作区管理员时 | 不可以 |

创建小队与将创建者加入为首位维护者原子完成。后续权限只看当前租户资格与有效维护者关系，
created_by 是审计信息，不提供永久特权。只有人类成员能成为维护者；Agent 不能通过其协作输出
变为工作区管理员或小队维护者。维护者可显式移交或撤回本队维护权，小队没有“最后维护者”阻挡：
即使所有维护者离开，当前租户管理员仍可接管，沿用已有最后管理员保护。

所有变更在服务端按当前资格与资源版本校验。跨租户对象不可见，不能通过读写错误枚举另一租户
成员；过期版本的写入产生明确冲突，客户端重新读取，不用最后写入覆盖撤销或归档。

## D3：leader 是可选的协作配置，配置不等于启用执行

小队可以没有 leader；人类成员或 Agent 成员也可为空，创建者显式退出后不伪造一个仍在队的人员。
界面将“编组存在”与“自动协作可用”分别表达。P1 只支持编组，所有小队都不提供自动委托入口。

leader 若配置，必须引用本队所属空间的活动 Space Agent；设置 leader 与必要的 Agent 入队关系
同事务完成。更换 leader 后旧 Agent 保留为普通队员，移除现任 leader 须在同一操作中明确清除或
更换其配置，不能留下一个仍被界面宣称有效的 leader。Agent 被退役时关闭有效编组，清除其有效
leader 配置并保留变更历史；不自动选择替代者。重新安装不自动恢复本队配置。

在两种类型名之间只做身份映射：Squad 的稳定 ID 即未来 `{type: team, id}` 的目标 ID，不增加
第二个协议目标类型。P1 不把小队注册为 Task 模式的可执行 Team 目标，也不使用开发夹具回复充当
真实执行。所有创建、入队、选择 leader、指派与编辑动作都不触发 IssueRun。

真实执行需后续 ADR 定义 leader 授权、显式意图、冻结上下文、委派因果、费用、串行交接和恢复。
即使配置了 leader，成员关系也不授予私人模型、Git 凭据或运行时使用权。

## D4：成员撤销与归档保留历史，但不保留有效资格

从某小队移除成员只结束本队编组，不停用工作区成员、不终止已准入运行。成员失去工作区资格时，
由 [tenancy 撤销事务](../tenancy/20261027-squad-targeted-joining-and-inviter-revocation.md#d5成员撤销与编组关闭保持同一权威)关闭其全部有效编组与维护权。
每次读取/写入仍先检查当前租户资格，不等待通知传播完成才拒绝访问。

归档不可通过普通编辑撤回，首期不提供恢复接口；归档关闭该小队的有效编组及 leader 配置，停止
新加入和编辑，从活动列表与选择器移除，保留历史供当前有权的工作区成员查看。定向加入中任何
目标已归档都按 tenancy 契约整体失败。归档不改变 Issue 负责人、不转交给原 leader、不重写运行
历史，也不隐式取消执行。P1 尚无真实 Team 指派，未来执行集成须另定义未完成工作的迁移责任。

添加成员、成员撤销、Agent 退役和小队归档的竞争必须有确定的提交顺序：若撤销/归档先提交，
后来的加入失败；若加入先提交，后来的撤销/归档关闭该资格。不能留下无有效资格的活动成员。

## D5：界面由真实状态投影，成员数不包含待加入意图

小队详情将“添加已有成员”“邀请新人”“添加智能体”分开；前者只选已有有效租户成员，邀请
入口继承工作区管理员权限。普通成员不能通过把邀请命名为“小队邀请”绕过工作区准入。

小队列表展示真实人类与 Agent 数量，详情显示成员职责和维护者；待兑换邀请及待审批申请另列。
未绑定接收人的邀请只有“待兑换邀请”，不能伪造待加入用户名。成员可以尚未加入任何小队；
“全部成员”若有聚合视图，来自真实成员目录，不成为自动执行的全员小队。

空列表、加载失败、无权读取与归档是不同状态；任何错误都不能回退 seed。安装状态、当前用户
配置完整性和执行可用性分别投影，不能用假在线指示暗示 Agent 可执行。成员目录与小队的变更
在提交后发送失效提示，列表/详情与关联选择器重新读取。SSE 不承载权威资格；断线重连、工作区
切换和重新聚焦仍校验/刷新当前状态，事件接收继续受租户成员撤销约束。

## 不变量

1. 有效小队成员必属于同一租户且满足其引用类型的当前资格；用户、Agent 和小队身份不混用。
2. tenant_memberships 是人类准入唯一权威，职责和维护者不产生新的资源/模型/执行授权。
3. 同一对象可加入多队，同一队同一对象最多一个有效编组；已结束编组不能隐式复活。
4. 工作区管理员可接管小队，创建人不持有永久权限；有效 leader 必为本队活动 Agent。
5. 小队变更不启动或取消运行；P1 不发布生产可执行 Team 目标。
6. 归档与撤销不丢失历史，当前访问与写入仍核验实时资格，不依赖缓存或历史快照授权。

## 为什么不是这些替代方案

| 方案 | 取舍 |
| --- | --- |
| 将全部工作区成员同步进默认小队 | 初次可见性简单，但失去明确加入意图，制造重复名单与自动恢复问题 |
| 小队即私有权限边界 | 隔离能力更强，但会改变所有共享资源访问，超出本次编组闭环 |
| 复制 user/Agent 并按名字匹配 | UI 接线容易，但用户改名、插件升级与撤权产生不同权威 |
| 创建者永久管理、强制最后维护者 | 维护者交接方便，但与真实工作区撤权冲突；现有管理员已能接管 |
| 配置 leader 就自动开跑 | 入口短，但违背显式执行意图，且没有费用及委派授权契约 |
| 仅隐藏停用成员、重入时自然显示 | 少一次关闭写入，但会自动恢复过去的编组和维护权 |

## 迁移、验证方向与落地

新增编组持久结构采用前向迁移，不回填演示小队/头像，不将既有全体成员自动编组；用户显式创建
首个真实小队并选择已有成员。成员及 Agent 退役的写入路径必须同批接入关闭编组责任，不能先上线
创建 API 后靠异步清理补安全约束。新建库与已有真实成员/邀请的升级库都须验证。

评审重点是多租户隔离、并发加入/归档/撤权、维护权恢复与幂等重放、旧详情 URL、两个用户的真实
加入与刷新、无 leader 编组及不产生执行。本文保持 proposed；评审通过后才在镜像目录维护核心用例，
不以这里的验证方向冒充已批准或已执行的证据。实现交付后按实际行为更新本决策与直接证据。

## 本决策未解决的问题

Team 执行与 leader 自动委派、私有队伍、跨小队嵌套、独立 Agent Profile、并行成果合并与小队归档
恢复均需独立后续决策。项目关联不在本期管理范围，不能借小队增加项目授权。
