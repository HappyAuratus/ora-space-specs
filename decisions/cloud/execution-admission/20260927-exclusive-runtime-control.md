# 运行时操作权绑定独占会话，旧入口关闭并结清执行责任后才交接

Cloud 以 PostgreSQL 当前状态裁决运行时操作权。使用权限、独占会话及写活动准入分别检查；每个
运行时至多一个有效持有者。到期、断线或撤权只关闭新资格，不能证明原任务结束，交接必须等旧
输入关闭和持久执行责任结清。

本决策的后端已实现于 Cloud、Controller 和 Node。前端获取/续期/释放、断线恢复及未覆盖联合
故障验收归入[后续 UI 与故障验收 ADR](20261013-runtime-control-ui-and-fault-acceptance.md)，
保持 approved。现有证据见[独占用例](../../../test-cases/cloud/execution-admission/exclusive-runtime-control.md)，
Partial/Missing 不因本次状态同步而改成完整验收。

## 决策

### D1：操作权由 Cloud 分配页面会话，普通管理员不能抢占

获取在事务中分配 session ID、绑定当前用户和运行时、增加 control epoch。第二页面不隐式复用
同用户资格；共享控制概况不暴露 session ID。只读不需要独占，但内容仍受使用权限约束。
创建、clone 和插件步骤使用有范围的系统维护身份，也占用同一写入边界。

### D2：数据库时间裁决租约，执行确认后才 held

租约 60 秒，续期契约为每 20 秒；续期只能延长尚有效的同一绑定，不复活过期代次。所有请求在
短事务中核验身份、权限、版本和幂等输入；网络/执行调用不跨事务锁。

| 状态 | 服务承诺 |
| --- | --- |
| idle | 获取原子预留 acquiring，竞争方 409 |
| acquiring | 当前 Node 确认绑定后 held；确认 stopped 且无存活沙盒时可直接 held |
| held | 有效绑定可续期；释放、过期或资格失效转 draining |
| draining / reconciling | 拒绝新资格，保留旧绑定和责任；关闭输入并结清执行后回 idle |
| maintenance | 只允许固定系统意图的执行，普通获取不能并行 |

历史幂等响应不恢复已失效资格。Node 重连可恢复可用性，但不能恢复旧页面绑定。

### D3：同会话仍只接受一个冲突写活动

clone、插件及会话执行等真实入口在持久接受和开始变更处校验绑定与活动互斥。任意命令不能仅按
名字推断只读；不能以 API 类型不同允许竞争写入。不同运行时可独立执行，项目生命周期仍串行。
后续文件/PTY 产品入口只有接入相同边界后才能开放。

### D4：撤回保存待办，不删除历史责任

成员/账号失效使新的 HTTP、续期、许可和事件投递重新校验失败，并保存旧资格撤回。已接受执行
按原稳定身份收尾，事实回报仍可接管；未接收动作不能因为已有数据库意图而被当作正在执行。
未知接受、未结束执行或输入未关闭都阻止交接。管理员紧急处置走独立强停，不直接夺取锁。

### D5：公开契约与审计由服务端拥有

服务提供控制读取、获取、续期、释放，以及安全的占用概况。权限拒绝与 409 冲突区分；客户端
不能自报用户/角色/代次建立权限。持久审计保留 holder、session、control epoch、期限、原因和
执行关联；proto/OpenAPI 由所属仓库生成。

## 实际同步与后续边界

原 approved 将浏览器行为和后端共同列为交付完成条件；本次按已完成后端划定 implemented 范围，
UI 与多实例/接受丢失等完整矩阵移到后续 ADR，原有安全义务没有删除。控制代次不替代 Controller
租约、运行时代次或真实终止证据；内存计数、超时与空新表均不能充当空闲证明。

## 不变量

1. PostgreSQL 原子预留一个会话，执行绑定确认前不开放新写准入。
2. 同一会话也不能启动两个冲突写活动。
3. 迟到续期和幂等重放不复活旧资格。
4. 未关闭输入、未结束/未知执行阻止交接。
5. 重连与旧派发只按稳定身份对账，不建立新的旧资格。
6. 当前成员、内容权限与跨租户隔离在每次入口核验。
