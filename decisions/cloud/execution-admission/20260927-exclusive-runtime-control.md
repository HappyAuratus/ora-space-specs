# 使用权限之外增加运行时独占操作权，交接前关闭旧入口并等待执行收尾

运行时以 PostgreSQL 中的权威状态决定谁可以操作；有使用权限不意味着可以在占用时操作。每个运行时至多一个有效操作会话，同一会话也不能让互相冲突的写活动并行。断线、租约到期或成员停用只撤回新的操作资格，已开始任务按生命周期收尾；确认旧入口失效且无未完成执行后才交接。

本 ADR 于 2026-09-28 经用户明确批准，状态为 `approved`，整体实施与验收尚未完成。它定义 Cloud 的业务独占与准入，不把数据库到期、浏览器关闭或 Controller 单连接当作真实进程停止的证据。Node 执行约束以[跨进程交付决策](../controller-integration/20260927-fenced-runtime-control-delivery.md)为共同生效条件。核心用例见[独占与安全交接](../../../test-cases/cloud/execution-admission/exclusive-runtime-control.md)，新保障的直接证据按核心用例逐项登记为 `Partial` / `Missing`。

## 现状与继承

前序[成员准入决策](0-access-follows-space-membership.md)经[一租户一空间](../tenancy/20260923-one-space-per-tenant.md)改为活动租户成员判断。[当前 access/admit](https://github.com/ora-space/cloud/blob/67dcbf95b408559acd5680cf36e84f30e4caad4a/internal/core/node.go)还检查运行时、Node 在线与准入开关，同一运行时可存在多个活动 ticket。ticket 是执行责任记录，不是单操作者证明。

| 前序约定 | 本决策处理 |
| --- | --- |
| 当前成员、运行时状态、准入开关与 Node 条件必须有效 | 继承，并增加[使用权限](../workspace/20260927-runtime-workspace-use-permissions.md)与独占校验 |
| 已准入执行保留 actor 与生命周期责任 | 继承；区分待派发、已接收、已结束和结果未知，不能将排队动作统称已开始 |
| ticket 幂等、Controller lease/epoch、idle 证据 | 继承；独占代次是独立维度 |
| 每项目一个未完成生命周期操作 | 继承；不同运行时可独立获得操作权，但生命周期仍受项目串行限制 |
| 成员可并行取得同一运行时的新写准入 | 修改：一个操作会话、至多一个冲突写活动 |

## 决策

### D1：操作权绑定会话，读操作不占用

操作权绑定运行时、当前用户、服务端确认的操作会话、单调递增的控制代次和有效期。会话标识只用于绑定，不是客户端自报身份；所有请求仍携带已验证凭证。第二个页面即使属于同一用户，也不得隐式共用操作权；恢复同一会话需重新核验身份及当前绑定。

只读查看不获取独占权，也不保证文件快照一致。进入编辑或执行模式需显式获取，离开时释放。操作权粒度为运行时，不把整个项目锁为一位用户专用。系统创建、删除、插件维护等也需受同一互斥状态约束，不能留下“没有用户所以不加锁”的写入入口。

新建运行时的初始 clone 由创建 operation 占有初始化写资格，完成后才允许用户操作；已确认停止的运行时可在 Cloud 获取操作权，但启动新一代后，必须先安装相应执行控制绑定，再开放内容写入。

### D2：租约以数据库时间判定，不以到期推断空闲

已批准的默认有效期为 60 秒、每 20 秒续期。租约表示有期限的操作资格。获取、续期、释放和新准入都在短数据库事务中核验当前成员、资源权限、状态和版本；不跨网络、文件或执行调用持有数据库锁。

租约过期不能通过迟到续期恢复旧代次。重新获取必须经历交接，新代次严格增加。重复请求使用原幂等键和原输入，返回原请求结果，但历史成功结果不恢复已经失效的操作资格，也不重新延长有效期。相同键不同输入沿用冲突契约。

| 当前状态 | 触发与前提 | 下一状态及行为 |
| --- | --- | --- |
| 空闲 | 有权限者获取，数据库原子预留 | 获取中；其他获取返回 409 |
| 获取中 | 当前执行目标确认控制绑定，或已确认没有存活执行目标 | 持有中；此后才可申请新写活动 |
| 获取中 | 外部结果不明、崩溃或身份失效 | 待对账；禁止直接返回空闲 |
| 持有中 | 同绑定在到期前续期且权限有效 | 持有中；保持控制代次 |
| 持有中 | 释放、断线后到期、成员停用或权限失效 | 收尾中；拒绝新操作，关闭旧输入入口 |
| 收尾中 | 旧入口关闭已确认，全部活动已结束 | 空闲；保留历史执行与审计 |
| 收尾中 | Node 不可达或存在未知执行 | 待对账；不交给新操作者 |
| 待对账 | 恢复后确认旧入口失效且全部活动结束 | 空闲；新的获取使用新代次 |
| 任一状态 | 管理员发起有效强停 | 进入生命周期强停流程，确认终止前不交接 |

断线可提前关闭已知失效的会话，但不能假设能立即检测所有网络分区。Cloud 在租约到期后拒绝新请求；Node 的已登记执行、迟到派发及跨进程撤回确认按交付决策处理。前端断线时立即停止本地发送和自动提交，恢复后重新读取权威状态，不盲目重放离线编辑。

### D3：独占会话内仍需写活动互斥

活动是一次可能改变代码目录、Git 状态或运行环境的执行责任。不能靠命令名称判定任意 shell 为只读，也不能以 Agent、终端和文件 API 不同就认为可以并行。

| 组合 | 第一阶段规则 |
| --- | --- |
| 不同运行时的内容读取和普通执行 | 可并行，各自校验权限与操作权；保留项目生命周期串行 |
| 同运行时多个获准只读的观察者 | 可并行，事件与输出每次投递重新校验所需权限 |
| 单次文件写入、Git 变更、Agent、shell/终端执行之间 | 同一运行时至多一个冲突写活动；第二个返回 409，不自动排队 |
| Agent 运行时同一操作者继续编辑或启动另一任务 | 拒绝；持有操作权不等于可以竞争写入 |
| 终端输入属于当前活动 | 仅有效操作会话可输入；释放或撤权后拒绝新输入，已运行命令收尾 |
| shell 产生后台进程 | 进程组或运行范围仍负有执行责任，不能以 shell 返回就报告空闲 |
| 插件维护与人工作业 | 共用互斥边界；维护意图可持久等待，人工作业不自动排队 |

任意命令都可能写文件或留下后台工作。支持这类入口前，必须能跟踪其运行范围和结束证据；不能证明时保持占用或待对账。第一阶段没有实现的文件、PTY、Agent 入口继续不可用，不能把界面禁用视为服务端完成控制。

### D4：撤权不丢失执行责任

成员停用事务立即让后续 HTTP、续期和准入失败，同时保存撤回待办。已经开始的任务继续收尾，但不能接受新的交互输入或新增顶层任务；原任务内部已授权的执行范围不能被当作无限续权通道。

仅存为意图、尚未被执行端接收的动作不能因“已写入数据库”就自动视为运行任务。派发前重新校验；响应丢失时按稳定执行身份对账，无法判断是否已开始则保留未知状态并阻止交接。撤回不删除 ticket、execution、effect 或成员审计引用。

管理员可以在旧会话失效后等待正常收尾并接管；有效会话正在使用时，普通获取返回占用。紧急打断通过[强制停止](../operation/20260927-safe-stop-and-administrative-force-stop.md)，而不是直接夺走锁。被移除创建者仍不能通过旧 token、旧控制代次或重试结果继续取得操作资格。

### D5：最小公开契约与审计

在既有版本、幂等键和 Fault 契约上增加控制状态读取、获取、续期、释放能力，以及服务端计算的有效操作集合。权限不足与占用冲突分别表达；占用返回 409，安全参数仅包含允许公开的概况。任何接口都不能接受服务端拥有的 userId、角色或控制代次作为授权来源。

Cloud 持久记录取得者、会话、代次、期限、状态、变更原因、任务 actor 和执行关联；每次交接可追溯。租约、活动登记及事件投递的权限核验不依赖单进程锁或前端状态。开发时字段和路由通过仓库生成流程同步。

## 为什么不是这些替代方案

| 方案 | 取舍 |
| --- | --- |
| 只锁用户，不锁同一用户的并发活动 | 能挡住其他成员，却挡不住自己同时启动 Agent 和编辑 |
| 到期立即把锁交给别人 | 恢复快，但旧进程可能仍写同一目录 |
| 断线或成员移除立刻杀掉全部任务 | 撤回直观，但违背已开始任务收尾约定，可能丢失未落盘工作 |
| 所有人工作业自动排队 | 提交方便，但过时意图可能在很久后执行；第一阶段要求用户看到冲突并重新判断 |
| 只使用进程内 mutex | 单实例简单，重启、多实例和旧执行端不受 PostgreSQL 权威约束 |

## 不变量与预期验收

1. 同时争用、两个管理员及同用户两个会话，数据库只允许一个有效持有者。
2. 有效会话也不能获得两个冲突写活动；拒绝方不产生文件、Git 或进程副作用。
3. 续期与到期、准入与撤回竞争均有可判定的先后顺序；迟到续期和幂等重放不复活旧资格。
4. 未知执行、未关闭输入、未确认终止均阻止交接；数据库过期不充当执行结束证据。
5. 旧会话恢复、重复派发、Node/Controller 重启不产生新写入或第二次任务。
6. 读权限、成员停用、跨租户隔离与现有安全停止证据保持有效。

## 落地顺序与后续边界

核心用例已建立；接下来完成 PostgreSQL 权威状态与跨进程执行协议，再开放前端获取/释放操作权。必须用真实 Node、Git、磁盘及进程证据验收旧操作者失效；仅 Cloud 或模拟器通过不能标记完整实现。实时合并、人工作业队列和并行写活动的精细分类不在第一阶段。
