# 成员加入来源与私有链接预检

继承 [一空间一租户](20260923-one-space-per-tenant.md) 的唯一成员权限、7 天单次邀请、30 天多人审批申请、令牌仅存摘要与内网目录加入。新增受限只读预检和真实加入来源；已有有效成员接受普通邀请时不消费 token。当前为 `approved`，表示契约已批准，不代表已实现或上线。涉及 Cloud、Gateway 与成员管理及受邀页面；小队编组与签发者失权策略由定向加入契约承接，本文只规定与它们相交的披露、消费和来源边界，不授予小队权限。

## 继承与修改

| 前序约定 | 处理 | 本决策的规则 |
| --- | --- | --- |
| 一空间一租户、唯一成员权限、admin/member 与最后管理员保护 | 继承，不变 | 来源记录不成为权限权威，当前权限仍来自 tenant_memberships |
| 7 天单次邀请、30 天多人审批申请、摘要存储及内网目录核验 | 继承，不变 | 预检不兑换、不延长期限、不替代审批，企业目录部署关闭链接入口 |
| 加入写接口要求认证并在事务内校验 | 继承，不变 | 仅新增一个受信 Gateway 可调用的只读预检入口，其结果不授予资格 |
| 已有有效成员接受普通邀请也消费 token 并通知成员刷新 | 修改 | 既未建立/恢复租户资格、也未新增编组时不消费、不发加入通知；有任一真实资格或编组新增才消费 |
| 加入成功建立成员关系，幂等重放不重复通知 | 扩展 | 真实建立或恢复资格时同事务追加来源，空操作和重放不追加 |

## 问题与约束

只有提交兑换后才能发现失效，会让受邀人先登录再遇到死路；直接开放成员接口则泄露工作区信息。预检以最小响应提前解释状态，代价是增加一个需同源校验、限流与服务身份保护的匿名读取边界。来源必须来自真实资格变更，不能把“有人消费过链接”推断为“此人通过该链接加入”。

## D1：只读预检与身份边界

`POST /api/v1/join/links/preview` 接收类型和 token。Gateway 只为此确切方法和路径允许无会话请求，校验同源和限流，移除浏览器提供的内部身份头，以自己的服务身份调用 Cloud。Cloud 仍校验 gateway 服务角色，提供用户身份时必须验证 caller 绑定；企业目录部署关闭此入口。

预检不调用身份创建，不产生用户、成员、申请、幂等或审计写入。匿名仅得到类型和 active/used/expired/revoked/unavailable；未知令牌、失活租户或空间统一 unavailable，不返回租户、人员或使用者。定向加入契约引入的签发者失权、定向目标归档或不合法也一律归为 unavailable，不新增匿名可见的状态值，不暴露签发者、目标或具体失效原因。已登录、活动的用户可以获得目标工作区确认信息及自己已加入/待审批的状态；这不开放成员、项目或小队名册。已有有效成员优先进入工作区，即使该邀请已使用或到期；失活工作区不提供进入入口。

预检不是兑换授权。真正写入仍在原事务内重新校验；原 join_link_unavailable 错误码保留，增加安全的 reason 参数。多条件重叠时 used 优先于 revoked，再于 expired；其他不可用统一 unavailable。外部页面永不显示兑换者。

## D2：已有成员不消耗普通邀请

修改此前“已有成员也消费邀请”的实现契约，统一规则为：既未建立/恢复租户资格、也未新增编组时不消费 token、不发加入通知、不新增工作区加入来源；有任一真实资格或编组新增才消费。

| 接受情形 | 行为 |
| --- | --- |
| 已有有效成员接受同工作区普通邀请（目标为空） | 空操作，返回自己的成员状态，不消费 token、不变角色、不记录新的加入、不发加入通知 |
| 新成员或停用成员接受普通邀请 | 必须持有当前有效邀请；建立/恢复资格、消费与来源同事务提交 |
| 已有有效成员接受定向邀请，已在全部目标队伍 | 同一空操作规则，不消费、不发加入通知、不新增工作区加入来源 |
| 已有有效成员接受定向邀请，新增至少一个编组 | 消费一次邀请，保留原租户角色；仅记录编组来源，不伪造工作区再次加入 |

后两项是与定向加入的契约边界，不在本轮实现小队。并发与幂等语义不变：不同接受者竞争普通单次邀请，只有一次真实准入可消费；空操作不占用它，其他合法接受者仍可使用。相同命令重放原结果，不再次授予资格、消费、记来源或发送通知；同键不同内容仍冲突。成员之后被移除，重放旧成功响应不能恢复资格，进入工作区仍检查当前成员状态。

## D3：来源是成员变更的持久事实

仅在真实建立或恢复租户成员资格的同一事务追加加入来源记录（membership_join_events），保存租户、用户、方式、发起/授权人、时间及关联邀请或申请。方式包括创建工作区、单次邀请、批准申请、目录添加；开发专用身份不伪装成真实邀请。邀请、审批、目录三种渠道均在资格变更事务内记录来源；任一步失败全部回滚。已有有效成员、重复审批与幂等重放不追加记录。已有成员经定向邀请或审批仅新增小队关系，不写工作区加入来源，编组来源由小队关系承载；同时建立/恢复租户资格和编组时，两种来源分别记录并原子提交。记录不成为第二份权限权威，当前权限仍只来自 tenant_memberships。

管理员可以读当前来源和重新加入历史，普通成员只能读基础名册；服务端承担权限和租户隔离，不能只隐藏按钮。历史迁移不根据 consumed_by 猜测加入，因为旧实现允许已入成员消费 token；无法严格证明的历史来源显示未记录。人员显示名来自当前名册，历史 actor ID 和链接引用永久保留。

## D4：链接管理与兼容

两类链接可带管理备注，不绑定收件人、不改变准入。原文只在生成弹窗内存中存在，关闭、换工作区或离开页面即丢弃；可反复复制同一原文但不增加次数。管理列表提供创建者、时间、状态、使用者或申请统计。生成/撤销/审批失败与空列表区分，用户页面准确区分已使用、到期、撤销及服务故障。

新增前向迁移保存备注与来源记录；保留旧表、摘要、版本和旧客户端兑换错误码。新客户端依赖的新字段由生成契约声明，OpenAPI、生成客户端和中英文文档同步。发布时先迁移，再更新 Cloud 与 Gateway，最后更新前端；旧前端可继续调用原写接口。

## 为什么不是这些替代方案

| 方案 | 取舍 |
| --- | --- |
| 只改前端错误文案 | 成本低，但不能匿名提前识别失效，也不能阻止已有成员消费邀请或可靠追溯来源 |
| 匿名开放成员或完整邀请详情 | 确认信息更丰富，但超出类型/状态所需，暴露工作区、签发者或目标 |
| 从 consumed_by 回填历史来源 | 易于生成完整列表，但旧行为允许已有成员消费，不能证明加入因果 |
| 资格提交后异步补来源 | 缩短事务，但失败时留下无法解释的成员资格，与可靠来源要求冲突 |

## 不变量与验收

- 匿名、伪造用户头、非 gateway 服务不能读成员或人物；预检前后业务表计数和版本不变。
- 匿名只返回类型和五种状态；签发者或定向目标失效统一 unavailable，不泄露原因细节。
- 并发单人兑换只有一次准入；既未建立/恢复资格也未新增编组的空操作不消费、不通知，停用者无有效 token 不可重入。
- 每次准入与来源原子提交，重复和重放不增记录，失败不留下半条历史。
- 旧数据来源不伪造，来源详情仅管理员可读且不能跨租户。
- 匿名失效提示、登录恢复、申请审批、复制/关闭、桌面与窄屏中英文均须提供实际验证。

核心验证义务见[加入来源与链接预检](../../../test-cases/cloud/tenancy/member-entry-provenance-and-link-preview.md)，没有直接证据的义务标为 `Missing`。先完成契约与用例，再交付迁移、服务端及页面验证；产品实现合并后按最终行为和直接证据落档为 `implemented`。邮件邀请、多人直接加入、小队实现及历史来源推断不属于本决策。
