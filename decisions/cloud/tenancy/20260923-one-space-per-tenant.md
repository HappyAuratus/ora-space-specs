# 每个可见协作空间对应一个租户，以租户成员身份授权

> 后续决策：[运行时使用权限](../workspace/20260927-runtime-workspace-use-permissions.md)与[独占操作准入](../execution-admission/20260927-exclusive-runtime-control.md)的后端规则为 `implemented`，UI/完整故障矩阵由后续验收 ADR 承接；[凭据连续性](../project/20260927-repository-credential-continuity.md)为 `implemented`。本文身份、成员规则和实现状态保持不变。

本决策继承 `0-self-serve-tenant-provisioning.md` 的已验证身份自助创建、原子建立首位管理员和空间、创建幂等性以及最后管理员保护；修改其「租户是隐式容器、可以再建多个空间、前端只取首个租户」的约定。用户可创建和加入多个独立空间，并明确切换。当前只有测试数据且没有独立 API 客户端；旧迁移保持不可变，新规则已通过前向迁移和同步更新的 v1 契约落地。

## 继承与修改

| 前序约定 | 本次处理 | 当前规则 |
| --- | --- | --- |
| 已验证用户可自助创建租户；创建幂等 | 继承，不变 | 创建租户、唯一空间与首位管理员仍在同一事务 |
| 最后管理员保护 | 继承，不变 | 最后一位有效管理员不能被停用或降级 |
| 租户是隐式容器，可有多个空间及独立空间成员 | 修改 | 一个可见空间就是一个租户；租户成员表是唯一角色来源 |
| 前端以首个租户定位空间 | 修改 | 完整列出用户空间，按选中 slug 定位对应租户 |

## 为什么不是这些替代方案

| 方案 | 取舍 |
| --- | --- |
| 保留租户内多个空间与两层成员表 | 可表达更细组织层级，但两份权限会使加入、移除和准入产生不一致 |
| 为每个空间复制租户成员表 | 能短期复用旧接口，但角色冲突与最后管理员保护仍需双重协调 |
| 公开空间目录或按邮箱域自动加入 | 加入便捷，但无法可靠证明管理员授权；内网身份和公网邀请都需要明确授予 |

## D1：租户是协作和授权边界

一个活动租户恰有一个可见的协作空间信息行。`tenant_memberships` 是唯一的成员角色与状态权威，只有 `admin`、`member`；所有管理员平权，创建者没有永久特权。Project、运行时 Workspace 和执行准入由有效租户成员身份授权。停用成员立即拒绝新访问；已建立的事件流在下次通知投递前重新校验成员身份并关闭，不能继续接收空间变更。已准入任务保留原生命周期和审计引用。最后一个有效管理员不能退出、被停用或降级。

共享 Project 允许不同成员读取、修改并创建运行时；同一 Project 同时只有一个未完成的生命周期操作，竞争者收到 `409 operation_in_progress`，待操作完成后再重试。本决策确立共享资源的访问和生命周期边界，不定义同一运行时目录内的实时编辑合并，也不把前端演示任务或聊天数据作为租户共享状态。

与上游独立运行时模型共同生效：每个运行时按自己的引用克隆仓库，共享访问不会恢复已停用的项目共享存储或工作树创建流程。操作发起成员与项目的持久所有者分别记录。租户迁移编号为 0017，保留上游 0001–0016 不变；旧 PR 编号的测试库须重建。

## D2：空间地址与生命周期

空间 slug 全平台唯一、创建后不可变、归档后不复用。租户与唯一空间同名，改名在同一事务更新两者。新建空间总是新建租户，不再在现有租户中创建第二个空间。旧的空间级成员写接口与空间创建、归档接口从 v1 契约移除；空间级项目路径仍指向租户的唯一空间。已应用迁移不重写；检测到复用 slug、多个空间或租户与空间名称不同的历史测试数据时明确失败并重建测试库，不静默删改数据。

## D3：加入与管理

内网管理员可通过受控人员目录将已在职人员直接加入，首次 IDaaS 登录时绑定身份。公网管理员可生成 7 天、单次兑换、只授予 `member` 的邀请链接，或生成 30 天、可重复使用但仅用于提交申请的链接。申请由管理员批准才产生成员关系。令牌只保存摘要、可撤销；跨租户成员身份从不自动推断。内网部署不开放链接加入，以免绕过在职核验。租户级成员写接口只调整既有有效成员的角色或停用状态，不能直接新建或恢复成员；已停用者重新加入仍走目录核验、邀请兑换或申请批准。三种加入路径成功建立成员关系后均通知已在线成员刷新列表；幂等重放不重复通知。

## 本决策未解决的问题

- Project 的 `owner_user_id` 与 Git 凭据引用仍保留创建者归属。成员停用不会自动转移或撤销项目已有凭据；团队凭据及创建者离开后的处理需要单独决策，以免在权限收回时误停共享项目。
- 同一运行时内多人同时修改工作树的冲突处理、任务与聊天的持久共享状态需要独立的业务与执行协议。当前租户成员关系只定义准入和资源共享，不保证这些内容的实时合并。

## 不变量与验收

1. 活动租户恰有一个活动空间，成员权限只有一份权威数据。
2. 空间地址不能指向另一租户；同一用户可安全切换多个租户。
3. 并发兑换、审批和角色调整不能绕过一次性令牌或最后管理员保护。
4. 搜索、邀请与申请均不能让未获授权者读取租户成员或项目。

受影响的核心用例位于 `test-cases/cloud/tenancy/`、workspace、project、execution-admission、api-boundary 与 persistence。旧测试数据不兼容时明确重建，既有生产数据拆分不在本次范围；外部运行任务的终止与恢复顺序保持原有契约。
