# 定向加入原子建立工作区与小队资格，邀请随签发者失权永久失效

加入意图可以携带同租户的小队目标；资格建立与全部编组、邀请消费在一个事务提交。无目标的普通
邀请保持只加入工作区。签发者失去邀请权会永久终止其尚未消费的邀请，之后恢复管理员身份不恢复
旧邀请。工作区成员撤销与关闭其小队关系共同提交，重新加入不能复活旧编组或维护权。

本决策为 `proposed`，继承并修改 [20260923 一空间一租户](20260923-one-space-per-tenant.md)，
与 [小队根决策](../squad/0-workspace-scoped-human-agent-squads.md)共同构成编组加入契约。
修改覆盖已有普通邀请的失权及空操作消费语义，必须通过前向迁移和升级部署启用，不能仅新增前端字段。
不改变外部登录身份映射、邀请有效期、内网目录核验、个人模型和既有运行生命周期。

## 继承与修改

| 前序约定 | 处理 | 本决策的规则 |
| --- | --- | --- |
| 一租户一空间、唯一成员权威、admin/member、最后管理员保护 | 继承，不变 | 小队关系不授予租户角色，也不引入独立 Space owner |
| 7 天单次邀请、30 天可复用申请链接、令牌摘要与可撤销 | 继承，不变 | 不延长存量有效期，不改为可重复直接入会；空操作不属于一次消费 |
| 当前普通邀请对已有有效成员也消费 token 并通知成员刷新 | 修改 | 与已批准的成员加入管理决策一致：既未建立/恢复租户资格、也未新增编组时不消费、不发加入通知；有任一真实资格或编组新增才消费 |
| 已有有效角色不因邀请被覆盖；停用成员重入须核验 | 继承，不变 | 已有 admin 接受定向邀请不降级，重入通过既有加入渠道 |
| 邀请/审批只建立租户关系 | 修改 | 可携带明确目标，同事务建立全部指定小队关系，任一目标无效整体失败 |
| 可用链接只检查其撤销、消费、期限与租户状态 | 修改 | 增加签发者有效邀请权及不可复活的签发资格，适用于无目标与有目标的链接 |
| 租户成员停用关闭访问，运行保留原生命周期 | 扩展关闭责任 | 同事务关闭该用户全部有效小队关系和维护权；运行及审计仍保留 |
| 加入后通知在线成员，幂等重放不重复通知 | 继承并扩展失效范围 | 通知相关成员/小队读取投影；通知不是资格权威 |

## D1：目标来自服务端冻结的加入意图

只有当前工作区管理员可创建外部邀请或申请链接。可选择零个或多个当前未归档、属于同一租户的
小队；使用稳定 ID，重复目标规范化为同一集合。目标集合在签发时冻结，修改名称不改变目标，
目标失效不自动换成别的队伍。要改目标必须撤销旧链接并重新签发，不能让接受者确认一组队伍后
在兑换时被加入另一组。每次加入意图最多包含 20 个不同小队，超过上限整体拒绝，并沿用公开 API
的请求大小限制；这个小而固定的上限约束事务写入量，不能靠前端限制替代服务端校验。

定向邀请只授予普通小队成员，不授予维护权或工作区 admin。已有有效用户的工作区角色保持不变。
人类编组与 Agent 配置严格分离：外部邀请不能添加或配置一个 Agent，也不能指定 leader。

预检与确认分两级：未登录的匿名预检只返回链接类型和状态，沿用成员加入管理的受限只读入口，
不返回工作区、邀请者、目标小队名或名册。签发者失权、目标归档或不合法统一归为 `unavailable`，
不新增匿名状态或暴露原因细节；预检不产生写入，也不构成兑换授权。

登录且身份有效后，确认页才在显式接受之前展示工作区、邀请者、将加入的小队名与普通成员权限，
只提供该 token 对应的最小确认信息，不开放工作区完整成员、项目或小队名册；最终提交仍重新
校验全部资格与目标。登录回跳保留原加入意图，客户端任意 query/body 中的目标不是授予依据。
令牌仍仅持久化摘要，不进入日志、分析事件或外部身份提供方的回跳参数。

## D2：单次邀请的成功只有一个原子结果

兑换在认证后执行，并在一个短数据库事务中校验 token、期限、撤销/消费状态、租户/空间、签发者
资格和全部小队目标，再建立或恢复租户资格、增加缺失编组、按实际变更记录来源及决定是否消费
邀请，并持久化幂等结果。
事务内不访问外部身份服务、发送通知或启动执行。任一步失败都不产生新的资格、编组或消费事实。

| 接受者/目标情形 | 行为 |
| --- | --- |
| 新用户或此前停用的成员 | 按原加入规则创建/恢复普通租户成员，仅加入本次目标 |
| 当前有效成员 | 保留原角色和状态，只增加缺失的目标编组 |
| 已有有效成员，已在全部目标队伍 | 空操作：不消费邀请、不发加入通知、不新增工作区加入来源；普通邀请目标为空时也适用 |
| 已有有效成员，新增至少一个目标编组 | 消费一次邀请，保留原租户角色；只记录编组来源，不伪造工作区再次加入 |
| 任一目标被归档或已不合法 | 整体拒绝，邀请不被消费，接受页说明需重新获取邀请；不得悄悄只加入工作区 |
| token 过期、撤销、已消费或签发资格失效 | 不建立任何新关系，按不可用处理 |

同用户、同幂等键、同请求重放原结果；同键不同内容冲突。不同用户或不同幂等键竞争同一邀请只能
有一个真实变更导致的首次消费成功；空操作不占用单次邀请，其他合法接受者仍可使用。同一空操作
幂等键重放只返回原结果，不因之后的状态变化重新授予；需要重新接受须使用新的命令身份。
响应丢失不需要管理员再次签发；同键重放不再次消费或发送加入通知。

工作区加入来源 `membership_join_events` 只在真实建立或恢复租户资格时追加；邀请、审批与目录
三种渠道共用资格变更事务记录来源。已有成员通过定向邀请或审批只新增小队关系时，不写工作区
加入来源，其来源保存在小队编组关系中。新建/恢复租户资格同时入队时，两种来源分别记录且原子
提交；任一步失败均回滚。空操作与幂等重放不追加来源、不发加入通知。

重放是返回历史命令结果，不是重新授权：若成员随后已被移除，重放不能恢复租户或小队关系。
成功页进入资源时重新读取当前资格；不能将旧成功响应当作继续访问工作区的凭证。

## D3：签发者失权永久终止旧邀请，不能只在接受时检查当前角色

签发者必须同时是有效用户、有效租户成员与当前 admin。以下变化一旦提交，其未消费且未失效的
邀请与仍可用于新申请的申请链接永久失效：管理员降级、成员停用/移除、用户停用/删除，以及其它
正式撤销该租户邀请权的操作。已消费邀请与已建立的其他成员资格不追溯撤销。

签发与撤权竞争必须在权威事务中串行判定；不能先检查 admin、释放锁，再写一个仍可用的邀请。
兑换与撤权的先后结果明确：兑换先提交，成员已合法加入；撤权先提交，兑换失败。失权操作失败
（例如最后管理员保护）不能附带撤销邀请。重新授予 admin 只允许签发新邀请，不使旧 token 复活。

持久记录须能证明失效不可逆，可采用显式终止链接或签发资格代次；仅存 created_by 并在兑换时
看其当前 role 不足以满足此规则。涉及多租户的用户停用也必须覆盖其所有租户的签发资格，不能
仅在当前页面的 tenant 上处理。客户端列表与预览应显示当前不可用状态，不继续提供可用承诺。

这一规则同时覆盖普通和定向邀请。对申请链接，失权停止接受新申请；已合法提交的 pending 申请
是独立、已记录的用户意图，可由另一位当前管理员按 D4 明确批准。撤销链接同样不自动拒绝既有
pending 申请；管理员可逐项拒绝，申请者可以看到决定。此区别避免把“签发入口”和“审批决定”
混为一次权限授予。

## D4：审批与目录加入复用同一编组不变量

申请提交时冻结链接中的目标 ID 集合，不产生租户资格或小队关系。保持每用户每租户最多一个
pending 申请；重复提交相同目标返回既有申请，不悄悄修改目标。已有 pending 申请但新提交目标
不同则明确冲突，保留原申请供决定；不能把申请 A 的同意解释成申请 B 的队伍选择。

审批时由当前有权管理员确认原目标集合，重新验证当前用户、租户及全部目标；批准在一次事务
建立必要租户资格、全部目标编组与审批结论。任一目标失效则批准失败，申请保持 pending，不产
生半加入状态；管理员可拒绝该申请，用户从正确的新链接重新申请。已有成员通过另一渠道先加入
工作区时，审批仅增加缺失编组，保留其现有角色，不新增工作区加入来源。审批版本竞争保证只有
一个最终决定；已是成员且已在全部目标队伍时可完成审批决定，但不伪造加入来源或发送加入通知。

公网普通成员不能调用审批能力。内网目录加入仍先通过受控目录核验；增加目标时与建立资格同
事务落实。外部核验按原有边界完成，提交时重新检查管理员与目标状态，不跨网络持有事务；内网
不因新增小队而启用公网链接加入。三种加入渠道共用同租户、当前资格与全部目标原子成功规则。

## D5：成员撤销与编组关闭保持同一权威

成员从有效变为无效的权威写入中，同时关闭该用户在该租户全部有效小队成员关系和维护权；对
用户全局停用/删除覆盖所有受影响租户。已结束关系及引用它们的历史不删除。服务端读取/写入始终
检查当前用户与租户成员资格，即使失效事件延迟或丢失，也不能继续使用旧页面上的权限。

被移除后重新接受邀请或审批，仅增加本次明确的编组，不恢复旧维护权。对一位仍有效的 admin
仅降级为 member，不自动移出其小队或撤销独立的本队维护者身份，但立即终止 D3 的签发资格；
小队维护者从此不能邀请外部新人。最后管理员保护保持原义。

关闭编组与并发入队采用一致的当前资格检查和提交顺序；不能留下已停用用户的活动编组。已经
准入的执行仍按原运行、成果保存及释放契约继续收尾，不将组织撤销偷换为直接杀死运行。

## D6：兼容升级保留已发生事实，明确启用时间

前向迁移新增目标与不可复活的签发资格记录，不改已应用迁移，不复制租户成员表，也不重建有
真实用户的数据库。已消费/撤销邀请、申请决定、既有成员与已结束运行保持不变。旧邀请和申请
链接的目标集合为空，旧 pending 申请也只代表加入工作区；不根据访问页面或演示小队推断目标。

在新策略启用时，旧未消费邀请及可用申请链接按当前签发者资格处理：当前有权的绑定到启用时的
有效签发资格，保留原 token 摘要、期限和单次约束；当前无权的永久失效。系统无法可靠重建升级前
管理员曾失权后恢复的历史，不伪造旧事件；不可复活规则从本次启用起生效，启用时点应有审计事实。
若部署需要追溯旧失权历史，应先明确撤销相关存量邀请，不以猜测替代证据。

启用需要阻止仍按旧规则写入的 Cloud 实例并行处理请求：先暂停加入/成员写入，升级所有相关写入
实例与 schema，再统一开放；或以服务端可验证的最小写入版本实现等价门禁。不能仅升级一台实例
后宣称整个集群已满足撤权原子性。迁移/启用失败时保持入口关闭，不回退旧写入路径继续授予资格。

不支持用旧二进制回退绕过新授权规则；回滚须保留新门禁或关闭相关写入口。新建库与含存量邀请、
pending 申请、有效及停用成员的升级库均须验证，迁移编号按合并时 main 顺序追加。

## 不变量

1. 工作区资格、全部指定编组和消费/审批事实只有一次原子成功，不存在部分成功。
2. 任何目标都来自冻结、同租户、仍有效的服务端意图；客户端不能扩大授予范围。
3. 当前有效成员接受定向加入不丢失原角色；普通邀请不隐式编组或提升权限。
4. 启用后签发者失权永久终止其未消费邀请与新申请入口，之后复权不恢复旧链接。
5. 当前管理员批准既有申请是独立授权行为，仍重验申请者与全部冻结目标。
6. 撤销工作区资格同时关闭有效编组，重新加入和幂等重放均不恢复旧编组或维护权。
7. 令牌摘要、单次消费、期限、最后管理员保护与内网目录核验不因编组而弱化。
8. 空操作不消费邀请、不发加入通知；仅新增编组也消费一次，但不记录工作区加入来源。
9. 匿名预检只返回类型与状态，签发者或目标失效统一为 unavailable；确认信息只向已登录有效身份提供。

## 为什么不是这些替代方案

| 替代方案 | 取舍 |
| --- | --- |
| 先加入工作区再异步入队 | 加入延迟低，但目标失效时用户得到未确认过的部分结果，且需要长期补偿责任 |
| 无效目标忽略，剩余目标继续 | 成功率高，但改变用户明确确认的加入集合，隐藏管理错误 |
| 在 URL 上附 squadId | 接线简单，但缺少服务端冻结意图与权限依据 |
| 失权只检查当前 role | 少一份失效事实，但复权会复活旧 token，违背不可复活语义 |
| 签发者失权直接拒绝所有已提交申请 | 简单，但阻止另一位当前管理员作新的独立审批决定 |
| 升级时作废全部旧链接 | 易于保证统一边界，但不必要地打断仍有权管理员的有效邀请；本决策保留它们并明示启用边界 |

## 验证方向、风险与落地

重点核验真实 PostgreSQL 上的兑换/撤权/归档/审批竞争、同键与异键重试、已有管理员角色保留、
全局用户撤销的多租户覆盖、复权不复活旧链接、成员重入不复活编组，以及存量升级与旧写入者门禁。
还需直接验证：普通邀请和定向邀请的空操作均不消费，新增一个编组即消费，三种渠道只有真实
租户资格变更才记录 membership_join_events，纯编组来源不混入工作区历史，以及匿名结果不含
工作区/签发者/队伍细节、登录后确认与提交重验的分级边界。
跨浏览器验证定向接受前说明、接受后的名单与人数、重连刷新、待审批与已加入的区分。事件只在
提交后发出，重放不重复发出；事件或浏览器中断不改变持久资格。

本决策尚待评审，核心用例按仓库规则在 approved 后维护。实现须同时覆盖加入、角色/用户撤销、
编组和迁移写入路径；只有前端入口完成不足以启用此契约。产品实现后再按最终行为与证据标为
implemented。邮箱定向邀请、私有小队与自动执行授权不属于本文。
