# 任务保留持续对话，已结束的 Thread 通过新运行续聊

Issue 的持续对话聚合评论、用户轮次、Agent 对外回复与执行记录；Run/Thread 仍描述一次执行。
同一可用 Thread 内继续追加，已结束时创建后续运行，恢复任务上下文和已保存成果。用户切换 Agent
不改变任务身份，也不重开已结束的 Thread。

本提案等待 owner 决策；兼容已有 Thread 终态、条目序号、个人模型权限与历史数据。新增任务级入口
是旧入口上的编排能力，不把独立 Chat、Workflow 或 Agent 子会话纳入同一身份。

## D1：任务消息引用原始事实，重试不重复创建执行

任务级对话消息具有任务内稳定顺序、发起者、显式目标、内容和来源引用。消息索引引用评论、Thread
用户轮次或 Node 输出投影，不复制一份可独立编辑的完整会话。首条系统提示和用户消息回声不再次显示
为用户消息。运行结论与逐轮回复若来自相同输出，引用同一来源，避免重复回复。

新增任务级读取、发送、取消待执行消息接口。发送携带幂等键；消息、队列意图与原始输入的关联在同一
事务提交。响应丢失后重试返回同一消息。取消仅影响尚未执行的消息，不能伪装成已取消运行。

普通评论保持不触发执行。输入框明确显示本次目标；选择 Agent 本身不发送、不停止，也不修改负责人。
对历史回复的引用属于新消息上下文，默认仍基于最新成果，不能隐式选择旧 Revision。

## D2：输入授权跟随实际执行发起者

同一 Agent、同一发起者、授权仍有效且尚无交接屏障时，复用当前 Thread。其他情况进入任务队列并创建
后续运行。新运行冻结该条消息发起者的个人配置，不继承前一运行的凭据。成员可读不代表可以追加其他
成员的模型请求；无权终止当前运行的用户不能通过切换操作绕过结束权限，交接须等待合法结束。

资格在接收和派发时均验证。目标归档、成员撤销、模型配置失效时消息保持可解释的失败/待处理状态，
不自动改发另一 Agent。停止、失败和保存异常的后续处理由
[任务串行交接](../issue-run/20261018-serialize-task-agent-handoffs.md)定义。

## D3：恢复代码成果与恢复对话上下文分别建立证据

初始提示必须包括已冻结的任务标题、说明、显式上下文引用、当前消息及历史范围；已有快照中的 issue
和 recentComments 不能被渲染器丢弃。成果恢复继续引用已登记 Revision，聊天历史不充当成果可用证据。

Agent 原始记录的正文语义由 Node 投影；Cloud 只保存有来源身份的用户/助手可见文本与截断标记，不解析
ACP 或 Agent 原生日志。新轮的对外回复按稳定 turn 身份上报；存量 Thread/归档使用同一 Node 投影器。
思考、工具原始转储和凭据不默认进入下一 Agent 的提示。

跨运行历史预算为最近 20 个交互轮次、最多 64 KiB UTF-8 正文，按由近到远选择，按原顺序交付；当前
消息仍适用既有独立大小限制。超大单轮在 UTF-8 边界截断并标记。界面可以查看实际带入范围；不能将
有界历史称为完整记忆。选择结果在派发前冻结，重试不能读取一套不同的历史。存量来源不可读时明确
说明缺失，不能杜撰 Agent 回复或声称恢复了它。

## D4：任务页优先呈现交流，历史执行可定位且只读

任务主体展示用户与 Agent 对话；执行记录、任务动态可分别查看。执行卡片明确 Agent、触发消息、状态、
成果与安全失败原因。所有历史 Run 有可定位入口，即使没有 Thread 也能显示启动失败。

正文使用安全 Markdown；思考和工具按类别呈现，调用与更新按明确身份合并。工具输入输出可展开，
未知耗时不推断为零。系统提示与原始记录放在详情。历史查看不产生消息或执行，不能随最新 Run 到来
悄悄切换选中的旧 Run。读历史时不强制跟随输出，加载更早消息保持视口锚点。

## 不变量

1. Thread 结束后仍保持 ended；任务续聊必须有新运行身份。
2. 每条已接收消息可查到执行、等待、取消或失败结果；重复提交不产生重复执行。
3. 新运行只使用自身发起者合法授权，历史读取不扩展调用权限。
4. 同一来源的提示、回声、逐轮回复和运行结论在统一对话中不重复展示。
5. 上下文范围和缺失可见，代码恢复与聊天恢复不能相互替代。

## 为什么不是这些替代方案

| 方案 | 取舍 |
| --- | --- |
| 重开旧 Thread | 表面简单，但旧执行授权、资源及终态已结束，无法安全沿用。 |
| 永久保留沙盒 | 恢复更快，但长期占用资源，违背一次性 Workspace 生命周期。 |
| 用评论存全部工具/思考 | 可复用评论 API，但淹没讨论且编辑语义不适合执行证据。 |
| 由 Cloud 解析所有 Agent 日志 | 少一个投影接缝，但使 Cloud 依赖 ACP 与插件记录细节。 |

## 风险与落地

先补可独立验证的历史查看、内容渲染及上下文遗漏修复，再增加任务消息和编排入口。旧接口与持久数据
保持原义，新增索引通过前向迁移建立；存量适配不得改写历史。仅展示修复不构成持续对话完成。
本提案不定义独立 Chat、并行成果合并或原生 Agent 会话跨 Workspace 迁移。批准后补充核心验证义务，
实施与多 Agent、重启、授权撤销和成果失败的真实联合验证完成后再标记 implemented。
