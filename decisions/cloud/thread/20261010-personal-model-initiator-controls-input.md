# 使用个人模型的 Thread 仅允许运行发起者追加消息，成员可读且管理员可结束

本决策继承 [Thread 根决策](0-durable-agent-thread-with-user-turns.md)，依据 2026-10-10 批准的 M4 计划，
明确个人模型连接的额度使用权：发起者授权本次运行调用其连接，其他成员的阅读权限不自动授予调用权。
状态 `approved`，完整浏览器验收未完成。

## 继承与修改

序号、事件接管、命令幂等、分页、SSE 提示和结束状态保持不变。
原允许有效成员追加消息的规则，仅对带个人模型绑定的运行收紧；Echo 与历史无绑定运行保持原义。

## 决策

### D1：服务端授权是唯一事实

带模型绑定的运行仅允许绑定用户追加消息；当前租户管理员及发起者可以结束运行，其他有效成员仍可读取。
账号、成员、连接绑定或 Thread 已失效时，即使界面保留旧状态也不能受理。
Thread 读取增加发起者、冻结的连接/模型摘要及 `canAppend` / `canEnd`，界面据此展示输入和结束控件。
响应不包含真实 Key、凭据引用、临时授权或上游地址。

### D2：撤销与终态均关闭输入

清除 Key、停用或删除连接会永久撤销旧运行的模型绑定。之后只允许有权限者结束运行，不可通过重新配置复活。
`ending` / `ended` 及运行取消后的输入关闭规则继承根决策。

## 不变量与取舍

管理员不因角色而获得个人 Key 的读取或额度调用权；结束权用于停止资源和开销。
这减少了同一 Thread 的多人输入便利，但使私人模型额度的使用边界清晰。
代表性验证见 [个人模型访问](../../../test-cases/cloud/model-access/personal-model-access.md#personal-model-usage-must-remain-controlled-by-the-run-initiator)。
