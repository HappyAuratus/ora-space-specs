# 个人模型 Thread 只由发起者追加，成员可读且管理员可结束

发起者授权一次运行使用其个人模型连接；读取 Thread 不授予消费私人额度的权限。带模型绑定的
运行只有发起者可追加，发起者与当前租户管理员可结束，其它有效成员仍可读。
状态 `implemented`；直接证据及多身份浏览器缺口见核心用例。

## 继承与修改

| [Thread 根决策](0-durable-agent-thread-with-user-turns.md)约定 | 处理 | 当前规则 |
| --- | --- | --- |
| 有效成员可追加消息 | 修改，仅限个人模型运行 | 只有绑定发起者可追加，管理员角色不授予额度使用权 |
| 有效成员读取 Thread | 继承，不变 | 读取资格不因个人模型绑定改变 |
| 有效成员可结束运行 | 修改，仅限个人模型运行 | 结束权收窄为发起者与当前租户管理员，其它成员只读；无模型绑定运行保持原规则 |
| 序号、接管、分页、命令幂等和 SSE 提示 | 继承，不变 | 仍由根决策的持久 Thread 规则拥有 |
| Echo 与历史无模型绑定运行 | 继承，不变 | 不随个人模型约束一并收紧 |

## 决策

### D1：服务端当前授权决定输入与结束能力

Thread 读取返回发起者、冻结连接/模型摘要及 `canAppend` / `canEnd`，前端据此呈现输入和结束
控件。每次追加/结束仍核验当前账号、成员、Thread 状态和模型绑定；旧界面或历史请求不恢复
受理资格。响应不包含 Key、密文引用、临时授权或上游地址。

### D2：永久撤销和终态均关闭输入

清除 Key、停用或删除连接永久撤销既有运行绑定；重新配置只影响新运行。撤销后有结束权者仍
可结束，但不能追加模型请求。ending、ended 和取消的输入关闭继承根决策；结束命令是持久责任，
不能因连接或页面状态变化丢弃。

## 不变量与取舍

1. 私人额度的追加资格只属于本次运行发起者。
2. 管理员结束权不授予读取 Key 或调用私人模型的权限。
3. 旧配置、旧界面和重放不能复活撤销/终态输入。

限制多人输入以保护个人额度。直接证据与多身份浏览器缺口见
