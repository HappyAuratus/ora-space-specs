# 会话分析从 Cloud 授权记录与已登记归档建立只读视图

Cloud Dashboard 以 Agent IssueRun 为会话身份，提供跨任务列表、历史时间轴和原始事件查看。
完整归档只由 Cloud 按已登记 Revision 读取，并在外部读取前后核验当前权限；浏览器不能选择对象键。
本决策已获批准，状态为 `approved`；配套实现仍需审查合并与验收。
已有 Thread 写入、结束、序号和授权规则保持不变。

## D1：会话列表只投影已持久化的 Agent IssueRun

身份为租户、Issue、Run；不将 Chat、Workflow 或个人电脑日志伪装成同一来源。
查询只解析已存在且启用的身份和别名，校验当前租户成员，不 JIT 建号、绑定别名或推进运行状态。
已删除 Issue/Run 不可见。项目、精确 Agent 插件标识、状态和创建时间 `[from,to)` 可筛选；
按 `(created_at,id)` 倒序，游标在当前租户内解析，默认 50、上限 100。未知、重复、空或畸形查询拒绝。

## D2：归档外部读取前后分别授权，不持数据库锁访问 S3

先在短事务中检查成员、Issue、Agent Run、未过期 Revision；对象必须匹配
`revisions/{tenant}/{run}/{work UUID}/session.jsonl`。只从配置的私有端点签名 GET，拒绝重定向。
读取最多 32 MiB，30 秒超时且传播取消；真实字节大小和 SHA-256 必须与登记相同。
只接受合法 UTF-8 JSONL 对象，最多 100000 条；保持物理顺序、未知字段和重复版本。

外部读取后开新短事务，重新检查当前权限与原登记一致性，然后才返回内容。
被撤销的成员和已更换的登记不能继续使用旧授权；公开结果不含对象键、存储 URL 或签名凭据。
成功响应为 `private, no-store`；缺少登记为 404，超限为 413，完整性损坏或存储故障为安全的 502。
错误归档不能悄悄降级成“完整”的 Thread。

## D3：界面保留来源、不完整性和未知值

有 Revision 时展示校验后的归档；否则展示 Thread 尾部快照并显式加载更早页。
归档按自身 seq 重放最终版本，同时保留每条物理记录；Thread 使用公开 seq，不能把 record.seq 当游标。
时间只能来自 record.at 和明确工具 timing，数据库创建时间不能冒充事件时间。
三泳道只展示用户、模型文本、工具；思考、生命周期和未知类型仍在完整事件中。
无时间的事件保留可查看入口；工具种类不是原生工具名，模型文本数不是 HTTP 请求数。
未知 token、费用、模型耗时与真实零不同；原始 JSON 以文本渲染。模型请求统计使用独立来源。

## 不变量

1. 所有读取以当前数据库权限为准，浏览器不能指定外部读取位置。
2. 外部 I/O 不在事务内；外部 I/O 后仍重新授权。
3. 查看会话不会改变身份、运行、Thread 或归档内容。
4. 不完整快照和未知测量不会被标为完整或零。

## 为什么不是这些替代方案

| 方案 | 否决原因 |
| --- | --- |
| 浏览器直接拿签名 URL | 凭据离开 Cloud，无法在完整读取后重新检查权限 |
| 扫描本地 Agent 日志 | 脱离租户归属与服务器登记，无法建立相同授权边界 |
| 只提供 Thread 并宣称完整 | 在线投影可能省略大记录，也可能只加载尾部窗口 |
| 用相邻事件时间差补耗时 | 间隔可能包含工具等待或无关事件，不能视为模型或工具测量 |

## 风险、验收与落地

记录数和字节上限是资源边界，不表示大归档浏览器性能已经验收；前端投影不能把全量数组展开成函数参数。
验证需覆盖租户/Issue/Run 越权、撤销与登记更换竞态、摘要和大小校验、取消、未知查询、只读身份、
原始记录保真以及 100000 条投影。真实 PostgreSQL 和 HTTP/对象存储边界测试不能由组件替身代替。

先提交路由、对象读取、契约与测试，再交付列表、适配器和交互视图。新增读取不需要 schema 迁移。
实时订阅、主动上传、跨会话类型、子 Agent 拓扑和大规模渲染基准不在本次范围。
核心验证义务与直接证据见[会话分析读取](../../../test-cases/cloud/thread/session-analysis-read-model.md)。
测试覆盖以各义务声明的边界为准，不据局部测试宣布完整部署验收完成。
