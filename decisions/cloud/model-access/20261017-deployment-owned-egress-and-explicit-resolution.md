# 企业模型出口使用部署方 host 白名单与显式解析，拒绝规则优先

企业模式只允许访问部署方列出的精确 HTTPS `host:port`；未列出的目标即使解析为公网地址也拒绝。
白名单内的私网地址仍须显式许可，cluster 网络、宿主地址、回环及链路本地始终拒绝。
模型域名由部署方指定的 resolver 或静态映射解析，不回退系统 DNS。
未启用企业模式的部署保持既有公网 HTTPS 与可信公网 DoH 行为。

`approved` 表示网络边界已有 owner 决策，本文将其落为可评审的文档契约；配置形态、TCP DNS 和受控
停机应用是本 ADR 的细化选择，随本文交 owner 审核合并，不能视为此前逐项批准或当前已实现能力。
实现和部署证据齐备后才转 `implemented`。涉及 Cloud 保存门禁、model-gateway、cluster 部署装配；
不改个人 Key 入口、运行绑定、协议支持范围或数据库历史，不包含真实供应商能力与现场连通性验收。

## 问题与约束

公网地址分类不能表达部署方信任：企业网络可能使用登记为公网的地址，单独更换 DNS 会让用户把代理
指向任意公司服务。因此企业模式先检查目标身份，再检查全部地址，不能只给原公网策略加私网例外。
普通用户控制连接和凭据，部署方控制出口、解析信任和禁止到达的基础设施；两者不可互相授权。

## D1：部署配置定义信任，用户只提交个人连接

首版配置使用包外 UTF-8 JSON `model-egress.json`，由部署管理员维护，只读挂载给 Cloud 和 Gateway。
显式配置路径由服务启动参数提供，用户 API、连接记录、请求头和 agent 环境均不能覆盖它。
未配置路径保持原公网模式；一旦指定路径，缺文件、未知字段/版本、重复键、非法值或模式冲突均启动
失败，不能按“未配置”处理。`schemaVersion: 1`、`mode: public|enterprise` 显式区分两种策略。
生产同时设置开发 allow-hosts 与 enterprise 配置必须失败，不能让例外优先。

企业配置包含 `targets`、可选 `resolver`，以及必需的 `topology`。每个 target 是一个独立的
`host`、`port`、`allowPrivate`（默认 false）、可选 `allowedCidrs`、可选 `staticAddresses`。
同一 host 不同 port 是不同许可；重复目标拒绝。`allowedCidrs` 缺省表示没有额外 CIDR 限制，
显式提供时必须非空且每个地址都命中该目标的集合；不能合并其他目标的许可。无需每目标必填 CIDR。
`allowPrivate` 只打开 D3 所列私网类别，不解除绝对拒绝或其他保留地址限制。

以下仅为配置形状，保留域名/文档地址不是可运行的生产配置；无凭据、真实站点参数或连接 base path：

```json
{
  "schemaVersion": 1,
  "mode": "enterprise",
  "resolver": {"transport": "tcp", "address": "192.0.2.53:53"},
  "targets": [{
    "host": "model.example.invalid", "port": 443,
    "allowPrivate": true, "allowedCidrs": ["10.60.0.0/16"]
  }],
  "topology": {
    "clusterCidrs": ["172.30.0.0/16"],
    "hostAddresses": ["192.0.2.10"],
    "complete": true
  }
}
```

`public` 不接受 enterprise 专用字段，继续使用既有部署 DoH 配置及公网数字 bootstrap。
首次启用需要支持本 schema 的服务版本；日常更换许可/DNS/个人 Key 不要求重建镜像，配置应用仍须遵守 D6。

## D2：按规范化后的精确 host 与有效端口匹配

需要出口准入的保存和每次模型转发都从服务端解析 `baseUrl`，仅接受 HTTPS 域名、无 userinfo/query/fragment 的
有效 URL。企业模式首版不接受数字 IP literal、通配符或后缀匹配；ASCII DNS 名按小写规范化，
允许一个末尾根点并移除后匹配，拒绝空标签、多个末尾点和未转换的 Unicode（国际域名须显式使用
ASCII A-label）。配置与 URL 使用同一规范化；省略端口等价于 443，显式端口须为 1–65535 的十进制数。
不通过字符串前缀、CNAME 名或反向解析获得许可。

`https://model.example.invalid/v1` 与同 host 的 `:443/other/v1` 命中同一项；`:8443`、
`model.example.invalid.attacker.invalid`、别名域名均不命中。路径继续由原协议规则追加接口，
不增加完整 base path 或协议白名单字段。host:port 许可意味着该站点的模型协议路径均在部署信任内；
站点若同时承载其他敏感服务，部署方应使用专用 host/端口，而非误以为有路径级隔离。

企业模式中未命中目标在 DNS 查询前拒绝，既包括通常的公网，也包括借用公网编号的内网（如 `7.x`）。
创建、重新启用连接及修改可调用连接时执行 URL、host:port、解析及 D3 门禁，解析失败不写入新连接版本。
网络 I/O 在数据库事务之外，提交仍检查身份、资源版本和幂等约束；已完成操作的合法幂等重放返回原结果，
不因之后的 DNS/策略变化重新执行准入。通过保存不等于之后可以拨号。Gateway 从冻结连接取得目标，
每次请求重新判定当前策略，不信任保存结果或客户端提供的已验证地址。

停用、删除连接和清除 Key 是降低权限的操作，必须在原有身份、归属、资源版本和幂等校验后完成永久
撤销，不依赖 host 是否仍在白名单、地址是否允许、DNS/TLS 是否可用或 D6 是否开放调用入口。
PUT 保存 `enabled=false` 时，只有其他连接配置未变才属于纯停用；不能通过附带修改 URL/模型等字段
绕过普通配置校验。纯停用允许原样携带历史配置，不对它重跑新增的 URL/出口规则；调用方应先独立
停用，再另行修改配置。重新启用须重新准入，且永远不复活停用时已撤销的旧绑定。

## D3：检查全部地址，基础设施拒绝不能被允许项覆盖

所有 IPv4-mapped IPv6 先转为 IPv4，再按以下顺序逐地址判断。整个 A/AAAA 集合通过后才允许任选
其中的数字地址拨号；任何一个不允许、无有效答案或某一族查询失败均拒绝，不筛掉坏地址继续连接。
一族明确 NODATA、另一族成功可接受；超时/SERVFAIL 不算 NODATA。

| 顺序 | 判定 |
| --- | --- |
| 1 | 命中 cluster 任一 CIDR、宿主任一地址、回环或链路本地，始终拒绝 |
| 2 | unspecified、multicast、文档、benchmark/fake-IP、地址转换等既有保留/特殊地址仍拒绝；只对下一行私网类别提供例外 |
| 3 | RFC1918 IPv4 与 IPv6 ULA 要求该 target `allowPrivate: true`；否则拒绝 |
| 4 | 若 target 提供 `allowedCidrs`，该地址还须命中其中一项；不存在跨目标许可并集 |
| 5 | 其余满足既有公网地址规则的地址可通过，但企业模式仍以 D2 已命中 target 为前提 |

部署装配负责生成 `topology`：`clusterCidrs` 来自此部署所有静态和动态容器网络的 Docker IPAM，
覆盖 Gateway 能路由到的默认桥接、Compose 网络、Controller/Node/Workspace 使用及预留的动态网络池，
包括 IPv4/IPv6；不能只读取 Gateway 当前所附网络。`hostAddresses` 来自所有相关宿主的接口地址、
Docker 网桥/网关地址，以及部署方声明的宿主对外地址/VIP/NAT 别名；容器自己的接口列表不够。
动态分配必须留在已声明的网络池，新增池、宿主、接口或别名都须更新快照后才能使用。

部署预检将采集值与管理员声明合并；`complete` 是采集与声明完成的确认，不能代替采集。来源不可读、
清单为空、缺失已知网络/宿主或存在未声明动态池时企业服务不 ready。OS/Docker 不能枚举外部 NAT
别名，部署方必须提供；这种完整性依赖部署管理员与网络管理的信任边界，不能由应用推测保证。
不受装配器控制的外部拓扑变化，须由部署方先阻断出口，再按 D6 更新；程序不声称能发现任意外部路由变化。
许可与这些禁止项重叠时仍拒绝，包括“模型正好在 cluster 网段”的情况。

## D4：显式 TCP DNS 或静态映射，不使用隐含解析路径

企业首版动态解析采用管理员指定的 DNS-over-TCP，`resolver.address` 必须为数字 IP 和端口，
直接连接该地址，不读取 `/etc/resolv.conf`、系统代理或搜索域，也不经 Docker 默认 DNS 发现 resolver。
TCP 是此 ADR 的细化选择：无需新增企业 DoH/CA 服务，但传输本身不提供 DNS 身份认证与保密；
部署方须提供可信、隔离的 resolver 通路。上游模型仍正常验证 HTTPS 证书，DNS 被信任不等于模型
地址被允许。resolver 是独立控制流，只允许发送 DNS 查询，不作为模型 HTTP 目标；其可达性不授予
访问同地址其他端口的权限，cluster/宿主上的模型 HTTP 仍被 D3 拒绝。

只查询显式 host 的 A/AAAA。限制查询总时长、响应大小、记录数和 CNAME 深度，验证 DNS 响应的查询
关联；CNAME 的最终全部地址仍按原 target 校验，不能把别名加入白名单，也不从 authority/additional
区提取拨号目标。超时、截断/畸形响应、循环 CNAME、无答案或解析服务故障均拒绝，不切换系统 DNS、
公网 DoH 或另一套配置。具体限额在实现配置中固定并由直接测试证明有界。

target 的非空 `staticAddresses` 完全替代该 host 的动态查询，所有地址同样通过 D3；静态项失败
不再查 DNS。没有静态项的 target 必须有 resolver；全部 target 静态时可省略 resolver。
静态映射不改变 HTTP Host、TLS SNI 和证书 hostname 校验。静态映射与数字 resolver 均不使用系统
DNS 做 bootstrap。未启用 enterprise 的部署继续原有可信公网 HTTPS DNS，不使用此 TCP 通道。

## D5：当前策略约束每次转发和连接复用

Gateway 在每次请求（包括复用 HTTP/1 keep-alive 或 HTTP/2 连接）发送前检查当前 target 许可；
每次新拨号重新解析并检查完整地址集合，只向已验证数字地址连接，不在实际 dial 时再按域名解析。
DNS 缓存若存在不得超出 TTL；静态数据按快照生效。连接池按策略版本和目标 authority 隔离，
禁止跨 host 的 HTTP/2 合并。DNS TTL 到期后不能直接复用旧连接：先重新验证全部答案，旧 peer
不在新通过集合内就关闭旧池；新答案含禁止地址时整次请求拒绝。这样解析变更不会被长连接永久绕过。

TLS 始终验证原 URL hostname，禁用环境 HTTP/SOCKS 代理，不跟随 3xx；不能以 TLS 失败为由改用
HTTP 或跳过证书检查。用户提供的 host/模型/认证头不能覆盖冻结绑定。有限错误分类与诊断脱敏沿用
根决策；不把配置原文、现场地址、凭据或供应商诊断写入公开日志/统计。

## D6：以一致快照应用配置，关闭旧池后再开放模型流量

首版加载不可变快照，不监听文件做热切换。规范化后的配置（含 topology、静态映射和解析策略）
计算内容摘要，Cloud 与 Gateway 必须报告同一摘要和支持的 schema。配置文件就地改写不生效，
单改一方不构成部署成功。企业模式的调用开关由 Cloud/Gateway 的请求 handler 执行，readiness
仅报告状态，不能代替拦截：关闭时拒绝需要出口准入的配置保存、grant 新建/续期和 runtime 转发，
返回有限的 503 分类，不解析模型目标、不解密用于转发的 Key、不发送上游。已持有有效 grant 的
Node 直连 runtime、既有 HTTP 连接上的新请求同样经过此检查；撤销、纯停用、删除、清除 Key 和
已登记统计的收尾继续可用。此开关不改变数据库中的 grant/绑定永久撤销状态。

每个进程启动时生成新的启动实例 ID，调用状态初始为 closed；加载文件成功不能自行打开。部署入口
是首版激活的唯一协调者，经仅部署管理员可用的受认证管理通道，核对两端配置摘要、schema、拓扑
预检和当前启动实例 ID，向两端确认同一激活记录（部署代次、摘要、Cloud/Gateway 启动实例 ID）。
激活记录不是用户参数或 model grant，不进入 Node 协议，不从旧进程、磁盘标记或重放消息恢复。

开放调用还要求对端确认自己处于同一激活记录；每次受开关保护的请求在副作用前，通过受认证的
服务间控制通道获取对端当前实例与激活状态，不用缓存的成功状态或仅靠 healthz。对端关闭、实例
变化、记录不一致或确认超时均拒绝本次调用并将本端置 closed，取消在途转发并清理池，等待部署
入口重新激活。进程重启者始终 closed，因此单端重启/自动重启也不能凭旧记录自行开放；另一端的
下一次请求检测到变化即关闭。控制检查有界且不在数据库事务中，不携带原始 Key 或用户模型正文。
激活消息只能确认本次受认证连接上核验的实例，旧记录/旧实例确认无效。prepared 状态可供部署
控制预检，但只有两端激活一致才报告模型调用 ready，避免用 ready 作为激活前置条件形成循环。

本文选用受控维护窗口作为首版应用路径；这是本次细化，并非复述旧提案已有批准：

1. 预检新配置、拓扑来源和两个服务版本，生成单一只读快照；预检失败不进入切换，旧策略仍是当前策略。
2. 经管理通道关闭两端调用开关，确认受保护 handler 已拒绝；停止全部旧 Gateway，取消在途流，
   关闭模型与 DNS 连接池；不自动重试生成。任何关闭确认失败都不得进入开放新策略的步骤。
3. 以同一快照启动 Cloud/Gateway，两端保持 closed；部署入口完成 prepared 预检并确认本次激活记录，
   请求检查只有在对端也确认同一记录后才通过，两端模型调用 ready 后新策略才算生效。
4. 启动或一致性检查失败保持模型入口关闭，不退回公网模式、旧池或开发例外。需要回滚时由管理员
   显式选择完整旧快照并重复该过程，不能在失败路径静默恢复旧许可。

维护会中断模型请求；不承诺零停机或多副本滚动切换。不能只重启 Cloud、只关闭 idle 连接或让旧
Gateway 继续接受新请求；新许可生效时任何旧流都已终止。收紧策略后，仍有旧冻结绑定的运行也按
新许可拒绝；扩大许可不修改其冻结 URL/模型/Key。网络准入失败不等于数据库永久撤销，重新允许
目标可供尚未撤销且授权仍有效的绑定再次请求；已经永久撤销的绑定无论策略如何都不能复活。

## 不变量

1. 企业模式的每次模型请求都先命中部署方精确 host:port，任何公网分类都不能绕过它。
2. cluster、宿主、回环和链路本地拒绝优先于 target、CIDR 与静态映射。
3. 全部地址通过后才拨数字地址，TLS 身份始终是原 hostname；错误不触发隐含解析、代理或重定向。
4. Cloud 保存和 Gateway 转发使用相同策略语义，保存通过不能免除之后的地址和授权检查。
5. 生效的新快照不复用旧策略连接或旧流，配置不一致/应用失败不会扩大许可。
6. 部署策略不能改变个人凭据所有权、运行冻结或永久撤销结果。
7. DNS、出口拒绝或调用入口关闭不阻断已授权的停用、删除与清除 Key；降低权限不授予任何新调用权。
8. 企业调用入口的开放同时依赖当前进程实例与两端同代激活；readiness、旧 grant 和重放激活记录均不能代替该检查。

## 为什么不是这些替代方案

| 方案 | 取舍 |
| --- | --- |
| 只更换 DNS，继续允许所有公网 | 部署成本低，但借用公网编号的内部服务仍全部可达，无法表达站点信任 |
| 公网默认加白名单私网例外 | 公网兼容更宽，但同样挡不住未列出的借用公网编号地址；仅用于非企业的原规则 |
| 强制完整 baseUrl 与每目标 CIDR | 更细的约束有其价值，但增加路径/地址变更成本；本次批准粒度是 host:port，CIDR 可选 |
| system resolver 或失败后回退 | 运维方便，但引入未显式选择的解析与 fake-IP 路径，破坏解析信任边界 |
| 生产复用开发 allow-hosts | 接入快，但其例外能绕过生产地址规则，不能承担正式企业许可 |
| 热加载/滚动更新 | 可减少中断，但需要请求、旧流、所有副本和池的版本栅栏；首版选用有界维护窗口 |

## 验收、落地与未解决范围

核心义务见[部署方模型出口用例](../../../test-cases/cloud/model-access/deployment-owned-egress.md)。
先交付共享 schema/准入与 Cloud/Gateway 接线，再交付 cluster 的拓扑采集、只读挂载、一致性预检及
受控应用，最后用受控双栈 DNS/TLS/连接池和真实部署验证。完成定义包括非企业公网回归、保存/拨号
一致性、白名单外借用公网地址拒绝、全部基础设施禁区、策略更新失败和旧绑定撤销；不能只凭配置
解析单测将本 ADR 改为 implemented。现有根决策保持 implemented，本 ADR 的新义务单独补证据。

实际 resolver、模型地址、CIDR、NAT 别名和真实模型能力由部署现场提供，不从名称推测。现场 Key
仍走个人凭据入口，不写入配置、镜像或公开仓库。动态热更新、多副本无中断栅栏、DoH/DoT 等额外
企业 DNS transport、企业 CA/IAM 和路径级许可留后续；这里不宣称已经验证任何真实企业模型。
