# D8 未声明删除操作的残留仅经显式部署运维接管，保留缺失来源与原业务历史

提议将 D8 已结束、但从未声明删除操作的残留纳入既有受控回收。运维必须明确选择这一变体并指定原 Run 与 Workspace；没有原删除操作作为独立事实持久保留，不补造历史记录。终止、迟到 ensure 围栏和独立的数据删除仍沿现有证据与许可边界。

本文是尚待批准的 Cloud IssueRun/部署运维边界提案。既有记录、原资源身份与默认命令保持兼容；不迁移原业务结论，不引入新的公开管理入口。

## 问题与约束

[IssueRun 根决策](0-agent-run-in-disposable-isolated-workspace.md) D8 依据原运行时的不可达事实放弃释放；删除声明可能仍被 Project 上其他操作阻挡，此时并没有一个已建立的删除操作可被标为失败。Run 仍可结束为 `done/workspace_unavailable`，Workspace 与原运行绑定保留。

[残留回收决策](20261018-residual-agent-run-reclamation.md) D6 的存量入口要求引用原 `failed/node_unavailable` 删除操作，因而没有覆盖上述状态。不能用不存在的操作作为必填身份，也不能为了满足准入而补造失败操作或改写 Run。根决策没有授予业务 `done` 物理回收权限；自动扫描和隐藏 Workspace 的公开操作边界仍须保持。

## 提议的决策

### D1：新变体默认关闭，运维必须明确选择原资源

仍只使用部署数据库运维身份。终止命令必须同时指定精确的 Run 和 Workspace、原因、幂等键、真实影响确认，并明确选择“没有原删除操作”的变体；不能只按 Project/tenant 发起，也不能同时指定一个原删除操作。

同一事务重新核对：Run 属于原租户，是已有交付结论的 Agent 运行，状态已经终结，阶段为 `done`，原失败原因是 `workspace_unavailable`；Workspace 为该 Run 的原隔离 Workspace，原 Project 与代次绑定保留，数据尚未释放且 admission 已关闭；没有任何删除操作历史或 D4/D5 残留账本；Project 未删除且没有在途操作。身份、既有责任或来源矛盾时拒绝，不能据错误范围推断另一份资源。

有任何删除历史的 D8 继续引用原失败删除操作，不得改选新变体来绕开旧责任。默认命令继续拒绝缺失原删除身份。

### D2：缺失是可审计事实，不是可被补写的历史

受控根意图显式记录没有原删除操作，原操作引用为空；二者须满足互斥完整性约束。从属数据删除继承同一来源，后续新建的清理操作只能记录为新的处置操作，不能被追认为原删除尝试。

升级保持既有有原删除操作的 D8、D4/D5 账本意图和命令回执语义。新选择参与幂等输入；默认未选择的旧命令不因增加新默认字段而失去已有回执。查询能够发现这个残留变体及其来源，查询本身不产生回收权限。

### D3：沿用两阶段处置和原责任证据

受理后关闭后续入口，取得同一资源的唯一受控责任；按原 sandbox/ensure 身份规划终止，经当前 Controller lease 和既有许可执行。每个目标仍须同时证明真实终止与迟到 ensure 围栏；缺失、超时或 Node Unknown 均不等价于该证明。

终止成功只报告数据保留。单独、明确确认的数据删除命令才可声明新的清理操作，且仅在真实移除证据齐全后软删除 Workspace 并完成处置。全过程不改 Run 的 phase/status/result，不创建伪造的 D4/D5 账本，不把备份本身当成平台清理证据。

## 不变量

1. 业务终态、经过时间和备份存在都不等价于物理终止或删除授权。
2. 缺失原删除操作只能是明确记录的事实，不能补写为一次历史尝试。
3. 同一资源只由一个受控责任推进；原租户、Run、Workspace、代次及目标绑定不得被替换。
4. 终止和迟到 ensure 围栏需要逐目标证据；终止成功保留数据，独立确认及真实移除才完成释放。
5. 回收保持原 Run 的 phase/status/result，不重开 admission，也不扩大迟到 Revision 的登记资格。

## 为什么不是这些替代方案

- **继续拒绝**：权限边界不变，但合法 D8 残留没有可用的恢复入口，任务无法解除未释放 Workspace 的暂停。
- **补造失败删除记录或回退 Run 阶段**：实现表面较小，却改变了历史执行来源，且可能重新启动本应终止的普通扫描；不采用。
- **公开隐藏 Workspace 的租户管理接口**：扩大角色边界并绕过部署级责任；不采用。

本提案增加一个明确、受约束的运维选择及持久来源约束；没有新增网络入口、物理处置机制或自动回收权限。主要风险是把未完成、错绑或已有删除责任的资源误归为新变体，准入和回放必须直接覆盖这些反例。

## 验收边界

需直接验证真实 D8 在没有删除声明时可产生该状态；默认命令拒绝、明确选择成功、错误身份与已有删除责任拒绝；既有 intent/receipt 升级与重放不变；终止保留数据、独立清理后释放，并且原 Run 历史保持不变。跨进程验收还需证明原目标的终止与围栏、真实数据移除及原任务恢复，不以下层数据库测试替代。

提案通过后再依据最终决策维护核心用例；本文件不代表新恢复边界已获批准。
