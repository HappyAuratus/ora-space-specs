# Run 保留一次尝试身份，Scope 关闭不卸除未完成责任

> 已被取代：本决策由 [Node 直接执行自己的 Git](../../git-execution/0-node-runs-git-directly-with-attempt-locks.md) 取代，原因：Scope 和 Run 不再存在，尝试只记在 Node 数据库里，收尾由取代者的停止证据判定。当前系统承诺以取代者为准；取代者的实现合并之前，desktop 里仍在运行的 host／guardian 以本文为历史依据。

当前 host／guardian 持久接受原身份，未知启动不自动重试。直接退出、Run 收尾和 Scope 关闭
分别表达。本文收紧至 Linux 可信本机路线，按这一范围处于 `implemented`，实现位于 desktop 的
`crates/process-runtime`；并发启动／关闭等完整验收缺口登记在核心用例中。

## 决策

### D1：意图、事实和清理分离

区分持久接受、未启动／已启动／未知、直接进程结果、清理状态和实际保证。
host 的关闭／停止请求不同于 guardian 已观察的完成。输出 EOF、业务成功和进程退出不互相替代。
结果接管和退休不属于当前状态机，未来 ADR 负责。

### D2：先登记责任，原身份去重

host 提交 Run 意图，guardian 提交原参数与尝试责任，再调用平台启动。
同 RunId 同参数返回原尝试，不同参数拒绝；未知不能换后端或再次 spawn。
Node 在业务对账后才决定新的尝试；运行层不会为长期工作负载自动重启。
即使确定 exec 失败，当前接受过的远程 Run 也不会因重传重新执行。

### D3：Run 收尾与 Scope 关闭不同

直接进程退出后按 Run 策略清理后代或等待全部受管进程；默认清理策略的宽限由调用方显式提供。
单 Run 停止不杀邻居；Scope Close 先持久封闭接纳，再涵盖已接受的 Run，关闭后不重新开放。
空的开放 Scope 不是已关闭；guardian 不可用时不能推定收尾完成。

### D4：停止升级不延长等待

内核支持限时等待、通知后等待和强制停止；重复请求只缩短或升级。
当前 host 远程 Stop／Close 请求强制收尾，不宣称全部内核策略已有远程接口。
Node 正常停止先关新派发并给当前 Git 有限宽限；异常退出由 owner 身份监测触发清理。
协调重试有界退避、不放弃原责任；连接超时、重试次数和取消等待不释放资源。

## 不变量

1. 原 RunId 不产生第二次启动尝试，未知不被改写成未执行。
2. 已接受运行纳入 Scope 关闭责任，不因回复丢失而遗漏。
3. 接受、退出、清理和业务完成分别解释。

## 取舍与未来 ADR

超时重跑可能重复 Git 副作用；把直接退出当完成会漏掉后代。
Controller 撤权竞争、租约、输入交付与退休由未来 ADR 承担；这些延期不能豁免当前
Start／Close 并发、持久故障和停止升级义务。

## 验收

真实 Run 重放、丢回复、日志失败、后代／邻居隔离、host 重启已覆盖主要路径；
所有接受／执行／关闭竞争窗口的独立进程证据尚不完整，按实际覆盖登记为 `Partial` 或 `Missing`。
