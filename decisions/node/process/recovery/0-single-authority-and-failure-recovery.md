# 独占资格之后核实原实例，缺少清理证据就保留阻塞

> 已被取代：本决策由 [Node 直接执行自己的 Git](../../git-execution/0-node-runs-git-directly-with-attempt-locks.md) 取代，原因：host／guardian 退役后，失败恢复由取代者的重启收口承接。当前系统承诺以取代者为准；取代者的实现合并之前，desktop 里仍在运行的 host／guardian 以本文为历史依据。正文里链接的核心用例只服务本决策，已随取代一并删除，链接不再有效。

当前 Linux 宿主在稳定锁下恢复持久意图，重连原 guardian；连接失败不重启旧 Scope／Run。
guardian 失效不接管活进程，也不承诺一定可以收尾。本 ADR 按 D1 表中的当前行为处于 `implemented`，完整故障
矩阵的缺口登记在核心用例中；
已交付的较窄启动／重连边界见[后续 ADR](20260917-rootless-guardian-bootstrap-and-reconnect.md)。

## 决策

### D1：故障按证据而非连接状态解释

| 故障 | 当前行为 |
|---|---|
| Node 管理请求断线 | 原意图继续协调，无 Controller 租约 |
| Node Git owner 退出 | guardian 按固定进程身份触发清理；结果仍须查询 |
| host 重启 | 新宿主取得锁并推进绑定，逐 Scope 找原 guardian |
| guardian 连接未知 | 保留历史投影及不可用状态，不创建替代实例 |
| guardian 被强杀 | 无独立安全清理证据时保持未知；不把 Scope 锁空闲解释为 Closed |
| 数据库／记录缺失或损坏 | 拒绝不安全恢复，不自动重建 |
| 机器重启 | 不提供完整自动恢复保证，未来 ADR 定义身份和遗留处置 |

### D2：稳定锁只证明恢复资格

显式定位、取得独占锁、核实版本与记录、发现原实例后再协调操作。
锁文件不由迁移或普通清理替换；旧 PID 消失和数据库可打开不证明旧 Git 写入结束。
状态目录仅接受已支持的本地文件系统，业务目录语义另由所属领域负责。

### D3：局部未知不阻塞所有工作

host 独立协调 Scope；Node 保留未知执行的冲突预留，不冲突任务可继续。
host 数据库不可用限制新的持久接受，不能因此撤销 guardian 已承担的责任。
条件恢复后继续查询／协调，不用重试次数生成完成事实。

## 不变量

1. 未取得独占资格不推进新的宿主绑定。
2. 失联不证明死亡，死亡不证明全部后代已停止。
3. 历史结果、实时可用性与清理证据分别报告。

## 取舍与未来 ADR

全局门禁简单却扩大局部故障；失联补启会产生双实例或重复副作用。
Controller 撤权、租约、跨休眠／重启期限、独占修复工具、服务管理器存续和独立残留清理，
由未来 recovery／control／平台 ADR 定义和验证，不作为当前自动恢复承诺。

## 验收

已有 host／Node 强杀、原尝试重连及 guardian 丢失局部阻塞证据；
完整暂停恢复、所有存储故障时序仍未覆盖。见[核心用例](../../../../test-cases/node/process/recovery/authority-and-recovery.md)。
