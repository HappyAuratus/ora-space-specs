# 宿主与 Guardian 分别提交日志，当前保留全部责任记录

host.sqlite 保存管理意图和历史查询投影，guardian.sqlite 保存接受与运行事实；各自使用
SQLite WAL 和 synchronous=FULL。接受回复晚于事务提交；不依赖跨库事务。
原方案的输出持久化、结果接管、退休和压缩改由未来 ADR 负责，当前不执行 GC。本 ADR 按这一范围处于
`implemented`，实现位于 desktop 的 `crates/process-runtime`（`host_state`、`guardian/journal.rs`）。

## 决策

### D1：唯一写入者和可恢复事实

host 管 Scope／Run 意图、关闭和停止请求及观测投影；每个 guardian 管自己的 Run journal。
Node 的 ora-node.sqlite3 独立保存业务执行及变更尝试关联，不并入上述数据库。
连接失败不删除意图，历史 Running 不证明存活，磁盘记录不授权按旧 PID 发信号。

### D2：先提交责任，再执行副作用或确认

guardian 先持久登记尝试，再调用平台执行；记录未知窗口不能通过再次 spawn 消除。
宿主接受意图后独立协调，调用方取消等待不撤销责任。打开数据库核实实际 WAL／FULL 设置
及链接引擎要求。进程强杀恢复证据不等于物理断电或任意文件系统耐久性认证。

### D3：暂不退休，不能凭时间删除身份

当前保留日志和 Scope 目录，不回收 guardian、结果或去重历史。关闭阻止新启动，但不表示已退休。
未知 Scope 的 Start 不隐式创建 Scope；同身份参数冲突拒绝，旧 ScopeId 不复用。
保留历史避免 GC 使旧请求重新有效，代价是磁盘、guardian 与扫描成本持续增长。

### D4：失败不卸除责任

写库失败、缺失／损坏记录或权限错误必须暴露，不确认尚未持久接受的操作，也不重建原目录。
运行观察与收尾分别保存，不伪造丢失的退出结果。状态目录显式注入且独立于业务 cwd／HOME。

## 不变量

1. 接受确认晚于所属事务提交，正常运行不直接写对方数据库。
2. 未知责任不因连接、存储故障或时间经过而消失。
3. 没有输出持久承诺，也没有结果接管／退休完成的隐含确认。

## 取舍与未来 ADR

共用数据库会耦合故障边界；统一 TTL 会丢失去重和未接管结果。
未来持久化 ADR 定义数据先于可读偏移提交、结果接管、资源解除关联、guardian 退休、
旧身份拒绝依据和压缩。安全迁移继续遵循 upgrade；不能以延期为由删除旧版本管理材料。
