# 不兼容时拒绝并保留旧责任，已知日志布局才允许迁移

当前实现检查两套 wire 版本和日志 schema，只迁移明确识别的 host 布局。
不兼容的活 guardian 必须保留兼容管理版本；不会通过重启同一 Scope 接管旧进程。
本 ADR 按上述拒绝与已知迁移的范围处于 `implemented`，实现位于 desktop 的 `crates/process-protocol` 与
`crates/process-runtime`；完整版本共存、升级中断与发布恢复矩阵的缺口登记在核心用例中。

## 决策

### D1：协议与存储分别检查

Node—host、host—guardian 以及程序—日志是独立兼容边界。
错误版本拒绝，不因 MessagePack 可解码就继续。已有 guardian 保持原进程和 journal，
不由新版原地重启；运行中热替换不属于本次能力。

### D2：旧文件是硬边界

状态目录显式注入，不覆盖旧 reaper、Node DB 或用户文件；稳定锁不由迁移替换。
缺失记录、未知布局、权限或符号链接错误不能通过清空目录“修复”。
旧版本仍有责任时保留其兼容管理程序和数据；当前不提供自动版本安装／回收管理器。

### D3：已知迁移不丢失责任

host 当前 schema 6，guardian schema 4；host 恢复支持已知旧布局的检查与事务迁移。
旧 v2 host 只要存在原 Scope 目录就拒绝迁移，保留旧 token 和实例信息供兼容版本管理。
去除秘密字段不保证 SQLite 空闲页或备份中的安全擦除。
旧 RunSpec 缺少 owner 退出策略时保持 Independent，不追溯改变旧 Run 的存续承诺。
具体布局和版本常量以实现为准；程序回滚不授权回滚数据库或去重事实。

## 不变量

1. 未知旧文件不覆盖，迁移不替换原锁或复活旧尝试。
2. 不兼容版本不能通过重建原 Scope 绕过责任。
3. 拒绝升级时原有恢复材料仍保留。

## 取舍与未来 ADR

原地覆盖更易发布，却可能使旧运行无法管理；恢复旧备份会倒退已接受责任。
自动版本共存部署、兼容矩阵、恢复工具、版本文件退休与回滚工作流由未来 upgrade ADR
负责。现有迁移的事务性、拒绝路径及文件保护仍是当前验证义务，不因延期而免除。

## 验收

已有精确 v1/v2 迁移、旧 v2 Scope 拒绝、未知／损坏文件保留、wire 错误版本拒绝测试。
v3–v5 各布局和迁移中断等完整矩阵仍待补齐，见
[核心用例](../../../../test-cases/node/process/upgrade/coexistence-and-migration.md)。
