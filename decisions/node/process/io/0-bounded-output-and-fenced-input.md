# Guardian 持有有界输出，当前不提供 stdin

> 已被取代：本决策由 [Node 直接执行自己的 Git](../../git-execution/0-node-runs-git-directly-with-attempt-locks.md) 取代，原因：guardian 退役后，输出的有界读取规则由取代者承接。当前系统承诺以取代者为准；取代者的实现合并之前，desktop 里仍在运行的 host／guardian 以本文为历史依据。

当前 Linux guardian 独立读取 stdout／stderr，支持丢弃或有界内存前缀捕获，通过偏移查询。
stdin 关闭；不提供插件协议流、输入交付或持久输出。本文于 2026-09-18 收紧原双向 I/O
范围后标为 implemented，只承诺下述已验收的结果捕获行为。

## 决策

### D1：捕获有界且完整性可见

stdout／stderr 分别限额；超限或读取失败触发停止，保留前缀并报告截断／失败。
后台读取不依赖消费者读取或 Node 连接。Git 遇到截断、失败或缺失输出不把前缀当完整事实解析。
丢弃模式不承诺可读输出；这不是日志轮转或协议流背压。

### D2：输出结束与进程退出分别报告

偏移读取返回保留范围、截断标识和读取状态。EOF 不等于全部原始字节已保存，也不等于进程退出；
直接进程退出后后代仍可持管道。guardian 存活时 host 重启仍可读取原内存输出；
guardian 死亡可丢失输出，不声明磁盘 output 目录已经提供持久输出。

### D3：控制不等待输出消费者

host 控制与输出端点分离，guardian 通道和任务有界，输出等待不占用控制状态锁。
拥塞、读者离线时仍能查询和请求停止；有界输出本身不构成通用资源配额。

## 不变量

1. 截断和读取失败可观察，不以 EOF 伪造完整结果。
2. 输出拥塞不要求消费者恢复后才能停止运行。
3. 本版不接受 stdin，不宣称字节交付或业务命令恰好一次。

## 取舍与未来 ADR

有界内存捕获足以支撑短 Git 结果，代价是超限终止和 guardian 故障丢失输出。
无限缓存不可接受；统一淘汰旧字节会破坏 Git 解析。
插件流背压、诊断日志轮转、持久分段输出、续订、stdin 去重及交付未知、交互终端与会话恢复
由未来 I/O ADR 定义和验收，不能由本次 implemented 推导支持。

## 验收

精确限额、无消费者读取、超限停止隔离、EOF／退出分离及真实 host 重连输出、阻塞读者下
控制可用已有直接测试。见[核心用例](../../../../test-cases/node/process/io/output-and-input-delivery.md)。
