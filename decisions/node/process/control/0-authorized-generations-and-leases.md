# 当前信任本机 Node，宿主代次只用于旧会话失效

> 后续已批准决策：[云端运行时控制同步交付](../../../cloud/controller-integration/20260927-fenced-runtime-control-delivery.md)区分宿主代次与用户控制代次，要求云端管理/工作负载权限隔离，状态为 `approved`，尚未实现。不恢复本文延期的完整信任体系，本文保留原状态。

当前不使用密钥、秘密令牌、Controller 授权或租约。可信 Node 通过受限本机端点请求 host；
host 在稳定锁保护下持久推进宿主代次，guardian 使旧宿主会话失效。
本文按 Eric 已确认的信任体系延期范围收紧；保留 approved，不把较窄的宿主会话机制称为
原 Controller—Node 授权体系已实现。

## 决策

### D1：不同身份不互相替代

ScopeId／RunId 标识不可复用的运行组和一次尝试；宿主实例及单调代次标识当前管理会话。
NodeId／ExecutionId 属业务层。PID、路径、socket 连接均不能替代持久尝试身份。

### D2：当前信任边界是部署约束

显式私有目录、OS 对端 UID 校验防止错接，不构成同 UID 恶意程序隔离。
不再要求可信 Node 提供秘密凭据，也没有只读观察者授权角色；知道路径不代表已经实施
安全授权体系。管理进程及同身份代码须可信。

### D3：持久宿主绑定在实际执行点检查

取得原 host 锁后才能推进宿主代次；guardian 提交新绑定后才确认。同绑定重传幂等，
低代次或同代次不同实例拒绝。旧通道和已排队变更在执行点重新核对绑定。
此机制解决 host 更替，不证明 Node 被 Controller 授权，也不证明旧业务进程已停止。

### D4：存活策略不冒充租约

host 断线策略和 Run owner 退出策略分别执行；Node Git 使用固定进程身份的退出清理。
连接失效、owner 死亡和清理完成是不同事实。没有租约续期、到期撤权或跨机器重启期限承诺。

## 不变量

1. 宿主接管确认晚于持久绑定，旧绑定不能重新取得执行资格。
2. 会话失效不自动释放业务资源。
3. 可信本机检查不被描述为密码学认证或同 UID 隔离。

## 未来 ADR 负责

Controller 授权与实例更替、凭据签发轮换、只读角色、Scope 授权代次、租约及跨重启时钟、
输入撤权须由本叶子后续 ADR 定义。旧方案保留为设计背景，不是当前必须实现的 API。
恢复信任体系时重新确认威胁模型，而不是直接启用历史字段。

## 验收与状态

宿主绑定已有真实 guardian 接管、迟到字节和执行队列测试；原授权／租约用例继续标记
未来范围、Missing。见[核心用例](../../../../test-cases/node/process/control/authorization-and-fencing.md)。
