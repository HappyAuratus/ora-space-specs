# Agent 实时预览独立传输，定型 Thread 记录仍是持久权威

在 Node → Controller → Cloud → 浏览器增加有界实时预览旁路，承载正文、公开思考和工具更新。
现有定型记录、确认和重放通道不变；实时预览可丢弃并从快照恢复，不能成为执行成功或持久接管证据。

本决策已实现，Node、Controller、Cloud 与浏览器的预览链路及真实成员撤权已有直接验证；
兼容性和故障组合的证据边界见末节。
新能力须协商，旧节点继续提供定型记录且界面明确展示能力差异，不能声称逐段实时输出已启用。

## D1：预览按稳定块身份更新

Node 在会话执行中为可展示块保留 execution、turn、block 身份与递增版本。文本、思考和工具状态使用
相同身份更新；最终定型记录关联同一块。Thread 的 Cloud seq 与原始记录 seq 仍各有用途，不能把其中
一个直接当成跨执行身份。未知事件保留诊断入口，不伪造成思考或工具成功。

工具调用的开始、增量和结束按调用身份归并；缺少开始事件的结果仍可显示，缺少身份的记录不能仅靠
工具名称合并。正文按明确的追加/替换语义处理，终态记录覆盖预览而不是再次拼接。

## D2：旁路慢消费者不能阻塞执行和持久化

Node 以小批量、有界缓冲发送预览，Controller/Cloud 各层同样有容量上限；过慢消费者被要求重新同步，
不使用无界内存队列。旁路不逐 token 写入执行账本，不参与持久事件 Ack。持久写入失败仍按原有规则
结束会话；仅预览断线不结束运行。

生产者断线、代次变化或缓存丢失后，旧预览不得覆盖新执行。Cloud 依据当前数据库授权与 execution
绑定接收预览、允许订阅；客户端不能自选租户或旧 Node 身份访问。个人模型凭据和供应商诊断不进入
旁路载荷或日志。

## D3：重连先恢复权威记录，再恢复未完成块

浏览器读取已持久 Thread 后，按同一执行身份获取当前未完成块的版本快照，再接实时更新。已经定型的
块不被快照或延迟增量复活；重复和低版本更新忽略。缺少可用预览快照时明确显示重新连接/等待定型记录，
不能把已有部分文本标为完整回复。

退出任务页只解除订阅，不取消 Agent。成员权限撤销后停止发送后续内容，并清除该订阅的预览缓存。
前端合并渲染，不因每个文本片段请求整个 Thread；现有空间事件依旧只作为持久读取失效提示。

## 不变量

1. 实时预览不能改变 Run、Thread 或成果交付的权威状态。
2. 持久记录只由现有确认路径产生，旁路失败不改变其完整性承诺。
3. 最终块胜过任意旧预览；重复更新不重复呈现文本或工具。
4. 所有缓冲有界，慢浏览器不阻塞 Agent。
5. 查看、断开和重连不会触发执行或终止命令。

## 为什么不是这些替代方案

| 方案 | 取舍 |
| --- | --- |
| 每 token 进入持久确认路径 | 恢复简单，但持久写入与确认成本随输出片段增长。 |
| 只缩短 REST 轮询 | 改动小，但 Node 未发送的中间状态仍不可见。 |
| 直接把 Node 暴露给浏览器 | 少一层转发，但绕过 Cloud 当前权限与执行归属检查。 |
| 断线后重复拼接所有片段 | 无需稳定身份，但造成重复正文和错误工具状态。 |

## 风险与落地

预览通过协商后的 Node/Controller 通道进入 Cloud 的受权订阅端点，再由浏览器合并显示。
仅在真实 Agent 完成前观察到未定型增量时，才构成流式能力证据；完整终态或全局至少一次的断言不能
自动归因给每一种 Agent。慢消费者、乱序、终态先到、重连、权限撤销与旧节点兼容仍各有独立验证义务。
子代理拓扑另行设计。
核心验证义务见[实时 Thread 预览](../../../test-cases/node/protocol/live-thread-previews.md)。
