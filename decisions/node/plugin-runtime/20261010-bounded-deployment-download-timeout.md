# 大型插件包允许部署配置下载时限，安装仍保持有界和校验

继承 [插件安装根决策](0-node-installs-plugins-into-workspace-home.md)。本轮 M4 固定官方 OpenCode 包约 62 MB，实际网络在 60 秒内仅传输约 14 MB；原有单次时限使重试从头下载后仍可能失败。部署可以调整单次下载时限，默认和安装身份、校验、重试及取消规则保持不变。状态 `implemented`，配置与预算在 desktop 的 `apps/ora-node/src/plugins/config.rs`。

## 继承与修改

| 根决策 | 本文处理 |
|---|---|
| Workspace 内安装、临时目录、摘要/包校验、原子替换、在用拒绝 | 继承，不变 |
| Cloud 指定包与版本，Node 不读取 marketplace | 继承，不变 |
| 固定下载时限 | 修改：Node 部署配置可设单次时限，保持总预算有界 |

## 决策

### D1：只有部署可调整，任务不能指定

Node 插件模块拥有 `plugins.download_timeout_seconds`，省略时为 60 秒，允许整数 10–1200。无效类型、越界及未知字段在启动前拒绝；不将它加入 Cloud 控制消息或用户请求。

连接时限仍为 10 秒，最多三次尝试，大小上限仍为 512 MiB。总预算固定为 `3 × 单次时限 + 70 秒`，默认仍为 250 秒。取消持续传入现有下载器，不因为配置增加而失去终止路径。

### D2：延长时间不能替代内容与身份校验

官方版本、SHA-256、HTTPS 验证和安装期检查保持不变；不能通过关闭 TLS 或接受部分下载来完成安装。普通部署使用默认值。

增加一个部署参数会带来更长的失败等待；换取大型包在慢网络中可以完整下载。总预算由单次值推导，避免引入互相矛盾的多个时限参数。本决策不增加共享下载缓存、不改变从头重试策略，也不改变模型生成请求不自动重试的规则。

## 验收

见 [有界下载用例](../../../test-cases/node/plugin-runtime/download-budget.md)。历史错误只保留 `download_failed`，不能把后续限时 GET 结果当作每一次历史失败的精确原因。
