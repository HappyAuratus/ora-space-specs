# 保留子代理投影来源，以只读详情和真实观察呈现运行状态

共享运行时保留 provider 在现有 ACP 更新中明确提供的来源；history 和聊天组装不得把不同来源合并。
首期消费 OpenCode v2 的父流投影，在父时间线展示只读子代理树。运行诊断展示收到的活动、工具和
待处理请求，区分观察时间与历史记录时间，不从静默、父工具完成或父 prompt 结束推断子代理健康与终态。

本 ADR 为 `proposed`，实现可在隔离 preflight 中验证，合并前须完成评审。覆盖共享 agent-runtime、
history 与聊天呈现；不新增 RFD 子会话路由、定向控制、模型 adapter 或独立调度器。
沿用 JSONL schema 2、目录布局及现有 SessionUpdate/LoadSessionEvent 结构；兼容变化是已存在的可选
metadata 开始被保留，以及未明确完成的子工具不再借父回合结束获得完成状态。旧记录无法补造来源。

## 继承与修改

本决策继承[插件拥有模型 adapter](20261017-plugin-owned-model-adapters.md)，不改变其授权与配置规则；
并补充[共享运行时根决策](0-shared-agent-runtime-crate-hosted-by-node.md)及
[静默策略](../../desktop/core/workflow/20261008-prompt-inactivity-policy.md)。

| 前序约定 | 处理 |
| --- | --- |
| 宿主拥有进程、会话及授权生命周期 | 继承，不新增子代理宿主管理实体 |
| JSONL 与 Thread 使用同一共享 history | 继承，在现有更新类型中保存来源，不新增记录类型或迁移旧文件 |
| 默认 Timeout / 显式 Wait 与取消清理 | 继承，不更改窗口或重试次数 |
| 父会话 in_progress 工具暂停无活动计时 | 继承；投影来的子活动不能单独证明父 prompt 正在等待它 |
| 父回合结束可收束父工具显示 | 限定：不能把此规则用于明确属于子会话的工具 |
| 配置、usage 等连接快照不进入持久 transcript | 继承，暖/冷加载可以缺少不同的连接信息，UI 必须标明未知 |

## D1：来源是 provider 的事实，不是从文案推导的关系

首期只识别 OpenCode 的 `_meta["opencode/child-session"]`，要求非空 id、parentID 与正整数 depth；
父子关系来自 id/parentID，depth 仅作说明。工具 ID 前缀、标题和最终文本不作为来源证据。
没有有效来源的内容继续留在父流；不把旧历史猜成子代理内容。未知扩展仍不透明地保留。

同一父回合中，同一 child id 的内容归为一组，嵌套按 parentID 连接。缺失父节点显示来源缺口，
自环、循环或冲突关系不得递归挂载；降级为可阅读的独立组并说明关系未知。分组不创建独立会话，
也不授予 prompt、steer、cancel 或 close 能力。

## D2：合并只发生在来源与内容语义一致的流中

文本/思考必须保存完整 ContentChunk，包括外层 metadata、内容层 metadata 与 annotations。
相同或缺失 messageId 不能跨来源拼接；只有完整 metadata、注解与消息类型一致时才允许追加文本。
非文本内容保持完整块。不同子会话的 plan 不覆盖父 plan 或兄弟 plan。

工具增量继续使用原 toolCallId 与原位置，增量 metadata 按顶层命名空间替换同名值；省略的键保留，
显式 null 覆盖旧值。命名空间内部对象不做未被协议定义的递归 patch。晚到的来源或结果应更新已完成
工具的同一快照。父回合结束不为带子来源标记的未完成工具生成 completed；UI 将未报告结局显示为未知。

这是保守的保真选择：metadata 变化可能产生更多文本块，但不以压缩展示为理由混合来源或丢失信息。
保存的是组装快照，仍不承诺永久保留每条原始通知。

## D3：观察、请求等待与 provider 状态分开表达

所有 provider 共享诊断面板：最近收到的真实内容/工具/plan 活动及其接收时间、当前工具、未决权限请求、
父回合执行状态，以及 provider 实际上报且已识别的状态。没有 provider 状态时显示“未上报/未知”。
已知扩展状态按各自字段解释，不把任意 metadata.status 当成通用状态协议。

接收时间是客户端观察该条实时事件的时间，不冒充 provider 发生时间。重新加载只知道历史记录时间时，
明确标注为记录时间；无法区分重放与实时的加载流不刷新“最近实时活动”。切换会话、重载、换 provider
和新 prompt 时清除不再有效的观察快照。定时刷新只改变已过去多久，不生成新活动或健康判断。

静默只表示多久未见活动；等待用户只在确有未决请求时显示。question 表单缺能力时不得制造一个等待
状态，也不得宣称问题已回答。当前工具状态与子代理生命周期分别展示，历史缺口及父回合结果保留。

## D4：可见子活动不自动延长父 prompt

带明确子来源的文本、plan、工具和工具增量仍发送给消费者，但不能重置或暂停父 prompt 的 Timeout。
子工具后续增量即便省略 metadata，也不能丢失已识别的来源而被重新算成父工具。父委托工具本身的
in_progress 继续按已有规则暂停计时；Wait、手动停止、真实错误与取消收敛均不变。

父流关联只证明这条内容应显示在哪里，不证明子工作正在被本次 prompt 等待。因此不根据后台日志、
子输出或 tool ID 文本保活，也不在此首期增加新的父子等待协议。

## 不变量与验收方向

1. 并发与嵌套的显式来源在实时、运行中重开、暖/冷加载后保持相同的内容归属。
2. 相同/缺失 messageId 不跨来源合并，晚到 metadata 与显式清除可重载。
3. 父回合结束不能让未上报终态的子工具显示成功；旧历史不补造来源与状态。
4. 子活动不会独立续期或暂停父 Timeout，父委托 in_progress 和 Wait 仍有效。
5. 诊断时间有明确来源；重放、切换、失败、取消和卸载不留下虚假的活动与待处理请求。
6. 详情树可展开文本、思考、工具输入/输出；循环、缺父、未知 metadata 和历史缺口不丢内容、不崩溃。

通过真实帧驱动生产 runtime/history/load 与聊天 store，并用带类型的契约处理器验证呈现；再做实际
Desktop/浏览器、Node/Cloud/工作流消费端验收。静态解析或计数相同不足以代替内容/来源及生命周期断言。
本提案不将未合并原型作为已实现证据；approved 后维护核心用例，最终实现通过后再转 implemented。

## 为什么不是这些替代方案

| 方案 | 未采用原因 |
| --- | --- |
| 只在 UI 按工具标题分组 | 没有可靠身份，重载仍丢来源，跨并发混组 |
| 立即升级为 RFD 独立子会话 | 增加路由、控制和生命周期契约，超出首期只读范围 |
| 任意子活动保活父 prompt | 关联不等于被等待，会让无关后台活动掩盖父 prompt 静默 |
| 冷加载时用当前时间补最近活动 | 把旧事件伪装成刚发生，制造健康假象 |
| 对所有 metadata 递归合并 | provider 的替换/清除语义未知，容易复活已清除来源 |

## 风险、未解决问题与落地

OpenCode 普通投影在父 prompt 结束后可能不再转发子更新，缺口不能当作子会话完成。更完整的后台历史、
question/elicitation、定向子代理控制与其他 provider 的来源适配留待后续决策。旧历史读取无需迁移，
但丢失的信息永久未知；新增 metadata 不能使旧文件变得不可读。

先批准此边界，再依次合入 history 保真与 liveness 隔离、通用运行诊断、只读详情 UI；各阶段独立验证。
OpenCode 试验插件的发布/marketplace 替换是独立发布决定。产品 PR 验收后由落地运行同步本文与核心用例。
