# 保留子代理投影来源，以只读详情和真实观察呈现运行状态

共享运行时保留 provider 在现有 ACP 更新中明确提供的来源；history 和聊天组装不得把不同来源合并。
首期消费 OpenCode v2 的父流投影，在父时间线展示只读子代理树。运行诊断展示收到的活动、工具和
待处理请求，区分观察时间与历史记录时间，不从静默、父工具完成或父 prompt 结束推断子代理健康与终态。

本决策为 `implemented`：history 保真、运行诊断与只读详情树分别由 desktop#695、#696、#697 交付，
按先后顺序合入 desktop 的 `main`。核心用例在
[子代理投影、终态缺口与运行诊断](../../../test-cases/node/agent-runtime/child-projection-and-diagnostics.md)
中维护，证据按最终实现登记，未覆盖的缺口如实保留。覆盖共享 agent-runtime、history 与聊天呈现；不新增 RFD
子会话路由、定向控制、模型 adapter 或独立调度器。沿用 JSONL schema 2、目录布局及现有
SessionUpdate/LoadSessionEvent 结构；兼容变化是已存在的可选 metadata 开始被保留，未明确完成的
子工具不再借父回合结束获得完成状态；父回合结束后仅将最晚一次可关联委托为前台完成的子组标为
「委托已返回结果」，其余子组转为「后续未知（投影已停止）」。旧记录无法补造来源。

## 继承与修改

本决策继承[插件拥有模型 adapter](20261017-plugin-owned-model-adapters.md)，不改变其授权与配置规则；
并补充[共享运行时根决策](0-shared-agent-runtime-crate-hosted-by-node.md)及
[静默策略](../../desktop/core/workflow/20261008-prompt-inactivity-policy.md)。

| 前序约定 | 处理 |
| --- | --- |
| 宿主拥有进程、会话及授权生命周期 | 继承，不新增子代理宿主管理实体 |
| JSONL 与 Thread 使用同一共享 history | 继承，在现有更新类型中保存来源，不新增记录类型或迁移旧文件 |
| 默认 Timeout / 显式 Wait 与取消清理 | 继承，不更改窗口或重试次数 |
| 父会话 in_progress 工具暂停无活动计时 | 继承；投影来的子活动不能单独证明父 prompt 正在等待它 |
| 父回合结束可收束父工具显示 | 限定：不能把此规则用于明确属于子会话的工具 |
| 配置、usage 等连接快照不进入持久 transcript | 继承，暖/冷加载可以缺少不同的连接信息，UI 必须标明未知 |

## D1：来源是 provider 的事实，不是从文案推导的关系

首期只识别 OpenCode 的 `_meta["opencode/child-session"]`，要求 trim 后非空的 id、parentID 与正整数
depth（`1.0` 这类整数值的浮点形式同样有效，超出 JavaScript 安全整数范围视为无效）；父子关系来自
id/parentID，depth 仅作说明。工具 ID 前缀、标题和最终文本不作为来源证据。没有有效来源的内容继续
留在父流；不把旧历史猜成子代理内容。未知扩展仍不透明地保留。

同一父回合中，同一 child id 的内容归为一组，嵌套按 parentID 连接。缺失父节点显示来源缺口，
自环、循环或冲突关系不得递归挂载；降级为可阅读的独立组并说明关系未知。分组不创建独立会话，
也不授予 prompt、steer、cancel 或 close 能力。

## D2：合并只发生在来源与内容语义一致的流中

文本/思考必须保存完整 ContentChunk，包括外层 metadata、内容层 metadata 与 annotations。
相同或缺失 messageId 不能跨来源拼接；只有完整 metadata、注解与消息类型一致时才允许追加文本。
非文本内容保持完整块。不同子会话的 plan 不覆盖父 plan 或兄弟 plan。

工具增量继续使用原 toolCallId 与原位置，增量 metadata 按顶层命名空间替换同名值；省略的键保留，
显式 null 覆盖旧值。命名空间内部对象不做未被协议定义的递归 patch。晚到的来源或结果应更新已完成
工具的同一快照。父回合结束不为带有效子来源的未完成工具生成 completed；显式 null 或无效来源的
未完成工具按父工具结算。UI 将未报告结局显示为未知。

这是保守的保真选择：metadata 变化可能产生更多文本块，但不以压缩展示为理由混合来源或丢失信息。
保存的是组装快照，仍不承诺永久保留每条原始通知。

## D3：观察、请求等待与 provider 状态分开表达

所有 provider 共享诊断面板：最近收到的真实内容/工具/plan 活动及其接收时间、当前工具、未决权限请求、
父回合执行状态，以及 provider 实际上报且已识别的状态。没有 provider 状态时显示“未上报/未知”。
已知扩展状态按各自字段解释，不把任意 metadata.status 当成通用状态协议。

父 prompt 活动与投影子活动分别记录和标注；后台子输出不得推进父活动时间。工具也按已观察到的父/子
来源区分：有效来源记为 child；命名空间出现但为显式 null 或无效值时记为 parent，并清除该工具已知的 child 归因；只有省略命名空间的增量才继承本次尝试已知来源。未观察到来源的历史工具不默认归为父工具。
观察时长不是超时倒计时，父委托工具暂停计时等运行策略仍由运行时决定。重试新尝试清除旧来源观察。

接收时间是客户端观察该条实时事件的时间，不冒充 provider 发生时间。加载与重放流不展示历史记录
时间，观察时间显示为未知（“重放不是新活动”），也不刷新“最近实时活动”；历史记录时间只作为
transcript 条目的创建时间。切换会话、重载、换 provider
和新 prompt 时清除不再有效的观察快照。定时刷新只改变已过去多久，不生成新活动或健康判断。

静默只表示多久未见活动；等待用户只在确有未决请求时显示。question 表单缺能力时不得制造一个等待
状态，也不得宣称问题已回答。当前工具状态与子代理生命周期分别展示，历史缺口及父回合结果保留。

**子组终态**指 provider 明确上报的子会话执行结束，首期内联投影不提供它。父 prompt 结束后，
OpenCode 普通投影不再投递该子会话的内容；子会话的 created/running/completed/failed/interrupted
只走 `opencode/session/child_update` 扩展通知，首期客户端既不订阅该扩展，也没有承载这些状态事件的
JSONL 记录类型。因此「投影已停止」是投影通道的事实，不是对子代理运行状态的判断。

**委托结果**提供另一项 provider 事实。OpenCode 的 `subagent`（v1 的 `task`）工具在结果 metadata
中给出 `sessionID` 与 `status`，经 ACP 落在该工具调用的 `rawOutput.metadata`。`sessionID` 等于
子组 `_meta["opencode/child-session"]` 的 id 时，这次调用才可能是该子组的委托调用；`status` 为
`completed` 表示前台委托随子会话结束而返回，为 `running` 表示委托在子代理仍运行时先返回（后台
委托，或前台委托转入后台）。关联只认这个字段：工具标题、tool ID 前缀（子工具带 `child:tool`
前缀，委托工具不带）、`<subagent sessionID=…>` 文本和时间先后都不作为关联证据；失败结果没有该
metadata 时不解析错误文本补关联。子组仍按同一父回合内的来源 id 分组，不依赖委托结果。

关联还必须限定在**子组所在的同一父回合**与**其 `parentID` 所在的来源流**：顶层子组只查父流的
委托调用，嵌套子组只查对应父子组的来源流。即使后续父回合续接同一个 `sessionID`，也不能把后续
委托拿来改判旧回合的子组。同一范围内有多次可关联委托时，以工具调用**首次出现的持久化位置**判定
哪次最晚，再读取那次调用的最终快照；晚到的结果更新不改变调用顺序，不按接收或 provider 时间戳排序。

父回合已结束（完成、失败或取消）时，按上述同一回合、同一来源流中已持久化的事实给出标注；实时与
重载得到同一结论：

| 该子组最晚一次委托调用的结果 | 标注 |
| --- | --- |
| 最晚一次可关联委托调用的 ACP 工具状态为 `completed`，`rawOutput.metadata.status = "completed"`，且 `rawOutput.metadata.sessionID` 等于该子组 id | 「委托已返回结果」 |
| 委托未完成、失败或取消，`rawOutput.metadata.status = "running"`，或没有可关联的 `sessionID` | 「后续未知（投影已停止）」 |

「委托已返回结果」只陈述这次前台委托已有结果，不把它当作子组终态。`status` 为 `running` 时子代理
可能仍在后台运行，后续产出不会再投影，因此归入「后续未知（投影已停止）」。两种标注都不显示为
进行中，也不显示为完成、失败或已取消。两者都只由「父回合已结束」与上述委托、终态事实推出——
重载不得改判为进行中或完成，也不得按时长自行补一个终态；都不据此释放资源，也不作为取消、
steer 或 close 的入口。父回合仍在运行时，子组只按已观察到的状态展示，不因尚未收到终态就提前
标为未知。

父回合没有持久化终态时（例如进程在回合中途崩溃），重载后不满足「父回合已结束」这一前提：父回合
与子组都按已观察到的状态展示，不标「投影已停止」，也不把缺失的回合终态补成完成、失败或取消。
崩溃恢复不在本决策范围内，这里只约定不据此推断。

## D4：可见子活动不自动延长父 prompt

带明确子来源的文本、plan、工具和工具增量仍发送给消费者，但不能重置或暂停父 prompt 的 Timeout。
子工具后续增量即便省略 metadata，也不能丢失已识别的来源而被重新算成父工具；子权限请求的往返同样
不能独立重置父计时。现有权限处理策略不变，诊断只展示宿主实际暴露的待处理请求。父委托工具本身的
in_progress 继续按已有规则暂停计时；Wait、手动停止、真实错误与取消收敛均不变。

父流关联只证明这条内容应显示在哪里，不证明子工作正在被本次 prompt 等待。因此不根据后台日志、
子输出或 tool ID 文本保活，也不在此首期增加新的父子等待协议。

## 不变量与验收方向

1. 并发与嵌套的显式来源在实时、运行中重开、暖/冷加载后保持相同的内容归属。
2. 相同/缺失 messageId 不跨来源合并，晚到 metadata 与显式清除可重载。
3. 父回合结束不推断子终态：未上报终态的子工具不显示成功；父回合结束后，最晚一次可关联委托的
   ACP 工具状态及 `rawOutput.metadata.status` 均为 `completed` 的子组标为「委托已返回结果」，
   `status=running` 及其余子组标为「后续未知（投影已停止）」，两者都不显示为进行中、完成、
   失败或已取消，实时与重载结论一致；旧历史不补造来源与状态。
4. 子活动不会独立续期或暂停父 Timeout，父委托 in_progress 和 Wait 仍有效。
5. 诊断时间有明确来源；重放、切换、失败、取消和卸载不留下虚假的活动与待处理请求。
6. 详情树可展开文本、思考、工具输入/输出；循环、缺父、未知 metadata 和历史缺口不丢内容、不崩溃。
7. 委托关联只来自同一父回合、子组 `parentID` 所在来源流的 `rawOutput.metadata.sessionID`；同一范围
   多次委托按调用首次出现的持久化顺序选最晚一次。并发、嵌套与跨回合续接不会交叉关联；缺少该字段
   时不建立关联，也不从标题、tool ID 前缀、结果文本或时间戳推断。

通过真实帧驱动生产 runtime/history/load 与聊天 store，并用带类型的契约处理器验证呈现；再做实际
Desktop/浏览器、Node/Cloud/工作流消费端验收。父回合结束后，已完成的前台委托与未完成、失败、
取消、后台运行或没有可关联委托的子组，必须在实时与重载中分别给出「委托已返回结果」与「后续未知
（投影已停止）」的相同结论；不能一侧显示进行中、另一侧显示完成，也不能省略委托结果。静态解析
或计数相同不足以代替内容/来源及生命周期断言。核心用例与证据见
[子代理投影、终态缺口与运行诊断](../../../test-cases/node/agent-runtime/child-projection-and-diagnostics.md)，
未覆盖的路径在用例中如实标为 `Partial`/`Missing`。

## 与批准版本的差异

| 批准时的要求 | 最终实现 |
| --- | --- |
| 重新加载只知道历史记录时间时，明确标注为记录时间（D3） | 加载与重放不展示历史记录时间，观察时间显示为未知（重放不是新活动），避免把历史时间当作最近实时活动；记录时间仍用作 transcript 条目的创建时间。 |
| 来源有效性同时约束归属与投影活动（D1、D4） | history 组装、聊天分组与 prompt liveness 都要求有效来源：显式 null 或无效来源在 history/分组中回到父流，在 liveness 中清除该工具的投影记录，按父工具照常暂停与续期。运行诊断也复用同一有效来源规则：有效来源记录子活动；显式 null 或无效来源记录父活动并覆盖同一 tool id 的 child 归因；省略命名空间才继承本次尝试已知来源。`session_info_update` 仅在有效子来源时跳过，父 retry/compaction 不被吞掉。 |

第一项差异是展示上的取舍：加载流无法可靠区分重放与实时，展示记录时间容易被读成最近实时活动。
第二项已由 desktop#723 消除诊断端差异：归属、计时与诊断统一按有效来源判定，避免同一工具在聊天分组中属于父流、在诊断中却仍属于子流。显式清除会覆盖已知来源，后续省略命名空间不能复活旧的 child 归因。

## 为什么不是这些替代方案

| 方案 | 未采用原因 |
| --- | --- |
| 只在 UI 按工具标题分组 | 没有可靠身份，重载仍丢来源，跨并发混组 |
| 立即升级为 RFD 独立子会话 | 增加路由、控制和生命周期契约，超出首期只读范围 |
| 任意子活动保活父 prompt | 关联不等于被等待，会让无关后台活动掩盖父 prompt 静默 |
| 冷加载时用当前时间补最近活动 | 把旧事件伪装成刚发生，制造健康假象 |
| 对所有 metadata 递归合并 | provider 的替换/清除语义未知，容易复活已清除来源 |
| 父回合结束即把未收到终态的子组收束为完成或取消 | 投影可能已经停止，收束把未知结局伪装成已知终态，重载后也无法与真实终态区分 |
| 把委托工具返回当作子组完成或取消 | `status` 只说明委托已返回：后台委托会在子代理仍运行时先返回，子会话之后仍可被继续，收束会把未结束说成已知终态 |
| 把后台委托的 `status=running` 也标为「委托已返回结果」 | 子代理可能仍在运行，后续内容也不会再投影；该文案容易被理解成子代理已完成 |
| 父回合结束后不看委托结果、一律标「后续未知」 | 最常见的前台委托已经返回结果，统一标未知会让用户以为子代理还没跑完或卡住，也丢掉 provider 已给出的事实 |
| 按 tool ID 前缀、`<subagent sessionID=…>` 文本或时间先后关联委托与子组 | 前缀只用来区分子会话内的工具，结果文本是模型可改的呈现内容，都不构成身份来源 |

## 风险、未解决问题与落地

OpenCode 普通投影在父 prompt 结束后不再投递子会话内容，子会话终态只在
`opencode/session/child_update` 扩展通知里；首期客户端不订阅该扩展，也没有承载它的 JSONL 记录
类型，因此子组没有自己的终态来源。缺口不能当作子会话完成，委托已返回也不代表子代理已经停止
运行。父回合结束后仍到达的子权限和表单请求按现有空闲期策略处理，不改变子组标注；若以后改变
空闲期请求处理，需要重新审视「投影已停止」的含义。订阅该扩展并把状态事件写入历史是后续决策，
需要同时解决记录类型与重载保真；更完整的后台历史、question/elicitation、定向子代理控制与其他
provider 的来源适配同样留待后续决策。旧历史
读取无需迁移，但丢失的信息永久未知；新增 metadata 不能使旧文件变得不可读。

落地（每阶段独立合入并验收）：

1. **history 保真与 liveness 隔离**：desktop#695（合并提交 `be72c252`）保留来源 metadata 与完整
   文本块，保留委托结果的 metadata 供关联与重载判定；liveness 的投影隔离由 desktop#696 的
   `e56bf9c2`、`c53afb23` 引入，子活动不续期父 prompt。首期 liveness 按「命名空间存在」判定，
   显式 null 与无效来源会被当成投影；desktop#721 把该判定统一到 history 的有效来源规则，
   清除后按父工具照常暂停与续期。
2. **通用运行诊断**：desktop#696（合并提交 `5a022b04`）区分观察时间、缺口事实与未上报状态；
   [desktop#723](https://github.com/ora-space/desktop/pull/723)（合并提交
   `d271fb3b94234ab0f5d7f5ae3dcf94c738f104af`）统一有效来源规则，补齐显式 null/无效来源清除、
   同一工具后续增量继承和父 retry/compaction 的诊断回归。
3. **只读详情 UI**：desktop#697 在父时间线展示子代理树，实时与重载一致；只有 ACP `completed`
   且 provider `status=completed` 的可关联委托标「委托已返回结果」，`status=running` 等情况标
   「后续未知（投影已停止）」。
