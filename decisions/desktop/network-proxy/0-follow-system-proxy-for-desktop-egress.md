# Desktop 默认按目标跟随系统代理，并保留手动和直连模式

Desktop 宿主为自更新和主动使用代理的市场源提供同一套出站路由。未保存代理模式的安装默认选择「跟随系统代理」，保存过手动代理的安装升级后继续使用原配置。用户也可以明确选择直连。

本文为 `proposed`，依据 [#1537 的 owner 结论](https://github.com/ora-space/circus/issues/1537#issuecomment-7156981452)。首版覆盖更新清单、安装包下载、市场源 Git 同步及插件包下载。Cloud 登录沿用[独立的宿主连接路由](../cloud-connection/20261121-first-version-loopback-login-and-host-held-token.md)，Node、外部 Agent 和其他网络请求仍由各自的契约管理。平台范围沿用 [Desktop 平台决策](../platform/0-windows-and-linux-only.md)。

## D1 宿主保存代理模式

| 持久状态 | 生效行为 |
| --- | --- |
| 无模式，无旧手动配置 | 跟随系统（`System`） |
| 无模式，有有效旧手动配置 | 手动（`Manual`），保留原地址、端口和凭据 |
| 明确保存任一模式 | 以该模式为准，重启后继续生效 |
| 配置读取失败，或模式、必需字段无法解析 | 明确报告错误，保留已有值 |

模式和手动配置都由 Desktop 宿主拥有，界面的未保存编辑不改变后台请求。保存手动模式时，模式与有效配置一并提交。默认值仅用于缺失，读取失败不会写回或覆盖任何数据。沿用 [#1462](https://github.com/ora-space/circus/issues/1462) 的宿主偏好存储与安全升级原则，由 SQLite 保存宿主偏好。产品实现评审时须核对旧版可读性及降级行为，避免旧程序把新模式误读为旧代理设置。

## D2 跟随系统按目标解析

每次新操作读取已保存的模式，按实际 HTTP(S) 目标决定路由。回环地址始终直连。直连模式忽略环境和系统代理；手动模式使用 Ora 保存的代理。跟随系统时，系统明确要求绕过或没有配置时直连。已选用的代理连不上、解析失败或配置类型不受支持时报告原因，避免私自改走直连。

- **Windows** 通过 [WinHTTP 当前用户配置](https://learn.microsoft.com/en-us/windows/win32/api/winhttp/nf-winhttp-winhttpgetieproxyconfigforcurrentuser) 读取静态代理与绕过列表，按目的协议选用。仅有 PAC 或自动发现时提示首版不支持。存在静态配置时按静态配置解析。
- **Linux** 优先评估 [GIO 系统解析器](https://gnome.pages.gitlab.gnome.org/libsoup/gio/GProxyResolver.html) 的静态设置和绕过能力。首版不得调用会求值 PAC/WPAD 的路径。没有可用的静态系统解析能力时，读取 `HTTP_PROXY`、`HTTPS_PROXY`，再按目标协议回退到 `ALL_PROXY`，并尊重 `NO_PROXY` 与相应小写变量。系统明确返回直连、仅配置自动代理或解析失败时，各自应用前述结果，不能把这些结果混成解析器不可用。正式实现验收须实际运行 AppImage 和 deb，记录可用的桌面与运行时组合；若能取得同版本 rpm 测试包也核对其行为，rpm 不扩大当前发布范围。

系统或环境值按实际目标解析，能够反映网络或系统设置变更，并避免将旧代理固定到整个进程。首版不解析 PAC/WPAD，避免同一配置因包型而被隐式求值。

## D3 更新与市场源使用同一套规则

更新器对清单和安装包都采用 D2，跨目标重定向重新应用路由规则。签名校验、安装和现有更新生命周期继续由更新模块负责。

[市场分发根决策](../plugin/registry/0-registry-distribution.md) 的源级 `useProxy` 与来源归属继续有效。本文修改其代理段落的行为，待批准时同步原文的历史提示。

| 市场源设置 | Git 同步与包下载 |
| --- | --- |
| 开启「使用代理」 | 跟随宿主模式，按实际目标解析。缺少系统配置或命中绕过时直连，解析或连接失败时保留错误。 |
| 关闭「使用代理」 | 强制直连，忽略 Git 配置和环境代理。 |

Git 的代理设置作用于单次操作。包下载包含按源策略获取的 pack 成员及 S3 端点，并继续遵守已有凭据与来源边界。代理确定后也不能扩张允许携带源站凭据的重定向范围。

## D4 连接测试报告实际路由

设置页可测试当前选择，包括尚未保存的有效手动配置。测试使用与实际请求相同的解析规则，报告通过系统代理、手动代理、环境代理或直连，并区分连通结果与解析失败。日志和用户提示不输出凭据。

## 替代方案

| 方案 | 取舍 |
| --- | --- |
| 只读取代理环境变量 | 跨平台接入成本低，无法覆盖只在 Windows 设置里开启代理的用户，保留为 Linux 兼容路径。 |
| 每个网络客户端各自使用系统默认路由 | 改动较少，Git、更新检查和包下载可能使用不同代理，设置页也无法可靠说明实际链路。 |
| 整个宿主进程统一设置代理环境变量 | 接入简单，但会改变 Cloud、Agent 或其他子进程的网络行为，且无法保留每个源的直连决定。 |

## 不变量与验收

1. 缺失配置、明确直连和读取失败可区分，升级保留旧手动配置。
2. 用可观察请求的本机代理验证更新清单、包下载与跨目标重定向，覆盖系统绕过、代理断开、仅 PAC 配置和签名校验失败。
3. 验证市场源开启和关闭时 Git 与包下载一致；系统无代理时开启仍能直连，解析失败时不得触发直连。
4. 原生包验收须覆盖从桌面启动的 Windows 与 Linux 样本，并区分 GIO 可用、不可用和配置报错。连接测试显示的路由应与代理实际收到的请求一致。
