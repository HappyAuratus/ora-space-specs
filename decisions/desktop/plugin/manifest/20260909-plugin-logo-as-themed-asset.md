# 插件图标：本地文件决定主题变体，契约只承载资产 URL

图标由 Host 从包根或 registry 条目目录读取，契约只返回本地资产 URL；主题适配由作者提供文件，
Host 选择并原样渲染。支持 SVG、PNG、静态 WebP 和 JPEG，失败的候选按不存在处理，不影响插件
发现、安装或运行。本决策已实现，证据见[图标资产核心用例](../../../../test-cases/desktop/plugin/manifest/logo-assets.md)。

范围是 `ora-plugin-asset`、registry 索引、包发现、Desktop 资产 handler 和图标渲染。
清单 schema 与 resolver 不变；包目录和条目目录不迁移，原有 `logo.svg` 继续有效。索引是派生
缓存，形状/版本不兼容时整体降级为尚未同步。图标 UI 尺寸、作者工具和内容审核不由本决策确定。

## 继承与修改

| 前序约定 | 处理 | 最终规则 |
| --- | --- | --- |
| [清单根决策](0-versioned-dual-form-manifest.md)的纯解析与未知字段忽略 | 继承，不变 | 图标信息不进入清单 |
| [分发根决策](../registry/0-registry-distribution.md)的目录约定 | 修改 | 一个候选扩为三个角色乘五个扩展名 |
| 内联 SVG 源码 | 修改 | 索引保存候选角色/扩展名，契约返回本地 URL |
| SVG 安全策略与 50 KiB 上限 | 继承并扩展 | 所有候选共用字节上限，位图另受尺寸上限约束 |
| 旧索引靠字段默认值继续读取 | 修改 | 类型变化依靠索引版本校验与整体降级 |

## 决策

### D1：资产 URL 绑定来源根，主窗口请求只读回同一根

契约的 `PluginLogo` 为 Universal URL、完整 Themed light/dark 对或无图标。URL 只命名来源根、
Plugin ID、候选角色和扩展名，不承载文件路径或内容。两个根为 `installed` 与 `registry`；
市场卡片描述源条目，已安装列表描述实际安装包，各自铸出绑定自己来源的 URL。

资产 handler 只接受主窗口调用，收敛对应 canonical root，校验封闭角色/扩展名后读取候选。
找不到不回退另一个根。平台可使用 `ora-plugin://localhost/` 或 `http://ora-plugin.localhost/`
形式，均由 Host 本地 handler 应答，不为图标发送网络请求。content-type 按扩展名映射。

### D2：候选文件名与主题判定只有一份实现

三个角色为 universal、light、dark；文件名分别为 `logo.<ext>`、`logo.light.<ext>`、
`logo.dark.<ext>`。同角色优先级为 `.svg`、`.png`、`.webp`、`.jpg`、`.jpeg`。

| 可用主题候选 | universal 可用 | 结果 |
| --- | --- | --- |
| light 与 dark | 任意 | Themed，使用两个主题候选 |
| 仅 light | 是 | Themed，dark 槽由 universal 补齐 |
| 仅 dark | 是 | Themed，light 槽由 universal 补齐 |
| 仅一个主题候选 | 否 | Universal，两个主题共用该候选 |
| 无主题候选 | 是 | Universal |
| 无任何候选 | 否 | 无图标 |

两半允许不同格式。每个槽保存实际候选的角色及扩展名，不能由槽名反推文件名；例如 dark 槽由
universal 补齐时必须指向 `logo.<ext>`。registry 与包发现共用 `ora-plugin-asset` 的解析规则。

### D3：真实格式必须与扩展名一致，动画不进入白名单

Host 由字节判定真实格式：SVG 复用 XML/脚本/外部引用安全校验；PNG 读取 IHDR；WebP 覆盖 VP8、
VP8L、VP8X，拒绝动画；JPEG 从 SOF 读尺寸。无需像素解码即可完成资源检查。GIF 与其他格式拒绝。
`.jpg` / `.jpeg` 同为 JPEG，但保留各自扩展名以准确寻址。扩展名与真实字节冲突按缺失候选处理。

### D4：全部候选共用 50 KiB 上限，位图另限 1024 × 1024

字节检查先于格式识别；位图宽高分别不得超过 1024。两道限制独立成立，防止高度压缩的大画布
绕过字节额度。Host 不染色、反色、重新编码或补背景，服务的字节来自选定本地文件。

### D5：失败以候选为粒度降级，不改变插件可用性

不可读、链接、无效格式、不匹配扩展名、超限、不安全 SVG 或动画 WebP 均使该候选失效，继续
尝试同角色的下一扩展名和主题判定。失败记 warning，缺失候选无需告警。图标校验在索引构建和
包发现时完成，资产读取不重新扫描全部候选，也不写入包或条目目录。

### D6：不兼容索引整体失效，打开市场仍不触发网络

图标形状变更伴随 `INDEX_VERSION` 提升。版本不符或无法反序列化的缓存与文件缺失同样返回
空列表和 `updated_at = 0`；手动同步后以当前形状重建。不能局部解析旧形状或把缓存问题变成
市场端点内部错误。代价是升级后的尚未同步窗口。

## 与 approved 文本的同步

最终共享 owner 为 `ora-plugin-asset`。两处设计纠偏已成为稳定规则：主题槽保存实际候选角色
而非只保存扩展名；URL 显式命名来源根，防止市场和安装包构成不同时读错文件。其原因分别是
universal 补齐不能反推候选文件名，以及不同版本的本地目录不能互相替代。

## 为什么不是这些替代方案

| 方案 | 取舍 |
| --- | --- |
| 内联 SVG / base64 位图 | 响应自包含，但重复传输和驻留图标内容，格式牵动契约 |
| 远程 URL | 发布方便，但暴露终端请求且增加网络及隐私边界 |
| 清单声明任意图标路径 | 可灵活命名，但与固定目录约定重复并扩大路径输入面 |
| 应答时按根优先级或回退 | 容错看似更强，却显示不属于该发布的字节 |
| Host 自动染色 | 可修复部分单色图标，但无法稳定区分剪影与彩色内容 |

## 不变量

1. 契约只承载 Host 本地资产 URL，不承载图标内容。
2. 图标字节只来自本地文件，不触发网络请求。
3. 清单不声明图标，候选角色和格式由固定文件名决定。
4. Host 不写入包或 registry 条目目录。
5. 任何候选失败不改变插件可用性。
6. 真实格式必须与扩展名一致，content-type 与字节对应。
7. 单候选不超过 50 KiB；位图宽高不超过 1024；动画拒绝。
8. 渲染不改写像素，主题适配只选择作者文件。
9. 已安装图标随包卸载清除，无独立无主资产。
10. 包和条目目录布局不变，只扩充固定候选文件名。
11. registry 与包发现共用候选解析和主题判定。
12. 索引版本不兼容时整体降级且打开市场不触发网络。
13. URL 绑定根、ID、角色和扩展名，应答只读该根且不重新扫描候选。

## 后果与未解决边界

只提供单色 `logo.svg` 的旧插件在深色主题下可能仍不清晰，修复由作者补主题对完成。累计图标
缓存、作者校验工具、UI 容器样式和内容审核需后续决策；不以这些边界阻塞已实现的本地资产契约。
