# Skill 配置通过宿主启动环境快照交付，敏感字段按声明脱敏

提议让静态 Skill 插件用 `assets/config.json` 声明配置，通过宿主启动时冻结的环境快照交付给 Agent 进程树。敏感字段不回传编辑器；公开字段正常显示。本 ADR 尚待 owner 评审，预开发实现不代表契约已经批准。

## 继承与修改

| 前序决策 | 处理 |
| --- | --- |
| `0-static-skill-package.md` D1–D3：静态包身份和浅层 Skill 布局 | 继承；`assets/config.json` 是插件级普通文件，不构成 Skill，也不复制到 Skill 目录 |
| 根决策 D4：Skill 无插件进程，脚本由 Agent 消费 | 继承；配置由宿主交付给 Agent，不为 Skill 启动 runtime |
| 根决策 D5–D7：Catalog 身份和生命周期 | 继承；配置完整性不影响 Catalog 或 Effect 物化 |
| MCP 的配置及全量脱敏约定 | 继承；新增 secret 不降低 MCP 现有保护 |
| Skill 脚本配置交付 | 新增；仅 Desktop 宿主配置，不扩展 Cloud 或普通导入 Skill |

## D1：配置沿用通用存储，增加敏感字段声明

Settings-only 配置中的每项 Setting 可声明 `secret: boolean`，省略为 false；字符串、数字、布尔值都支持。字段参与声明指纹，现有 revision CAS、声明变化冲突、必填判断、默认值和重置机制保持不变。

本提案将 `secret` 限于 v1 Settings（包括 Skill、MCP），不扩展已发布的 v2 Agent 声明。v2 Agent Setting 拒绝 `secret` 成员，包括显式 `false`，其编译输出与指纹契约保持不变；若要支持，需要另行修改 Agent 声明契约。该兼容边界仍随本提案等待 owner 批准。

secret 字段的默认值、存储值、有效值在编辑器响应中均为空，只返回来源与 redacted 标记。未编辑时保存保留原值；显式重置该字段删除存储覆盖。公开字段仍可见。MCP 即使省略 secret 仍全量脱敏。

配置仍保存在宿主插件数据目录的 store.json，不宣称加密存储。插件作者不得在发布包的默认值或说明中放置真实凭据：脱敏不能撤销包本身的公开内容。

## D2：完整配置在 Desktop 启动时冻结为全局环境快照

每次 Backend 初始化从已安装有效 Skill 插件及宿主配置建立不可变内存快照。Agent 插件启动和宿主 childprocess/spawn 使用同一快照，包括不指定 cwd 的子进程。非 Agent 插件不获得注入。

配置缺失必填值、损坏、非法或含 NUL 时，整包不注入，不阻止其他插件或会话启动。可选缺失值不产生变量。配置状态仍由原配置入口展示；宿主诊断不包含配置值。Skill 内容仍正常物化，脚本负责报告缺少配置。

快照对所有 Agent 和工作区共享。这是用户信任本机 Agent 的执行边界，不是按 Skill 或工作区授权的凭据代理。Agent 和脚本能够自行读取并输出值；宿主无法承诺第三方脚本不会泄漏。

## D3：变量名使用无损编码，前缀归宿主所有

变量名为 `ORA_SKILL_P<Plugin ID 的 UTF-8 大写十六进制>_S<Setting ID 的 UTF-8 大写十六进制>`。例如 `a/b` 与 `token` 得到 `ORA_SKILL_P612F62_S746F6B656E`。完整 canonical Plugin ID 包含 namespace。

编码保留大小写与分隔符身份，在 Windows 不因大小写不敏感而碰撞；代价是名称较长、不适合手写，作者应使用文档中的生成函数。字符串原样交付，数字采用 JSON 表示，布尔值为 true/false。

启动插件及宿主子进程前，移除继承环境中大小写不敏感匹配 ORA_SKILL_ 的变量，再注入快照。调用方不能通过 spawn 的 env 伪造该前缀。不提供自定义别名以免跨插件覆盖。

## D4：修改在重启 Desktop 后生效

保存、重置、安装、更新和卸载不改变当前快照。即使之后重新启动单个 Agent，也仍使用本轮 Desktop 的快照。设置页明确提示重启 Desktop；宿主不自动停止活动会话。

这避免直接 spawn 与宿主代 spawn 使用不同版本，但意味着撤销或卸载后旧进程仍能持有凭据。需要立即撤销时，用户必须终止相关进程并在外部服务吊销凭据；重启只刷新宿主交付，不是服务端吊销。

## 为什么不是这些替代方案

| 方案 | 取舍 |
| --- | --- |
| 全量脱敏 | 更简单，但 URL、环境名等公开配置也不可查看 |
| 工作区 .env | 通用脚本容易读取，但增加误提交、同步与备份泄漏面 |
| 按工作区隔离或即时更新 | 共享 Agent 插件进程不能表达该边界，需要另行设计执行或代理通道 |
| 凭据查询 Tool | 可按需授权，但要求脚本改用宿主接口，不适合作为本期通用交付路径 |
| 替换标点并转大写的变量名 | 可读性较好，但身份可能碰撞，尤其 Windows 上不能仅区分大小写 |

## 不变量与验收

1. 宿主的配置交付路径不将配置值写入工作区、Effect、ACP 消息或日志；此承诺不覆盖 Agent 或脚本自行输出值。脚本输出可能进入 ACP 消息、插件日志、debug TRACE 日志和会话 JSONL，界面脱敏不能防止这些泄漏。
2. 敏感字段不通过读取、保存、重置响应返回；MCP 保持全量脱敏。
3. 两条 Agent 启动路径消费同一快照，配置变化仅在重启 Desktop 后进入快照。
4. 无效配置整包跳过；无配置的 Skill 继续物化，其他 Agent 和 Skill 不受影响。
5. 环境变量编码不碰撞，继承值和调用方 env 不能冒充宿主变量。

预开发需提供配置保存与脱敏、跨进程注入、大小写冲突、NUL、缺失必填值、重启更新和卸载后的直接行为证据。ADR 批准后依据最终契约维护核心测试用例；当前 proposed 阶段不提前建立核心用例。

## 落地顺序与未解决的问题

先评审本 ADR，再对照结论修订预开发实现，最后验收并更新状态。旧配置无需迁移；带 secret 的新声明不保证可被旧版本宿主接受。工作区隔离、运行时热更新、系统钥匙串、Cloud/远程执行及普通 Skill 导入配置留待后续决策。
