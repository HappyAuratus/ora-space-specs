# 市场工作流同名冲突可重试，卸载保留存活副本的来源

Desktop 的市场工作流因同名冲突跳过后，用户可在解除冲突后从插件卡片重试，或卸载后重装。卸载清理冲突记录和已删除副本的来源记录，保留存活副本及其来源。安装结果分别说明插件包是否安装和工作流是否导入，并指出每份冲突文档以及恢复入口。

本文为 `proposed`，供规格评审。变更范围是 Desktop 的市场导入、卡片重试、卸载与结果展示，也适用于 Pack 内实际安装或卸载的 Workflow 成员。本地 `.orax` 导入沿用根决策。Cloud [资产导入规则](../../../../cloud/plugin-marketplace/20261016-workflow-plugin-assets.md) D4 同样允许名称冲突后的导入尝试，Cloud 的记录和接口由其自身决策定义。现有 Desktop 来源记录直接适用新规则，无需启动时全量回填或按名称推断来源。

## 决策

### D1 使用当前冲突判定处理安装、重装与卡片重试

来源键仍由 canonical Plugin ID 和包内文档路径构成。冲突判定使用文档中的工作流名和库里当前存活的工作流。导入遇到同名时保留已有工作流，记录 `conflict_skipped`，返回带工作流名和文档路径的 `SkippedConflict`。

| 现有来源记录 | 安装、重装或卡片显式重试 | 插件仍在安装期间的升级 |
| --- | --- | --- |
| 无记录 | 尝试导入。成功记录 `imported`，同名冲突返回 `SkippedConflict`，其他失败可重试。 | 同左。 |
| `conflict_skipped` | 重新检查当前工作流库。冲突消除后导入并记录 `imported`。仍有冲突时返回 `SkippedConflict`。 | 冲突消除后尝试导入。仍有同名冲突时跳过，避免对同一条已知冲突反复通知。 |
| `imported`，副本存活 | 沿用来源记录，即使副本已改名。 | 沿用来源记录。 |
| `imported`，副本已删除，来源记录尚未清理 | 在插件仍在安装期间保留用户的删除选择。完成卸载并清理后，重装按无记录处理。 | 保留来源记录和用户的删除选择。 |

冲突记录说明此前未交付副本，用户改名或删除冲突对象后可以让原文档重新参与导入。曾经成功并由用户删除的副本，在当前安装周期内维持删除状态。卸载后重新安装允许该文档再次导入。

### D2 卸载清理当前插件的可恢复来源记录

成功卸载 Workflow 插件时，清理该 canonical Plugin ID 下的 `conflict_skipped` 记录，以及对应副本已删除的 `imported` 记录。Pack 只对卸载计划中实际卸载的成员执行清理。取消卸载、卸载失败或保留 Pack 成员时，插件的来源记录仍然有效。

副本仍存活时，保留 `imported` 记录及其关联。用户改名后，工作流库和创建运行菜单仍能显示「来源插件已卸载」。重装同一 canonical Plugin ID 后标记消失，仍使用原副本和来源记录。

这一清理边界允许重装恢复缺失文档，同时保留定位存活副本所需的关联。旧版持久化的 `conflict_skipped` 记录可由卡片重试重新判定。旧版留下的已删除副本记录可在新版成功卸载时清理。

### D3 报告冲突文档并提供可操作的重试指引

安装、升级和显式重试使用一致的逐文档结果。响应包含 `SkippedConflict` 时，报告弹窗或明确提示逐项列出被跳过的文档和冲突工作流名。提示用户在工作流库改名或删除冲突对象后，到已安装插件卡片点击「重试导入失败的文档」。该动作会尝试冲突文档，以及其他仍可重试的文档。

包已安装而此次没有导入任何工作流时，摘要说明未导入结果，并按返回结果显示原因。混合批次分别呈现成功导入与被跳过或失败的文档。既有依赖报告继续说明成功导入工作流的 MCP / Skill 状态及处理入口。

## 替代方案与取舍

| 方案 | 取舍 |
| --- | --- |
| 只调整恢复行为和摘要文案 | 界面改动较小，用户仍缺少定位冲突文档所需的工作流名和重试指引。 |
| 只重试从未成功的冲突文档，永久保留已删除副本的来源记录 | 删除语义易于维持，主动卸载重装也无法找回之前成功交付的工作流。按安装周期保留删除记录能分别满足升级和重装的意图。 |
| 卸载清理插件的全部来源记录 | 清理规则简单，但会使存活副本失去来源标记。副本改名后重装也可能再创建一份。 |

## 不变量

1. 存活的导入副本及其来源键跨升级、改名和卸载重装保持可识别。同一路径已有存活副本时继续使用原副本。
2. 名称冲突保留已有工作流。冲突消除后，重装或显式重试允许该路径完成导入。
3. 插件仍在安装期间，升级和卡片重试尊重用户对成功导入副本的删除操作。成功卸载清理该记录后，重装按当前工作流库判断是否可导入。
4. 导入副本、首个已发布快照与成功来源记录一致提交。卸载清理以实际卸载的 canonical Plugin ID 为边界。
5. 包安装结果与文档导入结果分别可见。需要用户处理的冲突可以定位到文档和工作流，并给出恢复入口。

## 落地与验收

规格获批时，同步[核心用例](../../../../../test-cases/desktop/plugin/category/workflow/workflow-package-and-import.md)的验证义务。实现要覆盖首次同名、改名后重装、改回后重装、删除冲突对象后重装，以及保留插件直接从卡片重试。另须验证已导入副本删除后在装升级维持删除、卸载重装恢复，存活副本跨卸载保留来源，已知冲突升级不反复提示，以及全冲突和混合批次的界面呈现。两个来源具有相同 `identifier` 时，卸载和重装只影响目标 canonical Plugin ID。
