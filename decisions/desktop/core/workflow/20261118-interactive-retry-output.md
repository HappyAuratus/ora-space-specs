# 交互式节点按最终尝试的有效产出恢复

交互式节点以同一人工回合内最终一次 ACP 发送的有效产出判定交付。history 保存重发边界，agent-runtime 在取消确认后隔离各次发送，backend 在停靠和提交时校验产出。缺少有效产出的重试保留原会话并阻断后继，运行视图展示失败与恢复入口。

本决策已在 Desktop 落地。旧历史缺少边界时使用原回合窗口，已完成节点和已有审计无需回填。

## 继承与修改

| 前序决策 | 处理 | 本决策中的规则 |
| --- | --- | --- |
| [交互式节点完成契约](20261021-interactive-node-completion.md) D2 | 修改 | 回合身份继续使用原 turn key。有重试边界时，最终输出窗口从最后一次重发开始。 |
| [完成信号的尝试绑定](20261110-agent-completion-signal.md) | 继承，不变 | 仅接受当前发送的有效完成请求。 |
| [声明文件的实时校验](20261023-interactive-deliverable-contract.md) | 继承，不变 | 对当前工作区执行冻结的文件声明，包括路径匹配与 `mustChange`。 |
| [异常停靠与显式确认](20261102-first-turn-confirmation.md) | 继承，不变 | 停靠时保留会话，显式强制完成单独审计。 |

## 决策

### D1 持久化每次重发的边界

同一用户回合只记录一次用户消息。每次静默取消得到原请求的响应、即将重发时，历史划出新的尝试边界。取消排空阶段的文本、工具结果及完成请求归入被放弃的尝试。重新发送的凭证只授权本次发送。新尝试复用工具或消息 ID 时，两次尝试仍独立。

ACP 工具增量缺少尝试标识。相同 ID 重新打开前，增量更新原调用的位置。重新打开后，缺少归属的增量更新新调用的位置。若最终重试边界前，本回合仍有同 ID 的待处理或进行中调用，重开后的完成状态无法证明最终尝试交付，因此不计为有效产出。

### D2 以最终尝试校验交付

park、普通完成、自动接受和强制完成从相同的最终尝试窗口取输出。按冻结契约校验最终文本、结构化输出、实际工具结果、声明文件与完成信号。最终尝试报告工具成功或提交可核验的完成信号后，只交付文件的步骤可通过声明的文件校验。文件在节点开始前或旧尝试中就可能存在，仅凭其存在无法归属到一次完全静默的重试。需要 agent 信号时仍须有本次尝试的有效请求。等待中的工具、仅有思考、会话级更新和历时长短都不能证明步骤恢复。

### D3 空重试停靠并阻断后继

重试以 `EndTurn` 结束但缺少有效结果时，交互节点进入异常停靠，保留原会话。卡片和详情显示“节点运行失败”、原因和重试入口。持久化的失败原因在重启后可读。普通完成及自动接受都在后端拒绝，依赖成功的后继保持未启动。随后有效的人工回合按正常完成规则恢复，已有失败记录保留。

### D4 显式强制完成和旧历史兼容

用户仍可经既有的二次确认强制推进。完成审计单独标明空重试原因，并记录覆盖的 blocker。最终尝试没有文本时，强制采用的文本也为空。旧历史缺少新边界时沿用既有读取规则；保留既有审计和已经完成的节点。

## 不变量

1. 回合身份与最终尝试的输出窗口可以分别重建。
2. 后继调度以服务端验收为准，重复完成请求同样受门禁约束。
3. 只有显式强制完成可以覆盖未恢复结果的 blocker，并留下审计。

## 为什么不是这些替代方案

| 方案 | 收益 | 对本场景的影响 |
| --- | --- | --- |
| 转入引擎 `Failed` | 复用引擎已有的失败策略 | 会触发失败边，打断用户在原会话补交有效结果的路径。 |
| 只显示界面告警 | 客户端能立即解释异常 | 旧页面仍能提交完成请求，宿主自动接受也可能启动后继。 |
