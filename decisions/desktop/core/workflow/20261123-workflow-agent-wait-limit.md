# 工作流 Agent 单次发送默认按进展等待，超长静默须显式选择

工作流图中的 `agentConfig.promptInactivity: "wait"` 允许一次发送后持续工作。提议以最近一次有效进展为起点，连续静默 30 分钟后结束该轮。适用于已有图与新图。确需长期等待隐藏子代理的节点可以选择 `"unbounded"`。本提案供评审，具体信号及配置取值在批准时定稿。

## 继承与修改

| 前序约定 | 处理 | 行为 |
| --- | --- | --- |
| [静默策略 D1](20261008-prompt-inactivity-policy.md) 的显式等待 | 修改 | `wait` 有限，`unbounded` 承接原无限等待语义。普通聊天及缺失、null、显式 timeout 的工作流继续使用原超时重发策略。 |
| [静默策略 D2–D4](20261008-prompt-inactivity-policy.md) 的冻结配置、取消与隔离 | 继承 | 每次发送使用所属运行的冻结配置，真实终止和释放路径对两种等待都有效。 |
| [交互节点重试输出](20261118-interactive-retry-output.md) | 继承 | 轮次失败进入现有节点重试与输出归属流程。 |

## D1　等待从每次实际发送开始

`"wait"` 的默认窗口为 30 分钟。节点可用 `{"waitMinutes": 75}` 指定 1 至 65535 的整数分钟。非法值在节点执行前拒绝。已有图直接按其冻结字段解释，无须重写草稿或运行记录。打开编辑器、修改无关字段都不能使节点自动选择无限等待。编辑器将 `"unbounded"` 标为「无限等待（需手动停止）」；运行详情展示冻结策略及有限窗口。每次新 turn 或节点级重试从实际发送重新计时。

## D2　按本轮可归属的进展续期

| 事件 | 有限等待窗口 |
| --- | --- |
| 本轮收到非空消息或思考内容、变化的计划、工具第一次报告状态或随后发生状态变化 | 从收到该事件起重新计满一个窗口。 |
| 可归属到本轮仍 pending 或 in-progress 委托的子代理输出 | 采用同样的内容和状态变化判据，可续期。游离或已结束委托的更新不能续期。 |
| 本轮父工具等待的权限交互完成 | 从答复完成起续期。等待答复和执行工具期间都继续计时。 |
| 重复工具状态、相同计划、空文本、用量更新、stderr、其他会话活动 | 保留原截止时间。 |

长任务可以跨越多个窗口。已经发送的 prompt 即使持续收到工具运行中状态，也须在最后一次有效进展后到期。计时只描述 Ora 可观察的进展；静默本身不能证明进程已退出。

## D3　到期收敛与真实故障

连续静默达到阈值后，结束本轮及其订阅者，节点记录可辨识的静默超时原因，按已有节点策略处理失败。单轮自动重发次数为零。服务连接断开、用户取消或工作流停止可提前结束两种等待。正常响应已经完成的 turn 不能再被迟到的计时事件改成失败。无限等待仅豁免 prompt 静默期限，建立会话与取消仍有各自期限。

## 取舍与验收边界

保留旧图的无限等待会使已有故障工作流继续挂住。默认有限窗口可自动覆盖旧图，代价是完全静默但仍在工作的委托也可能失败。显式无限等待保留了这类节点的选择权。按总运行时长强制结束则会中断持续产出结果的长任务。

验收时以可控制时钟覆盖旧图默认、到期前续期、工具运行或等待授权时到期、跨会话隔离，以及显式无限等待长时间静默后的正常完成与手动停止。分别核对单轮发送次数和节点级重试次数，再检查运行详情展示的冻结配置。批准后将这些义务并入[核心用例](../../../../test-cases/desktop/core/workflow/prompt-inactivity.md)。
