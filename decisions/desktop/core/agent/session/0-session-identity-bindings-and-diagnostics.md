# Ora 会话保持稳定身份，以独立只读查询展示插件绑定历史和统一诊断

Desktop 以 Ora 会话作为对话的稳定身份；插件返回的 ACP session id 属于可变绑定。
绑定历史由后端结合会话行与已有 JSONL 读取，通过面板专用查询供「会话信息 / 诊断」使用。
对话与工作流复用同一份绑定投影和同一面板，工作流运行另提供按执行定位的索引。

本根决策处于 `proposed`，覆盖 Desktop 会话身份、绑定历史读取及只读诊断呈现边界，尚未批准实现。
不改变会话生命周期、ACP 切换/handoff、权限处理、工作区归属或工作流调度；不迁移历史路径、不改写旧 JSONL。
新增查询不扩展公开 `Session` 的 provider session 字段，不创建另一份绑定持久化账本。

## 问题与约束

同一 Ora 会话切换 Agent 后，Ora id、Workspace 与历史文件保留，插件绑定改变。当前会话行只能回答
「现在绑定谁」，旧绑定保存在 `Meta` 和 `AgentSwitched` 记录中，普通消息载荷不展示它们。
工作流节点、失败尝试与循环轮次又各自持有 Ora session 引用，因此当前插件 id 无法代表整次运行。

排障需要复制准确的插件会话 id，而不应依赖用户查数据库或客户端扫描 JSONL。历史记录和当前行可能
在切换的短暂窗口内不同步；读不到历史也不能被表达为「从未创建」。插件身份与时间必须保留来源，
不能靠显示名称、消息内容或请求时间猜测。新入口还需要容纳已有 provider 运行诊断，避免信息重复。

术语见[共享词汇表](../../../../../domain/glossary.md#agent-conversation)。

本目录首次定义 session 根决策；下表明确既有相邻领域的所有权，既有子模块决策继续有效。

| 依据 | 继承或新增边界 |
|---|---|
| [共享 Agent Runtime 根决策](../../../../node/agent-runtime/0-shared-agent-runtime-crate-hosted-by-node.md) | 继承 runtime 对连接、binding、记录、切换与 handoff 的所有权；本 ADR 新增 Desktop 的只读查询与展示边界，不另建 lifecycle 路径 |
| [Session MCP 根决策](mcp/0-acp-session-setup-delivery.md) | 继承 MCP setup/refresh 与协调 seam；诊断读取不触发 refresh，不暴露配置实值 |
| [Workflow 根决策](../../workflow/0-node-runtime-orchestration.md) | 继承 node-run、作用域和 session 归属的持久事实；索引是读取投影，不参与调度 |

provider 活动、子来源和投影中断状态由独立的运行诊断决策维护。本 ADR 不批准或修改这些规则；
在其决策与实现未合入时，不将草稿字段或状态表述为既有系统承诺。

## D1：Ora 身份与 Agent 绑定分别拥有各自的含义

Ora Session ID 标识 Workspace 中的整条对话。切换 Agent 不能创建新的 Ora 身份、移动历史或替换 Workspace。
Agent Session ID 是插件返回的不透明字符串，其定位范围是完整插件身份和所属 Ora 会话；不作为全局唯一键、
Ora id、访问凭据或子代理终态使用。不按前缀解析，不截断复制内容，不用插件显示名称匹配身份。

绑定段表示这条对话在一段连续绑定期间使用的插件和 Agent Session ID。相同插件在不同时间再次绑定必须
保留为不同段；也不能仅按 Agent Session ID 去重。切换没有改变 Ora 会话身份，是展示多段绑定的原因。

尚未建立插件会话与插件会话已经失败是不同事实；查询本身不调用 `session/new`、`session/load`、
prompt、重试或任何插件启动操作。

## D2：后端从已有记录恢复绑定段，以当前行判定当前绑定

后端读取 `Meta` 的初始绑定与各条 `AgentSwitched` 的目标绑定；`HandoffDelivered` 只证明转写被接收，
不产生新段。保留历史语义序号 `seq`，按其顺序呈现绑定，不按墙钟时间排序。记录时间 `at` 是该段的
记录时间，UI 明示这一来源；它不是插件服务端创建时间。无法取得时间的活绑定显示未知，不拿查询时间补齐。

每段返回完整插件引用、Agent Session ID、可用的记录时间、稳定的段定位信息及当前标记。插件显示名称只是
可选展示信息；插件已卸载或不可解析时仍保留历史中的完整身份和 id。

当前绑定以同一查询读取的会话行中 `agent_ref` 与 `agent_session_id` 为准。历史末段与该绑定一致时只标
该末段为当前；历史末段不一致或尚未存在时，将当前行作为独立的活绑定补在末尾，并明确尚无对应历史记录。
不能在历史中搜索任意同 id 的旧段并把它冒充当前段。没有有效当前绑定时，不把历史末段默认标为当前。

读取在宿主已有的会话协调边界内取得一致视图，或通过前后核对当前 binding 检测并发变化。若切换使视图
不一致，只允许有界重读；仍不稳定时返回明确的重试状态，不拼出同时有两个当前绑定的成功结果。
此要求不新增持久 revision，也不允许读操作阻塞 prompt 或持有调度事务等待文件 IO。

历史和当前行不能组成覆盖全部崩溃窗口的绑定审计。若旧绑定从未落盘且已被后续绑定覆盖，查询无法恢复它；
界面不得承诺超出现有记录的完整性，也不为了补历史重新访问插件。当前行补段是已知当前事实，不证明缺口已填平。

## D3：专用查询区分尚未创建、历史不可用和会话不存在

公开 `Session` 继续不带 provider session id；增加只服务诊断面板的 typed query，由 session 领域负责投影。
前端只传 Ora session 引用，不传文件路径，不扫历史，不自行重建绑定。宿主从受控会话路径读取，沿用会话
读取的范围和访问边界；能看到一个 WorkflowRun 不等于可以请求任意会话。

| 事实 | 查询与展示行为 |
|---|---|
| 当前无 binding、历史可读且无绑定记录 | 显示尚未创建，不输出空 id 或可复制空值 |
| 历史缺失或不可读 | 显示历史不可用；已知当前 binding 仍可展示，不声称没有旧绑定 |
| 存在损坏记录、显式 Gap、不支持的 schema 或相互矛盾的身份/序号 | 标明历史不完整或不支持；仅保留能验证归属和顺序的部分，不静默跳过后宣称完整 |
| 会话不存在或已删除 | 返回相应不可用结果；不只凭残存 JSONL 重新建立会话 |
| 读取期间持续切换 | 返回需重试，不将旧响应覆盖新上下文 |

批量读取按 Ora session 去重并限制每批大小和读取并发，超限可分批；结果逐 session 对应，单项失败不抹去
其他节点的数据。底层历史读取必须有资源上限，达到上限时明确标记不完整，不能静默截断成完整结果。
客户端切换会话、关闭面板或切换 run 后释放其查询生命周期，迟到响应不能进入新的会话面板。

不返回原始 JSONL、绝对路径、MCP 配置、密钥或任意工具输出；插件 session id 只在用户打开的诊断信息及
主动复制中出现，不加入会话列表、消息气泡或默认日志。

## D4：会话信息和运行诊断共享一个只读面板

对话菜单提供「会话信息 / 诊断」，默认收起。面板先展示可复制的 Ora id，再展示绑定时间线、当前运行诊断、
子代理只读详情。每段可复制完整 Agent Session ID，并能区分历史段和当前段。

聊天中的诊断快捷入口定位同一个面板，不继续维护第二份诊断正文或独立弹层。子代理消息仍可按所属组留在
聊天时间线，详情定位使用相同会话上下文；不将子代理 id 混入父会话的绑定段。

诊断由其领域 owner 提供观察结果，面板只组合这些数据。持久绑定的记录时间和客户端最近接收活动的时间
必须标注不同来源；冷加载不能用历史时间充当最近实时活动。未知活动、自动处理权限与未支持的请求表单
不得被展示成「健康」「正在等待用户」或不存在的控制能力。本 ADR 不增加 cancel、steer、close 或审批入口。

## D5：工作流运行索引按执行事实关联所有绑定段

仅运行页展示索引：节点、轮次、尝试、状态、插件、Ora Session ID、Agent Session ID。节点、失败尝试与
循环轮次保留自己的入口，均定位同一面板。编辑态没有执行会话，不展示索引或伪造 session。

索引从 node-run 和作用域持久记录取出 session 引用，再批量取得统一绑定投影；轮次与尝试按原领域的语义
标注，不自行把所有循环重编为同一零基或一基计数。节点名称或视觉位置不参与执行归属。

每次执行占一项，包含它关联的全部绑定段；多个绑定用展开明细表达，不仅保留当前 id。两个 Agent 节点中
一个重试一次时，应定位三次执行；同一 Ora 会话出现多个执行引用时，读取可去重，执行行不能合并。
状态来自相应执行事实，不以插件仍可连接或诊断有输出推导成功。

没有 session 的执行保留相应状态并说明尚无会话；会话丢失或历史不可用时保留执行定位及已知 Ora id，
标明不可用而不删行。失败诊断结束后已丢弃的临时会话本期不追溯，也不伪造它的 Agent Session ID。

## 不变量

1. Agent 切换不改变 Ora 会话、Workspace 和历史文件身份。
2. 查询只读，记录存储与 lifecycle 的既有 owner 不变。
3. 绑定段来自可验证历史或当前行，未知时间和缺失记录显式表达。
4. 单次成功结果至多一个当前绑定，当前标记与所读取的会话行一致。
5. 相同插件或重复 session id 不会合并不同历史段。
6. 前端不读 JSONL，公开 Session 不增加 provider session id。
7. 诊断入口复用同一面板和会话上下文，迟到结果不串会话。
8. 工作流执行归属与状态只取持久事实，批量失败按会话隔离。

## 为什么不是这些替代方案

| 方案 | 优势与否决理由 |
|---|---|
| 消息流常驻显示 id | 容易看到，但挤占对话内容并仍不能表达切换历史；采用主动打开的排障信息 |
| 只展示 sessions 当前行 | 读取便宜，但切换前绑定丢失，不能满足历史排障 |
| 前端扫描 JSONL | 少一个查询，但暴露路径、重复历史规则，也无法统一取得当前 binding |
| 新建绑定审计表并回填 | 可提供更强查询一致性，但改变写入和恢复边界，旧缺口仍不能凭空补齐；本期复用现有事实 |
| 扩展所有 Session 载荷 | 所有消费者均能直接取 id，但扩大默认暴露和刷新范围；采用按需专用查询 |
| 只在节点逐个展示 | 简单，但重试与循环运行仍需人工遍历；增加运行级索引 |
| 将全部规则并入运行诊断 ADR | 一次评审，但把会话身份/历史读取与子投影状态绑定；本根 ADR 独立定义 session 所有权 |

## 风险和未解决的问题

旧 JSONL 保持原样，记录缺失不回填、不换路径、不调用插件恢复。损坏或有限读取产生的信息缺口要可见，
不能被成功复制当前 id 掩盖。文件读取量、并发上限和一致读取机制需在实现 review 中以生产接口验证。

本期不定义 Cloud 远端会话诊断 API、不追溯已丢弃临时会话、不增设完整绑定审计账本，也不判断 Agent
原生记录保留多久。子代理状态、父子活动及投影停止判定遵循其独立决策，不因面板重组改变。

## 验收方向与落地顺序

先评审本 proposed ADR；批准后改为 approved，维护镜像 session 领域的核心用例。此阶段不将草稿产品分支
当作已实现证据。再以最终合入的 provider 诊断/子详情实现为基线，在独立运行中开发查询、面板与工作流索引。
产品 review 后另开落地运行，同步最终规则和核心用例证据，再于产品合并后改为 implemented。

验收覆盖：两次切换得到三段；同插件重复绑定保留；历史落盘滞后与并发切换；缺失/损坏/不支持历史的降级；
未创建提示；两个节点含一次重试的三次执行；循环轮次隔离；批量部分失败；统一入口与切换会话迟到响应隔离；
公开 Session、会话列表和消息气泡保持原有 id 暴露边界。新增查询与 UI 不触发任何插件副作用。
